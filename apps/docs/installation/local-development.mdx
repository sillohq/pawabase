This guide covers setting up Pawabase on your local machine for development. The platform requires Python, PostgreSQL, and Redis. Once installed, you can run the full stack and develop flows, functions, and extension routes.

<CardGroup cols={2}>
  <Card title="Requirements" icon="cpu">Python 3.12+, PostgreSQL 16, Redis 7.</Card>
  <Card title="Workflow" icon="refresh">Hot-reloading, debugging, and testing built in.</Card>
</CardGroup>

## Requirements

| Tool | Version | Purpose |
| --- | --- | --- |
| Python | 3.12+ | Runtime and package management |
| PostgreSQL | 16+ | Database |
| Redis | 7+ | Cache and job queue |
| pip | latest | Package installation |

## Installation

```bash
# Clone the repository
git clone <repo-url>
cd <repo-name>

# Create a virtual environment
python -m venv .venv
source .venv/bin/activate

# Install the package
pip install -e .

# Install development dependencies
pip install -r requirements-dev.txt
```

## Starting the platform

```bash
# Start Postgres and Redis
brew services start postgresql
brew services start redis

# Create the database
createdb pawabase

# Run the platform
python -m pawabase.bootstrap
```

The bootstrap process starts the API worker, scheduler, and all background services.

## Hot-reloading

During development, the platform supports hot-reloading. When you modify Python source code or flow definitions, the platform automatically reloads the changed modules.

## Configuration

Create a .env file with these variables:

```env
PAWABASE_ENV=local
PAWABASE_ENTRYPOINT_GROUPS=default
PAWABASE_WORKER_CONCURRENCY=4
PAWABASE_WORKER_MAX_JOBS_PER_WORKER=100
PAWABASE_WORKER_HEARTBEAT_INTERVAL=30
PAWABASE_WORKER_HEARTBEAT_TIMEOUT=120
PAWABASE_SCHEDULER_INTERVAL=10
DATABASE_URL=postgresql://pawabase:secret@localhost:5432/pawabase
REDIS_URL=redis://localhost:6379
```

<Warning>
Do not use the debugger in production. The debugger can pause the worker and block other jobs.
</Warning>

## Testing

Run the test suite with pytest:

```bash
pytest tests/
```

Tests cover the worker, scheduler, bootstrap, and all platform components.

## Setting up PostgreSQL

PostgreSQL is the primary database for the platform. Install PostgreSQL 16 or later. Create a database named pawabase. The platform uses asyncpg for async database access.

## Setting up Redis

Redis is used for caching, job queues, and event subscriptions. Install Redis 7 or later. Configure the connection string in the REDIS_URL environment variable.

## Installing the package

Install the package in development mode with pip install -e . This creates a link to the source code so that changes are reflected immediately.

## Running the platform

Run the platform with python -m pawabase.bootstrap. This starts the API worker, scheduler, and all background services.

## Hot-reloading in development

During development, the platform supports hot-reloading. When you modify Python source code or flow definitions, the platform automatically reloads the changed modules.

## Debugging with pdb

The platform supports standard Python debugging. Set breakpoints in your code and use pdb or your IDE debugger.

## Debugging with an IDE

You can use any Python-compatible IDE to debug the platform. Set breakpoints in the worker.py, scheduler.py, or bootstrap.py files.

## Testing flows

Flows are tested by creating a FlowRun with the flow definition and a fake Runtime. The fake Runtime implements the Runtime protocol.

## Testing functions

Functions are tested by calling the handler with a fake FunctionContext. The fake FunctionContext provides the same interface as the real FunctionContext.

## Testing the platform

Run the test suite with pytest. Tests cover the worker, scheduler, bootstrap, and all platform components.

## Test fixtures

The platform provides test fixtures for creating fake runtimes, fake function contexts, and fake flow definitions.

## Test coverage

The test suite aims for high coverage of all platform components. Use pytest --cov to measure coverage.

## Environment-specific configuration

The PAWABASE_ENV variable controls whether the platform runs in local or production mode. In local mode, the platform enables development features.

## Logging in development

The platform logs to stdout in development mode. Use standard Python logging to add additional log statements.

## Error handling in development

Errors in the platform are displayed with full stack traces in development mode. Use the error messages to debug issues.

## Performance in development

The platform runs with a single worker in development mode. Use PAWABASE_WORKER_CONCURRENCY to control the number of concurrent jobs.

## Security in development

Never use production secrets in development. Use the .env.example template and create a .env file with non-sensitive defaults.

## Customizing the development environment

You can customize the development environment by modifying the .env file, adding additional entry point groups, or configuring additional services.

## Troubleshooting

If the platform fails to start, check that PostgreSQL and Redis are running. Check the DATABASE_URL and REDIS_URL environment variables.

## Common issues

Common issues include: database not running, Redis not running, incorrect environment variables, missing dependencies, and port conflicts.

## Summary

Local development requires Python 3.12+, PostgreSQL 16+, and Redis 7+. Install the package, create the database, and run the bootstrap.
