If you prefer to run Pawabase directly on your machine (without Docker), this guide walks through the prerequisites, setup, and development workflow. This is useful when you need to debug issues, add custom Python functions, or contribute to the platform.

The Docker installation is still the recommended approach for most users — see [Docker installation](/installation/docker) if you just want to run Pawabase locally and start building.

## When to use this approach

Use the standalone development setup when you need:
- Debugging with `pdb` or an IDE debugger
- Hot-reloading of custom Python functions
- Direct access to the Python package for development
- Running tests against your local setup

<Warning>
This setup is for **development only**. Do not use it in production. The Docker Compose installation includes proper health checks, restart policies, and isolation that are required for production use.
</Warning>

## Prerequisites

| Tool | Version | How to check |
| --- | --- | --- |
| Python | 3.12+ | `python --version` |
| PostgreSQL | 16+ | `pg_config --version` or `psql --version` |
| Redis | 7+ | `redis-cli --version` |
| pip | latest | `pip --version` |

### macOS

```bash
# Using Homebrew
brew install python@3.12 postgresql@16 redis
brew services start postgresql@16
brew services start redis
```

### Ubuntu

```bash
# Python, Postgres, Redis
sudo apt install python3.12 python3-pip postgresql-16 redis-server
sudo systemctl start postgresql redis
```

### Windows

Use **WSL2** with Ubuntu. The standalone setup is not supported on native Windows.

## Installation steps

### 1. Get Pawabase source

```bash
git clone https://github.com/silloHQ/pawabase.git
cd pawabase
```

### 2. Create a virtual environment

```bash
python -m venv .venv
source .venv/bin/activate  # macOS/Linux
# or: .venv\Scripts\activate  # Windows WSL
```

### 3. Install the package

```bash
pip install -e ".[dev]"
```

This installs Pawabase and its development dependencies (pytest, debuggers, etc.).

### 4. Configure environment variables

```bash
cp .env.example .env
```

Edit `.env` and set the required values. For local development, you can use simple values:

```env
# Generate with: openssl rand -hex 32
PAWABASE_INTERNAL_SECRET=dev-internal-secret-00000000000000000000000000000000
PAWABASE_JWT_MASTER_SECRET=dev-jwt-secret-000000000000000000000000000000
PAWABASE_MASTER_KEY=dev-master-key-00000000000000000000000000000000

POSTGRES_PASSWORD=pawabase

# First admin user
PAWABASE_ADMIN_EMAIL=admin@example.com
PAWABASE_ADMIN_PASSWORD=DevPass123!

# Local URLs
PAWABASE_PUBLIC_URL=http://localhost:8080
PAWABASE_PUBLIC_GATEWAY_URL=http://localhost:8080
PAWABASE_COOKIE_SECURE=false
```

### 5. Set up the database

```bash
# Create the database user and database
psql -U postgres -c "CREATE USER pawabase WITH PASSWORD 'pawabase';"
psql -U postgres -c "CREATE DATABASE pawabase OWNER pawabase;"

# Run migrations
pawabase migrate
```

### 6. Start the platform

Open **five** terminal windows:

```bash
# Terminal 1: Gateway (port 8080)
pawabase gateway

# Terminal 2: API (port 8001)
pawabase api

# Terminal 3: Akountz - identity service (port 8002)
pawabase akountz

# Terminal 4: Angula - realtime service (port 8003)
pawabase angula

# Terminal 5: Worker and scheduler
pawabase worker &
pawabase scheduler
```

<Info>
Each process reads its role from the `PAWABASE_ENTRYPOINT` environment variable. The `pawabase` CLI command sets this automatically based on the subcommand (`gateway`, `api`, `akountz`, `angula`, `worker`, `scheduler`).
</Info>

Once all services are running, you can access:
- **Studio** at `http://localhost:8090`
- **API gateway** at `http://localhost:8080`

## Development workflow

### Hot-reloading

The API process watches for changes to:
- Python source files in the code directory (`PAWABASE_CODE_PATH`, default `./code`)
- Resource definitions in Studio (picked up on the next request)
- Flow definitions (picked up on the next execution)

No restart is needed — changes take effect automatically.

### Adding custom functions

1. Create a Python file in the `code/` directory:
   ```python
   # code/my_functions.py
   from pawabase_kit import function

   @function("send_notification")
   def send_notification(ctx, user_id, message):
       ctx.logger.info(f"Sending to {user_id}: {message}")
       return {"status": "sent"}
   ```

2. The function is automatically discovered and available in Studio's flow editor under **Blocks → Functions**.

### Debugging with a debugger

Attach your IDE debugger to the API or worker process:

```bash
# With breakpoints in your code
python -m pdb -m pawabase.api
# or use debugpy for VS Code
DEBUGPY=1 pawabase api
```

### Testing

```bash
pytest tests/
```

Tests cover the API, worker, scheduler, and platform components. See the [test fixtures documentation](/concepts/testing-fixtures) for writing your own tests.

## Common issues

**"Connection refused" on port 5432** — Postgres isn't running. Start it with `brew services start postgresql@16` (macOS) or `sudo systemctl start postgresql` (Linux).

**"Connection refused" on port 6379** — Redis isn't running. Start it with `brew services start redis` or `sudo systemctl start redis`.

**Health check failing** — Make sure all five processes are running. The API health check is at `http://localhost:8001/health`.

**Database migration errors** — Drop and recreate the database, then re-run migrations:
```bash
pawabase migrate
```
