Use this setup to **contribute to Pawabase** or to debug a service with breakpoints. If you only want to build an app on Pawabase, use [Docker](/installation/docker).

## Requirements

- [uv](https://docs.astral.sh/uv/) (Python toolchain)
- Node.js 20+
- Optional: a local Redis. Without it, events, queues and cache fall back to in-memory backends, which is fine for one developer.

## Run everything

```bash
uv sync --all-packages
scripts/dev.sh                  # every service on SQLite, Studio on :8090
STUDIO_VITE=1 scripts/dev.sh    # …with Studio's front end served by `npm run dev`
```

Sign in as `admin@pawabase.local` with `Pawabase!admin1`. Create a project with the reference `demo` to load the example function in `examples/code/demo`.

## Repository layout

```text
packages/kit/        shared library: policies, flow engine and blocks, schemas, service auth
services/api/        Pawabase API, worker and scheduler
services/akountz/    identity
services/angula/     realtime
services/gateway/    public gateway
services/studio/     control plane (Python server + frontend/)
examples/code/       example project code (mounted at /code in Docker)
apps/docs/           this documentation (Mintlify)
docker/              image entrypoint, Postgres init
```

The **kit** is a library, not a service. It holds the policy engine, flow engine and blocks, schema compiler, transformers, service authentication, context propagation, telemetry and service bootstrap, which every service imports.

## Tests and lint

```bash
for p in packages/kit services/*; do (cd $p && uv run pytest -q tests); done
uv run ruff check . && uv run ruff format --check .
```

Each service's tests run in-process with Sillo's `AsyncTestClient` and a fake of the services it depends on, so the suite needs no network, Docker or Redis.

<Note>
Run pytest **from inside each package directory**. Running `pytest services/api/tests` from the repository root fails to import the service's `app` package.
</Note>

## Working on Studio

```bash
cd services/studio/frontend
npm install
npm run dev        # Vite on its own port; Studio proxies assets when STUDIO_VITE=1
npm run build      # production bundle consumed by the Docker image
```

Studio is a Sillo app using `sillo-inertia`. Pages live in `frontend/src/pages`, shared components in `frontend/src/components`, and the definition editors (the form panels for resources, policies, routes and so on) in `frontend/src/components/definitions`.
