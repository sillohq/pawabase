The Pawabase platform can run entirely inside Docker containers. The platform provides a Dockerfile, a docker-compose.yml, and a .env.example template for configuring the environment.

  <Card title="Dockerfile" icon="box">Multi-stage build that produces a lean production image.</Card>
  <Card title="docker-compose.yml" icon="layers">Orchestrates the API worker, scheduler, and Postgres and Redis dependencies.</Card>
</CardGroup>

## docker-compose.yml

The docker-compose.yml at the project root defines the full platform stack:

```yaml
services:
  api:
    build: .
    ports:
      - "8000:8000"
    environment:
      - DATABASE_URL=postgresql://pawabase:secret@postgres:5432/pawabase
      - REDIS_URL=redis://redis:6379
      - PAWABASE_ENV=local
      - PAWABASE_WORKER_CONCURRENCY=4
      - PAWABASE_WORKER_MAX_JOBS_PER_WORKER=100
      - PAWABASE_WORKER_HEARTBEAT_INTERVAL=30
      - PAWABASE_WORKER_HEARTBEAT_TIMEOUT=120
      - PAWABASE_SCHEDULER_INTERVAL=10
      - PAWABASE_ENTRYPOINT_GROUPS=default
    volumes:
      - .:/app
    command: python -m pawabase.bootstrap
  postgres:
    image: postgres:16-alpine
    environment:
      POSTGRES_DB: pawabase
      POSTGRES_USER: pawabase
      POSTGRES_PASSWORD: secret
    volumes:
      - pgdata:/var/lib/postgresql/data
  redis:
    image: redis:7-alpine
    command: redis-server --appendonly yes
    volumes:
      - redisdata:/data
volumes:
  pgdata:
  redisdata:
```

## Dockerfile

The Dockerfile uses a multi-stage build to keep the production image lean:

```dockerfile
FROM python:3.12-slim AS base
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

FROM base AS build
COPY . .
RUN pip install --no-cache-dir -e .

FROM base AS production
COPY --from=build /app /app
COPY docker/entrypoint.sh /entrypoint.sh
RUN chmod +x /entrypoint.sh
ENTRYPOINT ["/entrypoint.sh"]
CMD ["python", "-m", "pawabase.bootstrap"]
```

## .env.example

The .env.example template documents all environment variables:

```env
PAWABASE_ENV=local
PAWABASE_ENTRYPOINT_GROUPS=default
PAWABASE_WORKER_CONCURRENCY=4
PAWABASE_WORKER_MAX_JOBS_PER_WORKER=100
PAWABASE_WORKER_HEARTBEAT_INTERVAL=30
PAWABASE_WORKER_HEARTBEAT_TIMEOUT=120
PAWABASE_SCHEDULER_INTERVAL=10
DATABASE_URL=postgresql://pawabase:secret@postgres:5432/pawabase
REDIS_URL=redis://redis:6379
```

<Note>
The PAWABASE_ENTRYPOINT_GROUPS variable controls which entry point groups are loaded at startup. The default group includes the built-in blocks and functions.
</Note>

## The entrypoint script

The docker/entrypoint.sh script waits for Postgres and Redis to be ready, then starts the bootstrap process:

```bash
#!/bin/sh
set -e

# Wait for Postgres
until pg_isready -h postgres -U pawabase; do
  echo "Waiting for Postgres..."
  sleep 1
done

# Wait for Redis
until redis-cli ping; do
  echo "Waiting for Redis..."
  sleep 1
done

exec python -m pawabase.bootstrap
```

## Volumes and persistence

Postgres and Redis data are persisted using named Docker volumes. The API service mounts the project directory as a volume for hot-reloading during development. In production, remove the volumes mount and rebuild the image.

## Development vs production

For development, docker-compose up starts the full stack with hot-reloading. For production, build the image and run it with docker run or deploy to a container orchestration platform. The key difference is the PAWABASE_ENV variable.

## Environment variables

The platform reads environment variables from .env or the container environment. Key variables include PAWABASE_ENV, DATABASE_URL, REDIS_URL, PAWABASE_WORKER_CONCURRENCY, PAWABASE_SCHEDULER_INTERVAL, and PAWABASE_ENTRYPOINT_GROUPS.

## Worker configuration

The worker is configured by WorkerOptions which reads from environment variables. PAWABASE_WORKER_CONCURRENCY controls the number of concurrent jobs. PAWABASE_WORKER_MAX_JOBS_PER_WORKER controls how many jobs a worker processes before shutting down for a restart.

## Scheduler configuration

The scheduler is configured by SchedulerOptions which reads from environment variables. PAWABASE_SCHEDULER_INTERVAL controls the interval in seconds between schedule checks.

## Database configuration

The DATABASE_URL environment variable specifies the PostgreSQL connection string. The platform uses asyncpg for async database access. The connection pool size is configured separately.

## Redis configuration

The REDIS_URL environment variable specifies the Redis connection string. Redis is used for caching, job queues, and event subscriptions. The platform uses aioredis for async Redis access.

## Entry point groups

The PAWABASE_ENTRYPOINT_GROUPS environment variable controls which entry point groups are loaded at startup. The default group includes built-in blocks and functions. Additional groups can be added for custom extensions.

## Multi-stage build

The Dockerfile uses a multi-stage build. The base stage installs dependencies. The build stage installs the package. The production stage copies from the build stage and adds the entrypoint script.

## Health checks

The entrypoint script waits for Postgres and Redis to be ready before starting the platform. This ensures the platform does not start with unavailable dependencies.

## Volume management

Postgres and Redis data are persisted using named Docker volumes. The API service mounts the project directory for hot-reloading. In production, remove the volumes mount and rebuild the image.

## Networking

The API service exposes port 8000. The Postgres and Redis services are internal-only. The API service connects to Postgres and Redis using their service names as hostnames.

## Scaling

The API service can be scaled horizontally using docker-compose scale api=N. The scheduler should only run one instance. The worker can be scaled for parallel job processing.

## Logs

The platform logs to stdout. Docker captures the logs. Use docker-compose logs api to view the API logs. Use docker-compose logs postgres to view the database logs.

## Debugging

Use docker-compose exec api to run commands inside the container. Use docker-compose exec postgres psql to query the database. Use docker-compose exec redis redis-cli to query Redis.

## Customization

You can customize the Dockerfile to add additional dependencies. You can customize docker-compose.yml to add additional services. You can customize the entrypoint script to add additional startup steps.

## Security

Never commit .env files containing secrets. Use Docker secrets or a secrets manager for production. The .env.example file contains non-sensitive defaults.

## Performance

Set PAWABASE_WORKER_CONCURRENCY to the number of CPU cores. Set PAWABASE_WORKER_MAX_JOBS_PER_WORKER to a value that balances throughput with memory usage. Set PAWABASE_SCHEDULER_INTERVAL based on the required schedule precision.

## Monitoring

Use Docker stats to monitor resource usage. Use Docker Compose logs for application logs. The platform also exports metrics via ctx.runtime.metric().

## Backup

Back up the pgdata volume regularly. Use docker-compose exec postgres pg_dump to create a backup. Use docker-compose exec redis redis-cli BGSAVE to create a Redis backup.

## Recovery

To recover from a failure, restore the pgdata and redisdata volumes. Restart the API service. The platform will reconnect to the database and Redis automatically.

## Upgrade

To upgrade the platform, rebuild the Docker image. Run docker-compose build --no-cache. Restart the services. The data volumes persist across upgrades.

## Summary

Docker provides a consistent environment for running Pawabase. The docker-compose.yml orchestrates the full platform stack. The Dockerfile produces a lean production image.
