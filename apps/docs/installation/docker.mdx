Docker Compose is the recommended way to run Pawabase. A single command starts all services — the gateway, API, worker, scheduler, identity service (Akountz), realtime service (Angula), and Studio — each as a separate container with its own health checks and restart policy.

<Steps>
  <Step title="1. Install Docker">
    Pawabase requires Docker Engine 24+ with Compose V2. If you don't have Docker, install it from [docker.com](https://docs.docker.com/get-docker/).

    Verify:

    ```bash
    docker --version
    docker compose version
    ```
  </Step>

  <Step title="2. Get the compose file">
    Download the latest `docker-compose.yml` and `.env.example` from the [Pawabase release page](https://github.com/silloHQ/pawabase/releases):

    ```bash
    mkdir pawabase && cd pawabase
    curl -L https://github.com/silloHQ/pawabase/releases/latest/download/docker-compose.yml -o docker-compose.yml
    curl -L https://github.com/silloHQ/pawabase/releases/latest/download/.env.example -o .env.example
    ```
  </Step>

  <Step title="3. Configure secrets">
    Copy the example file and set the required secrets:

    ```bash
    cp .env.example .env
    ```

    Edit `.env` and fill in these **required** values:

    | Variable | What to set | How to generate |
    | --- | --- | --- |
    | `POSTGRES_PASSWORD` | Password for the Postgres user | `openssl rand -hex 16` |
    | `PAWABASE_INTERNAL_SECRET` | Signs internal service tokens | `openssl rand -hex 32` |
    | `PAWABASE_JWT_MASTER_SECRET` | Derives user token secrets | `openssl rand -hex 32` |
    | `PAWABASE_MASTER_KEY` | Encrypts secrets at rest | `openssl rand -hex 32` |
    | `PAWABASE_ADMIN_EMAIL` | First Studio operator email | Your email address |
    | `PAWABASE_ADMIN_PASSWORD` | First Studio operator password | 8+ chars, upper+lower+digit+symbol |
    | `PAWABASE_PUBLIC_URL` | Public URL clients use | `http://localhost:8080` for local, `https://api.yourdomain.com` for production |

    <Warning>
    **Never reuse secrets between environments.** Generate unique secrets for each project. Store `.env` outside version control; the file contains passwords and encryption keys.
    </Warning>

    <Note>
    `PAWABASE_COOKIE_SECURE` controls whether Studio's session cookie requires HTTPS. Leave it `false` for local development; set to `true` in production behind a TLS-terminating proxy.
    </Note>
  </Step>

  <Step title="4. Start the platform">
    ```bash
    docker compose up -d
    ```

    The first start pulls Docker images and initializes the database. This takes 30–60 seconds. Track progress:

    ```bash
    docker compose logs -f --wait
    ```
  </Step>

  <Step title="5. Verify everything is healthy">
    Each service has a health check. Wait for all to report healthy:

    ```bash
    docker compose ps
    ```

    All services should show `healthy` in the `State` column. If any shows `unhealthy`, check its logs:

    ```bash
    docker compose logs api
    ```

    Once healthy, Studio is at [http://localhost:8090](http://localhost:8090) and the API gateway is at `http://localhost:8080`.
  </Step>
</Steps>

## What each service does

| Service | Port | Purpose |
| --- | --- | --- |
| **gateway** | 8080 | The only public entry point for clients. Routes to API, Akountz, and Angula based on the path. |
| **studio** | 8090 | The web UI for configuring projects, resources, flows, and observing runs. |
| **api** | 8001 | Handles REST API requests, data plane operations, and triggers flow execution. |
| **akountz** | 8002 | Identity management: users, sessions, MFA, organizations. |
| **angula** | 8003 | Realtime engine: WebSocket channels, presence, message history. |
| **worker** | — | Background job processing, flow execution, email, webhooks. |
| **scheduler** | — | Cron and interval-based scheduled triggers. |
| **postgres** | 5432 | Platform state (definitions, audit log, sessions). |
| **redis** | 6379 | Job queue, event bus, realtime pub/sub, caching. |

<Note>
The gateway is the **only** port you need to expose to clients in production. Studio, API, Akountz, and Angula are on the internal network and should not be directly reachable from the internet.
</Note>

## Volumes and data persistence

```text
postgres  →  /var/lib/postgresql/data   (platform state)
redis     →  /data                      (queues, events, cache)
api-data  →  /data                      (compiled apps, storage objects, file-based queues)
```

Named volumes persist across `docker compose down` and `docker compose up`. They are also preserved across image upgrades, so your projects, users, and data survive restarts.

Back up regularly — see [Self-hosting → Backups](/self-hosting/backups).

## Production checklist

Before going live:

1. **Set `PAWABASE_PUBLIC_URL`** to your real domain with HTTPS.
2. **Set `PAWABASE_COOKIE_SECURE=true`** so Studio sessions require HTTPS.
3. **Use a reverse proxy** (Caddy or Nginx) in front of the gateway to terminate TLS. See [TLS setup](/self-hosting/tls).
4. **Set strong, unique secrets** — never commit `.env` with real secrets.
5. **Review resource limits** — set `PAWABASE_WORKER_CONCURRENCY` based on your CPU cores.
6. **Enable health checks** — the gateway exposes `/health` for your load balancer to monitor.
7. **Configure backups** — see the production checklist page.

## Managing the stack

```bash
docker compose up -d        # Start all services
docker compose down         # Stop all services (data persists)
docker compose restart      # Restart everything
docker compose logs -f api  # Follow API logs
docker compose exec api sh  # Open a shell in the API container
```

## Upgrading

```bash
docker compose pull          # Get the latest image
docker compose up -d         # Restart with the new version
```

Database migrations run automatically on startup. Check the [Upgrade guide](/self-hosting/upgrades) for version-specific steps and breaking changes.
