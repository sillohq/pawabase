Docker Compose is the supported way to run Pawabase, locally and in production. The repository's `docker-compose.yml` starts every service from **one image** with a different command, so services stay separate processes and containers while sharing a single build.

## What gets started

| Container | Command | Port | Role |
| --- | --- | --- | --- |
| `gateway` | `gateway` | **8080** (public) | The only public entry point: key resolution, signed context, CORS, rate limits, HTTP and WebSocket proxying. |
| `studio` | `studio` | **8090** (public) | The control plane (Sillo + Inertia + React). |
| `api` | `api` | 8001 | Projects, definitions, the data plane, storage, functions, flows, events, keys, secrets, docs. |
| `worker` | `worker` | — | Queue workers: flows, functions, event processing, webhooks, mail. |
| `scheduler` | `scheduler` | — | Cron and interval schedules. **Run exactly one.** |
| `akountz` | `akountz` | 8002 | Identity: users, sessions, OAuth, MFA, organizations, roles. |
| `angula` | `angula` | 8003 | Realtime: channels, presence, history. |
| `postgres` | — | — | The platform's own state (one database for the API, one for Akountz). |
| `redis` | — | — | Queues, events, cache, rate limits, realtime fan-out. |

Only the gateway and Studio publish ports. Everything else talks over the Compose network with short-lived, audience-bound service tokens.

## Install

<Steps>
  <Step title="Clone">
    ```bash
    git clone https://github.com/sillohq/pawabase.git && cd pawabase
    ```
  </Step>
  <Step title="Configure">
    For a local trial, copy the public test settings:
    ```bash
    cp .env.test .env
    ```
    For anything else, start from the example and generate real secrets:
    ```bash
    cp .env.example .env
    for v in PAWABASE_INTERNAL_SECRET PAWABASE_JWT_MASTER_SECRET PAWABASE_MASTER_KEY POSTGRES_PASSWORD; do
      sed -i.bak "s|^$v=.*|$v=$(openssl rand -hex 32)|" .env
    done
    ```
    Then set `PAWABASE_ADMIN_EMAIL` and `PAWABASE_ADMIN_PASSWORD` (upper- and lower-case, a digit and a symbol). See [environment variables](/reference/environment-variables) for every option.
  </Step>
  <Step title="Start">
    ```bash
    docker compose up -d
    docker compose ps
    ```
    Containers apply their migrations on start. The first operator is created from `PAWABASE_ADMIN_*` on first boot.
  </Step>
  <Step title="Open Studio">
    Visit `http://localhost:8090` and sign in with your admin credentials.
  </Step>
</Steps>

## Where data lives

<Tabs>
  <Tab title="Platform state">
    The bundled Postgres holds definitions, keys, secrets (encrypted), users, sessions, event and run history. It is the platform's database, not your app's.
  </Tab>
  <Tab title="Application data">
    Each environment's resource tables live wherever you point **Settings → Infrastructure → `database_url`**: your own Postgres, MySQL or SQLite. Unset, Pawabase uses `PAWABASE_DEFAULT_DATA_URL` (by default a SQLite file per environment under the `api-data` volume). See [Use your own database](/data/your-database).
  </Tab>
  <Tab title="Files and mail">
    Storage defaults to the local driver on the `api-data` volume; point an environment at any S3-compatible service instead. Mail is suppressed and logged until you configure SMTP.
  </Tab>
</Tabs>

## Common commands

```bash
docker compose logs -f api worker          # follow the data plane and workers
docker compose restart scheduler           # after changing schedules outside Studio
docker compose run --rm api migrate        # when PAWABASE_MIGRATE=false
docker compose up -d --build               # after pulling a new version
docker compose down                        # stop (volumes are kept)
```

<Tip>
Rebuild with `docker compose up -d --build` after changing anything under `services/` or `packages/`. Services don't mount source code; only project code under `examples/code` (mounted at `/code`) is read live.
</Tip>

## Troubleshooting

<AccordionGroup>
  <Accordion title="A service keeps restarting">
    Read its logs: `docker compose logs --tail=100 <service>`. In production mode (`PAWABASE_APP_ENV=production`, the Compose default), every service **refuses to start** while a development secret is still configured. That's deliberate.
  </Accordion>
  <Accordion title="Studio loads but sign-in fails">
    The admin is created only on the first start. If you changed `PAWABASE_ADMIN_PASSWORD` later, reset it from the Akountz container or recreate the volumes in a throwaway install.
  </Accordion>
  <Accordion title="Links in emails point to localhost">
    Set `PAWABASE_PUBLIC_URL` and `PAWABASE_PUBLIC_GATEWAY_URL` to the address clients use. Email links, OAuth callbacks and signed storage URLs are built from them.
  </Accordion>
</AccordionGroup>
