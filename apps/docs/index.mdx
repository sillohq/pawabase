Pawabase is a backend platform that compiles your backend **definitions** — resources, policies, flows, buckets, schedules, and more — into a running API for each environment of your project. You describe *what* your backend should do, and Pawabase generates the routes, models, validation, policies, and OpenAPI docs that serve traffic.

<Callout>
You do **not** need to understand Pawabase's source code or internal Python implementation to use it. Everything you configure lives in **Studio** or as declarative definitions you manage through the Platform API. This documentation teaches you how to build backends with Pawabase, not how Pawabase is built internally.
</Callout>

## What can I build with Pawabase?

Anything that needs a backend: APIs with CRUD, file storage, user authentication, real-time collaboration, background processing, scheduled jobs, webhook handling, and event-driven automation. See the [feature comparison](/compare/feature-matrix) for the full picture, or read the [mental model](/concepts/mental-model) for the single idea that explains every feature.

## Learning paths

### Beginner journey

```text
Understand Pawabase      →  Quick start        →  Build a backend
  ↓                            ↓                      ↓
[What is Pawabase?]       [Quickstart guide]   [First project tutorial]
  ↓                            ↓                      ↓
Core concepts              Connect to Studio    Resources → Flows → Events
```

**Goal:** Start with zero knowledge. End with a working, deployed backend you understand end to end.

### Advanced journey

```text
Application  →  Platform API  →  Flow  →  Database  →  Event
     ↓            ↓            ↓         ↓          ↓
  Auth    →  Validation   →  Policy  →  Queue  →  Webhook  →  Realtime
```

**Goal:** Build complex, production-grade systems that span multiple Pawabase capabilities — multi-service event-driven architectures, approval workflows with retries, real-time dashboards with presence, and more.

See the [advanced examples](/flows/recipes) and the [concepts section](/concepts) for the building blocks.
