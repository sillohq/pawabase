## Summary

The Pawabase documentation covers getting started, installation, code, and concepts.

## Getting started

Start with the quickstart guide to get from zero to a working Pawabase platform in minutes. The quickstart covers creating a project, defining flows and functions, and running the platform.

## Installation

Choose between Docker and local development. Docker provides a consistent environment with docker-compose. Local development requires Python 3.12+, PostgreSQL 16+, and Redis 7+.

## Code

The code documentation covers all aspects of building with Pawabase. Functions handle the algorithm. Runtime handles the execution engine. Extension routes handle HTTP-specific logic.

## Mental model

The mental model documentation explains how Pawabase thinks about backend logic. It covers the core concepts that underpin all platform features.

## Overview

The overview documentation provides a deep dive into the platform architecture. It covers the execution flow, the block registry, and the function registry.

## Functions

Functions are the core computation units in Pawabase. Write functions with the @function decorator. Register functions via entry point groups.

## Runtime

The runtime protocol defines how the platform executes flows and functions. Implement the Runtime protocol to customize execution.

## Extension routes

Extension routes are HTTP handlers added via the pawabase.routes entry point group. They have full access to the Sillo router.

## Flows or code

The decision framework for choosing between flows and functions. Flows handle orchestration. Functions handle algorithms.

## Python extensions

Extending Pawabase with Python packages. Add custom blocks, functions, and routes via entry point groups.

## Docker

Running Pawabase in Docker containers. The platform provides a Dockerfile, a docker-compose.yml, and a .env.example template.

## Local development

Setting up Pawabase locally for development. Requires Python 3.12+, PostgreSQL 16+, and Redis 7+.

## Quickstart

Get started with Pawabase in minutes. Create a project, define flows and functions, and run the platform.

## Architecture

The platform architecture consists of the API worker, scheduler, block registry, function registry, and runtime protocol.

## Best practices

Use flows for orchestration and functions for algorithms. Keep flows focused on shape and functions focused on algorithm.

## Error handling

Flows have built-in error handling with error edges. Functions raise exceptions. Handle errors gracefully.

## Testing

Test flows with a fake runtime. Test functions with a fake FunctionContext. Use pytest for the test suite.

## Performance

Consider the performance implications of each architectural choice. Inline function calls are faster than background dispatch.

## Security

All components are subject to the same policy engine. Functions have the policy parameter.

## Observability

Both flows and functions produce observable data in Studio. Use the platform observability to monitor execution.

## Versioning

Flows are versioned per environment as JSON. Functions are versioned with git. The platform tracks flow versions automatically.

## Collaboration

Flows can be edited by non-engineers in Studio. Functions require Python knowledge.

## Deployment

Both flows and functions are deployed immediately. No traditional deployment is needed.
