## Overview

Filtering allows you to query resource lists using filter[<field>] query parameters. Each filter parameter targets a specific field and applies a comparison operator.

Filters are applied before pagination, sorting, and policy evaluation. The platform translates filter parameters into SQL WHERE clauses for efficient database querying.

## String filtering

String fields support exact match filtering and pattern matching. The basic filter[<field>]=value syntax performs an exact match.

For partial matching, use filter[<field>][contains]=value. This performs a LIKE query against the database.

String filters are case-sensitive by default. Case-insensitive matching is available with filter[<field>][icontains]=value.

| Operator | Syntax | Example | Meaning |
| --- | --- | --- | --- |
| Exact | `filter[name]=John` | Name equals John | Exact match |
| Contains | `filter[name][contains]=ohn` | Name contains ohn | Partial match |
| Starts with | `filter[name][starts]=Jo` | Name starts with Jo | Prefix match |
| Ends with | `filter[name][ends]=hn` | Name ends with hn | Suffix match |
| Not equal | `filter[name][neq]=John` | Name not John | Exclusion |

## Number filtering

Number and integer fields support comparison operators: equals, not equals, greater than, less than, greater than or equal, and less than or equal.

| Operator | Syntax | Example | Meaning |
| --- | --- | --- | --- |
| Equals | `filter[amount]=100` | Amount equals 100 | Exact match |
| Greater than | `filter[amount][gt]=100` | Amount > 100 | Above threshold |
| Less than | `filter[amount][lt]=1000` | Amount < 1000 | Below threshold |
| Range | `filter[amount][gte]=100&filter[amount][lte]=500` | 100 <= amount <= 500 | Range query |

## Date and datetime filtering

Date and datetime fields support comparison operators and range queries.

Date filters use ISO 8601 format. For example, filter[due_on][gte]=2026-01-01 returns records with due_on on or after January 1, 2026.

## Boolean filtering

Boolean fields support exact match filtering. filter[status]=true returns records where status is true.

## Array filtering

Array fields support membership testing. filter[tags][contains]=finance returns records whose tags array contains the finance element.

## Multiple filters

Multiple filter parameters are ANDed together. filter[status]=overdue&filter[amount][gt]=100 returns records where status is overdue AND amount is greater than 100.

## Filter pushdown

The platform pushes filter conditions into SQL WHERE clauses whenever possible. This means filters are executed at the database level, which is much more efficient than fetching all rows and filtering in application code.

When a filter cannot be pushed down — for example, when the field is not indexed or the filter uses a complex expression — the platform fetches rows and filters them in application code. This is slower but produces the same results.

## Filtering and policies

Filters interact with policies. A filter may return fewer results than expected because the policy's WHERE clause further restricts the result set.

The total count in the list response reflects the combined effect of filters and policies.

## Troubleshooting

- Filter returns unexpected results: check that the field name is correct and the operator matches the field type.

- Filter returns 400: the field name does not exist or the operator is not valid for the field type.

- Performance issues with filters: ensure the filtered fields are indexed.
