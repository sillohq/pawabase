**Studio → Database** gives operators a window into an environment's data store without leaving the control plane.

## What it shows

- The **dialect** (`postgres`, `mysql`, `sqlite`) and whether the environment uses **your database** or the platform default.
- Every **table**, marked with the resource that exposes it (if any).
- For a table: its **columns** with types, nullability and keys, and a paginated **row browser**.

## Running SQL

The query box runs **one statement** at a time.

| Statement | Behaviour |
| --- | --- |
| Read (`SELECT`, `WITH`, `EXPLAIN`, `PRAGMA`, `SHOW`, `DESCRIBE`) | Runs; up to 5,000 rows returned (`truncated: true` beyond that) |
| Anything that writes | Refused with `400 this statement writes; set allow_write to run it`, unless **allow writes** is ticked |
| Several statements (`;`) | Treated as a write |

```sql
SELECT c.name, COUNT(s.id) AS students
FROM classes c LEFT JOIN students s ON s.class_id = c.id AND s.status = 'active'
GROUP BY c.name ORDER BY c.name;
```

The same endpoint is `POST /platform/v1/projects/{ref}/envs/{env}/database/query`:

```json
{ "sql": "UPDATE invoices SET status = ? WHERE id = ?", "params": ["void", 44], "allow_write": true }
```

Queries time out after `PAWABASE_QUERY_TIMEOUT` seconds (default 15) with `504`.

<Warning>
The console runs with the environment's database credentials and **bypasses policies, validation, events and realtime**. A write made here is recorded in the [audit log](/operate/audit-log) as `database.write` with the SQL, and every resource cache in the environment is invalidated, but no `*.updated` events fire and no flows run. Prefer the resource record editor for data changes.
</Warning>

## Editing records the safe way

**Resources → a resource → Records** writes through the API, so validation, events, cache invalidation and realtime all happen, just as for client writes.

## Prototyping flow SQL

The console is the fastest way to develop the SQL for a flow's `db.query` block: run it here against real data, then paste it into the block with `?` placeholders. Note that `db.query` itself only accepts read-only statements; flows write through resource blocks and `db.transaction`.
