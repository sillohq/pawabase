Pawabase keeps **your application data in your database**. The platform's own Postgres only holds definitions and platform state.

## Configure an environment

**Settings → Infrastructure**:

```json
{ "database_url": "postgres://app:secret://DB_PASSWORD@db.internal:5432/school" }
```

Put the password in [Secrets](/operate/secrets) as `DB_PASSWORD` and reference it; the resolved URL is never returned by the API or shown in Studio.

| Database | URL form |
| --- | --- |
| PostgreSQL | `postgres://user:pass@host:5432/dbname` |
| MySQL / MariaDB | `mysql://user:pass@host:3306/dbname` |
| SQLite | `sqlite:///absolute/path/app.db` |

Without a `database_url`, the environment uses `PAWABASE_DEFAULT_DATA_URL` (default: a SQLite file per environment, `…/{project}__{env}.db`), which is ideal for development and nothing else.

## One database per environment

Give each environment its own database (or at least its own schema). Environments are isolated by configuration, not by a shared table prefix, so pointing two at the same database would mix their data.

## Existing schemas

Pawabase works with tables it didn't create:

- set a resource's `table` and `primary_key` to match;
- declare only the columns the API should see;
- skip migrate, or use it only to add columns.

Relations, filters and policies work on existing tables as long as the columns are declared as fields.

## Portability rules for SQL you write

Flows can run read-only SQL with `db.query`. To keep flows working when you move from SQLite in development to Postgres in production:

- use `?` placeholders (they're adapted per dialect) and pass values as `params`;
- prefer standard SQL: `CASE`, `COALESCE`, `CAST(x AS TEXT)`, `SUBSTR`, `||`, CTEs and window functions (`RANK() OVER …`) work on both;
- avoid dialect functions (`printf`, `lpad`, `date('now')`); pass "today" in as a parameter from `time.now` with `format: date`;
- compare booleans with a parameter (`= ?` with `true`) rather than `= 1`.

## Connection behaviour

Connections are opened per environment on first use and pooled by the underlying engine (Tortoise, Sillo Record's ORM). SQL is built with PyPika. Query time for `db.query` is capped by `PAWABASE_QUERY_TIMEOUT` (default 15 s).
