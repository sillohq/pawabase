A **schema** is a named list of fields with no table behind it. Use schemas to:

- give embedded objects a validated shape (`teachers.address` → `Address`);
- define the **request body** of a custom route (`input_schema`);
- document a custom route's **response** (`response_schema`);
- nest shapes inside other schemas (`BulkGrades.entries` → array of `GradeEntry`).

## Defining a schema

```json
{
  "name": "GradeEntry",
  "description": "One student's score on an assessment.",
  "fields": [
    { "name": "student_id", "type": "integer", "required": true },
    { "name": "score", "type": "number", "required": true, "minimum": 0 },
    { "name": "remarks", "type": "string", "max_length": 240 }
  ]
}
```

Names start with a letter and use letters, digits and underscores (`^[A-Za-z][A-Za-z0-9_]{0,62}$`). PascalCase reads well in OpenAPI.

## Referencing a schema

<CodeGroup>
```json As a field
{ "name": "address", "type": "ref", "schema": "Address", "nullable": true }
```
```json As array items
{ "name": "entries", "type": "array", "items": { "type": "ref", "schema": "GradeEntry" } }
```
```json As a route body
{ "method": "POST", "path": "/grades/bulk", "input_schema": "BulkGrades", "handler_type": "flow", "handler": "grade_book" }
```
</CodeGroup>

References are resolved when the environment compiles. Referencing a schema that doesn't exist is reported as a definition problem, and the affected route isn't served.

## Schemas vs inline fields

| Use a schema when | Use inline `fields` when |
| --- | --- |
| The shape is reused | It's used once |
| You want one named component in OpenAPI | A throwaway body is fine |
| Clients generate types from the docs | |

Custom routes can use either: `input_schema` for a named schema, or `input_fields` for an inline list. See [custom routes](/data/custom-routes).

## Evolving schemas

Changing a schema changes every resource field and route that references it on the next request. Adding optional fields is always safe; making a field required rejects old clients that don't send it. For breaking changes, create `AddressV2` and move references over.
