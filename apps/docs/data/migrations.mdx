## Overview

Migrations manage database schema changes when resource definitions change. The platform handles most schema changes automatically, but some require manual intervention.

## Automatic migrations

When you add fields to a resource definition, the platform automatically generates migration suggestions. Running the migration adds new columns to the database table.

The platform creates the appropriate column type based on the field type: VARCHAR for strings, INTEGER/BIGINT for integers, DECIMAL for numbers, BOOLEAN for booleans, DATE/TIMESTAMP for dates and datetimes.

The platform also creates indexes on frequently queried fields to ensure good performance.

## Manual migrations

Some changes require manual migration: changing id_type, changing primary_key, changing table, or modifying column types that require data transformation.

For these changes, the platform provides guidance on the required manual steps. You should follow the guidance carefully to avoid data loss.

## Migration safety

Migrations are safe and reversible. They add columns, modify constraints, and create indexes without dropping existing data.

The platform validates that migrations are safe before executing them. If a migration would cause data loss, the platform warns you and refuses to execute it.

## Skipping migrations

When exposing an existing table, you can skip the migrate step if the schema is managed elsewhere. Columns not declared in the resource definition remain invisible to API clients.

## Migration and promotion

When you promote a resource definition between environments, the platform copies the definition and any pending migrations to the target environment.

Run migrations on the target environment after promotion to ensure the database schema matches the new definition.

## Troubleshooting

- Migration fails: check that the database connection is valid and the migration script is correct.

- Column already exists: the field was already added to the database. The migration may be a no-op.

- Data migration needed: changing a field type may require transforming existing data. Use a custom route or the database console for data migration.
