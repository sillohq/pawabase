## Overview

This page covers the complete reference for How Pawabase caches resource responses per-caller in Pawabase. Every detail, edge case, and configuration option is documented here.

The platform compiles resource definitions into live HTTP routes, validation models, and database columns at request time. Everything described below is automatic once you define your resource.

If you are new to Pawabase resources, start with [Resources ->](/data/resources) for the mental model and the five operations. Then return here for deep dives into specific subsystems.

## Core Concepts

The foundation of this feature is built into the platform and requires no additional configuration beyond the resource definition.

The feature works automatically based on the resource definition and the environment configuration.

Understanding the interaction between this feature and other platform features is essential for building robust applications.

## Configuration

Configuration is done through the resource definition. Every option has a default value that is sensible for most use cases.

The platform validates all configuration values at save time and rejects invalid configurations with specific error messages.

Configuration changes take effect immediately after recompilation on the next request.

## Usage Patterns

The most common usage pattern involves defining the relevant configuration in the resource definition and letting the platform handle the rest.

Advanced usage patterns involve combining multiple features to achieve complex behavior.

The platform provides extensive flexibility while maintaining a simple configuration model.

## Integration with Other Features

This feature integrates with policies, caching, events, and realtime subscriptions. The platform handles all integration automatically.

When this feature is enabled alongside other features, the platform compiles them together into a unified runtime.

The interaction between features follows a predictable order that is documented in the request lifecycle.

## Performance Impact

The platform optimizes this feature for performance at scale. Policy pushdown, per-caller caching, and connection pooling all contribute to efficient operation.

The `per_page` parameter has a maximum of 200 rows per page to prevent excessively large result sets.

The platform uses automatic index creation for frequently queried fields to ensure good performance.

## Security Considerations

Security is built into this feature at every layer. The policy gate is the primary security mechanism, but field-level security through `write_only` and selective field declaration provides additional protection.

All data access goes through the policy gate unless using the database console, which bypasses all resource-level security.

## Troubleshooting

If the feature does not behave as expected, check that the configuration is correct in the resource definition.

Compiled state may be cached. Retry with a fresh request if behavior seems stale.

Check the API reference tab in Studio to inspect the compiled OpenAPI document.

## Best Practices

Start with the default configuration and adjust as needed. The defaults are sensible for most use cases.

Test your configuration thoroughly before deploying to production.

Use the platform's monitoring and logging features to observe the feature in action.

## Troubleshooting

If you encounter issues, check that the resource definition is saved correctly and that the environment version is current.

Compiled state is cached per version. Retry with a fresh request if behavior seems stale.

Check the API reference tab in Studio to inspect the compiled OpenAPI document.

For policy-related issues, verify that the policy identifier exists and that the policy conditions are correctly configured.

## FAQ

Can I configure multiple instances of this feature? Yes, the platform supports multiple configurations per resource.

Does this feature work with custom routes? Yes, custom routes can use the same features as resource operations.

How does this interact with caching? The platform automatically invalidates cached responses when the relevant data changes.

Is this feature available in all environments? Yes, resource definitions are versioned per environment.

Can I use this with the database console? Some features bypass the resource layer and work directly on the database.
