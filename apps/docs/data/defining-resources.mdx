Create resources in **Studio → Resources → New resource**, or with `POST /platform/v1/projects/{ref}/envs/{env}/resources`. The Studio panel groups settings into *Details*, *Fields*, *Access*, *Relations* and *Behaviour*.

## Details

<ParamField path="name" type="string" required>
  Lower-case letters, digits and underscores, starting with a letter (`^[a-z][a-z0-9_]{0,62}$`). It becomes the URL segment (`/rest/v1/<name>`), the event prefix and the default table name. **Fixed once created.** Reserved: `docs`, `openapi.json`, `x`, `rpc`, `health`, `internal`, `platform`.
</ParamField>
<ParamField path="table" type="string | null">
  The database table. Defaults to `name`. Set it to expose an **existing** table under a different API name.
</ParamField>
<ParamField path="primary_key" type="string" default="id">
  The primary-key column.
</ParamField>
<ParamField path="id_type" type="'integer' | 'uuid'" default="integer">
  `integer` for auto-increment ids, `uuid` for server-generated UUIDs, useful when ids appear in URLs and shouldn't be guessable or countable.
</ParamField>
<ParamField path="description" type="string">
  Shown in Studio and the API docs.
</ParamField>

## Fields

A list of field specs. The primary key and timestamps are added for you. See [field types](/data/field-types) and [validation](/data/validation).

```json
{ "name": "title", "type": "string", "required": true, "max_length": 200, "description": "Shown in lists" }
```

## Access

```json
"operations": {
  "list":   { "enabled": true,  "policy": "public" },
  "get":    { "enabled": true,  "policy": "public" },
  "create": { "enabled": true,  "policy": "authenticated" },
  "update": { "enabled": true,  "policy": "owner" },
  "delete": { "enabled": false, "policy": null }
}
```

`policy` accepts a policy **name** (built-in or yours), a **parameterised** built-in (`"role:admin"`, `"owner:author_id"`), an **inline condition**, a **list** of references that must all pass, or `null`. For resource operations, `null` means *secret keys and operators only*. [Policy references →](/policies/references)

## Behaviour

<ParamField path="owner_field" type="string | null">
  A field set to the **caller's user id** on every create, overriding any value the client sent. Anonymous creates are refused with `401`. Pair it with the `owner` policy for private rows. Only use it for "who created this"; for a user id that someone else assigns (e.g. an admin linking a guardian), use a normal field.
</ParamField>
<ParamField path="timestamps" type="boolean" default="true">
  Maintain `created_at` and `updated_at`.
</ParamField>
<ParamField path="events" type="boolean" default="true">
  Emit `<name>.created|updated|deleted` with `{resource, change, record}`. See [resource events](/data/resource-events).
</ParamField>
<ParamField path="realtime" type="boolean" default="false">
  Publish every change on the `resource:<name>` channel.
</ParamField>
<ParamField path="transformer" type="string | object | null">
  A named or inline [transformer](/data/transformers) applied to every response.
</ParamField>
<ParamField path="cache_ttl" type="integer" default="0">
  Seconds to cache `list` and `get` responses, per caller (0–86400). Writes invalidate. See [caching](/data/caching).
</ParamField>
<ParamField path="rate_limit" type="object">
  `{"limit": 60, "window": 60}`: requests per window per caller, counted across instances. `{}` for none.
</ParamField>
<ParamField path="tags" type="string[]">
  Groups the endpoints in the API docs.
</ParamField>

## Create the table

A definition doesn't touch your database. Click **Create / migrate table** (or `POST …/resources/{name}/migrate`) to create the table or add new columns. The response lists the SQL statements that ran. [Migrations →](/data/migrations)

## Exposing an existing table

To put an API on a table that already exists:

1. set `table` to its name and `primary_key` to its key column;
2. add fields matching the columns you want to expose (you can leave some out);
3. **don't** run migrate if the schema is managed elsewhere, or run it only to add Pawabase-specific columns.

Columns you don't declare are invisible to the API: they're neither read nor writable.

## Editing safely

- Adding fields is safe; migrate to add the columns.
- Removing a field hides it from the API; the column stays.
- Changing a field's type changes validation and serialisation, not the column. Migrate the column yourself if needed.
- Renaming a resource isn't possible; create a new one with `table` pointing at the old table.
