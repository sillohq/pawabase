## Sorting

```text
?sort=<field>[,<field>…]
```

Prefix a field with `-` for descending. Multiple fields sort in order:

```bash
GET /rest/v1/students?sort=last_name,first_name
GET /rest/v1/announcements?sort=-pinned,-created_at
```

Only declared fields (plus `id`, `created_at`, `updated_at`) can be used. Without `sort`, order is the database's and not guaranteed; always sort when paginating.

## Pagination

```text
?page=<n>&per_page=<m>
```

| Parameter | Default | Limits |
| --- | --- | --- |
| `page` | 1 | ≥ 1 |
| `per_page` | 20 | 1–200 |

Every list response has the same envelope:

```json
{
  "data": [ { "id": 1, "...": "..." } ],
  "page": 2,
  "per_page": 50,
  "total": 431
}
```

`total` counts every row matching your filters **and** the policy. When a policy has a residual condition that can't run in SQL (for example array membership), `total` may be `null`, because counting it would mean reading the whole table. Page until a short page instead.

### Reading everything

```js
async function all(path, params = {}) {
  const rows = [];
  for (let page = 1; ; page++) {
    const r = await get(path, { ...params, per_page: 200, page });
    rows.push(...r.data);
    if (r.data.length < 200 || (r.total != null && rows.length >= r.total)) return rows;
  }
}
```

## Selecting fields

```text
?select=<field>[,<field>…]
```

Return only some fields. The query reads fewer columns, and responses shrink:

```bash
GET /rest/v1/students?select=id,first_name,last_name,class_id&per_page=200
```

`select` runs before the transformer; if the transformer adds computed fields, they're added to the selected set.

## Putting it together

```bash
GET /rest/v1/invoices?filter[status]=in.issued,overdue&sort=-due_on&select=id,invoice_no,balance,due_on&expand=student&per_page=50&page=1
```
