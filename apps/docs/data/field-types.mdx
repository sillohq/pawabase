Fields are compiled into Pydantic models, so a type decides **validation**, **serialisation**, the **OpenAPI schema** and, on migrate, the **column type**.

| Type | JSON | Validates | Typical column |
| --- | --- | --- | --- |
| `string` | string | length, pattern, allowed values | `VARCHAR` |
| `text` | string | length | `TEXT` |
| `integer` | number | range, allowed values | `INTEGER`/`BIGINT` |
| `number` | number | range | `DOUBLE`/`NUMERIC` |
| `boolean` | `true`/`false` | | `BOOLEAN` |
| `datetime` | ISO-8601 string | a valid timestamp | `TIMESTAMP` |
| `date` | `YYYY-MM-DD` | a valid date | `DATE` |
| `uuid` | string | UUID format | `UUID`/`VARCHAR(36)` |
| `email` | string | `^[^@\s]+@[^@\s]+\.[^@\s]+$` | `VARCHAR` |
| `url` | string | `^https?://…` | `VARCHAR` |
| `json` | any | any JSON value | `JSON`/`TEXT` |
| `array` | array | each item by `items` | `JSON` |
| `object` | object | nested `fields` | `JSON` |
| `ref` | object | a named [schema](/data/schemas) | `JSON` |

## Structured types

<Tabs>
  <Tab title="array">
    ```json
    { "name": "tags", "type": "array", "items": { "type": "string" } }
    { "name": "marks", "type": "array", "items": { "type": "ref", "schema": "AttendanceMark" } }
    ```
    Without `items`, elements are `json`. Arrays are stored as JSON.
  </Tab>
  <Tab title="object">
    ```json
    { "name": "settings", "type": "object", "fields": [
        { "name": "theme", "type": "string", "enum": ["light", "dark"] },
        { "name": "digest", "type": "boolean", "default": true }
    ] }
    ```
    Nested fields validate like top-level ones, to any depth.
  </Tab>
  <Tab title="ref">
    ```json
    { "name": "address", "type": "ref", "schema": "Address", "nullable": true }
    ```
    Reuses a [schema](/data/schemas). The schema appears once in OpenAPI and is referenced everywhere it's used.
  </Tab>
  <Tab title="json">
    Accepts any JSON. Use it for data whose shape you don't control (a provider's payload) or computed structures (a report card's breakdown).
  </Tab>
</Tabs>

## Common options

| Option | Applies to | Effect |
| --- | --- | --- |
| `required` | all | Must be present on **create** (unless it has a `default`) |
| `nullable` | all | `null` accepted. Optional fields are nullable by default |
| `default` | all | Used when omitted on create |
| `description` | all | Shown in docs and Studio |
| `example` | all | Shown in docs |
| `read_only` | all | Refused in create/update bodies, returned in reads |
| `write_only` | all | Accepted in writes, never returned (e.g. a PIN) |
| `enum` | string, integer, number | Allowed values |

<Note>
Update bodies are **partial**: every field is optional on `PATCH`, and `required` only applies to create. Reads never fail validation, so rows written by other systems still come back.
</Note>

## Choosing types well

- Money: `number` with `minimum: 0`, plus a `currency` string with allowed values. Store minor units as `integer` if you need exact arithmetic.
- Status fields: `string` with `enum`, never free text.
- Foreign keys: `integer` (or `uuid`) named `<thing>_id`, plus a [relation](/data/relations).
- User ids: `string` (Akountz ids are strings in tokens and policies).
- Denormalised lists for policies (e.g. `guardian_user_ids`): `array` of `string`.
