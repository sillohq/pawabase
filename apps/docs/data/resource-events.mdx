Every resource write — create, update, or delete — emits an event. These events are how the rest of your backend (flows, functions, webhooks, realtime subscribers) learns that data changed. They're guaranteed to fire if and only if the write succeeds, and their payload is the full record as it exists after the write.

## The three resource events

| Event name | Triggered by | Payload |
| --- | --- | --- |
| `<resource>.created` | A record is inserted | The created record, including `id` and all declared fields |
| `<resource>.updated` | A record is modified | The updated record, including `id` and all declared fields |
| `<resource>.deleted` | A record is deleted | The record as it was **before** deletion, including `id` and all declared fields |

The `<resource>` part of the event name is the **resource name** you defined — the same name used in the URL (`/rest/v1/<resource>`). For example, a resource named `orders` emits `orders.created`, `orders.updated`, and `orders.deleted`.

<Note>
Resource events are emitted **inside the same database transaction** as the write. If the write is rolled back, the event is not emitted. If the write succeeds, the event is guaranteed to be on the event bus.
</Note>

## The event payload

The payload is the full record, shaped exactly as it exists in the database after the write. This means:

- **All declared fields** are present — not just the ones provided in the request.
- **Computed fields** (defaults, generated columns) are included.
- **Relational fields** are not embedded — only the foreign key values are present. If you need related data, join it in the flow or function that handles the event.
- **Field types** are serialized as JSON values (strings, numbers, booleans, arrays, objects).

Example: a `students.updated` event:

```json
{
  "id": "stu_001",
  "name": "Ada Lovelace",
  "email": "ada@example.com",
  "grade": 12,
  "enrollment_date": "2024-09-01",
  "created_at": "2024-09-01T08:00:00+00:00",
  "updated_at": "2026-09-28T10:00:00+00:00"
}
```

## The full event envelope

The complete event you receive as a subscriber contains more than just the payload:

```json
{
  "event": "students.updated",
  "payload": { ... },
  "id": "evt_abc123",
  "published_at": "2026-09-28T10:00:00+00:00",
  "project": "school",
  "env": "production",
  "actor": "usr_001",
  "correlation_id": "req_xyz789"
}
```

| Field | Description |
| --- | --- |
| `event` | The event name: `<resource>.<action>` |
| `payload` | The full record (see above) |
| `id` | Unique event identifier |
| `published_at` | When the event was emitted, as an ISO 8601 timestamp |
| `project` / `env` | Which project and environment emitted this event |
| `actor` | The user ID or service account that triggered the write. `system` if no user context. |
| `correlation_id` | Links the event to the original request |

## Subscribing to resource events

You can react to resource events in several ways:

### In a flow

Add an **Event trigger** to a flow:
1. Create or open a flow in Studio.
2. Click the trigger block → **Choose trigger** → **Event**.
3. Enter the event name: `orders.created` (or use `orders.*` to catch all events for the `orders` resource).
4. The flow's `$input` will have the full event envelope:
   ```text
   $input.event          → "orders.created"
   $input.payload        → the record
   $input.id             → the event ID
   $input.actor          → who made the change
   ```

### In a webhook

Create a subscription that sends the event to an external URL:
1. Go to **Automate → Webhooks**.
2. Create a new webhook targeting the event `orders.created`.
3. Set the URL to your external endpoint.
4. The webhook receives the full event envelope as the JSON body.

### In realtime

Subscribe to resource events over WebSocket:
```javascript
const ws = new WebSocket('wss://api.your-app.pawabase.io/realtime');
ws.onopen = () => {
  ws.send(JSON.stringify({
    type: 'subscribe',
    channel: 'resource:orders'
  }));
};
ws.onmessage = (msg) => {
  const event = JSON.parse(msg.data);
  console.log('Order changed:', event);
};
```

### In a function or code

Use the EventBus client:
```python
from pawabase_kit.events import EventBus

bus = EventBus.from_env()
bus.subscribe("orders.created", handle_order_created)
```

## Event delivery guarantees

| Guarantee | What it means |
| --- | --- |
| **At-least-once** | An event is delivered at least once. If the consumer fails, the event is retried. |
| **Ordered within a resource** | For a single resource, events for the same record are delivered in the order they occurred. |
| **Transactional** | The event is only emitted if the database write commits successfully. |
| **No ordering across resources** | Events from different resources or different records may arrive in any order. |

<Note>
If you need exactly-once processing (e.g., financial transactions), design your consumer to be idempotent. Use the event `id` or `correlation_id` to deduplicate.
</Note>

## Configuring event delivery

Event subscriptions control where resource events go. You can subscribe to:
- A specific event: `orders.created`
- All events for a resource: `orders.*`
- All events in a domain: `*.created`
- All events: `*`

Each subscription has its own retry policy and failure handling. See [Event subscriptions](/events/subscriptions) for details on configuring delivery, retries, and dead-letter handling.

## Resource events in the audit log

Every emitted resource event is recorded in the environment's audit log. If a flow or function fails to process an event, you can find the failed delivery in the audit log and retry it manually from Studio.

## Disabling resource events

You can disable event emission for a specific resource in Studio:
1. Open the resource.
2. Go to the **Events** tab.
3. Toggle **Emit events** to off.

This is rarely needed — it's mainly useful for bulk import flows that would flood the event bus. When events are disabled, the resource still works through the API; it just doesn't notify subscribers.
