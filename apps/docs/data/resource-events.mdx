A resource with `events: true` (the default) emits an event after every successful write, whatever made it: a client, Studio, a flow, a function.

| Change | Event name |
| --- | --- |
| Create | `<resource>.created` |
| Update | `<resource>.updated` |
| Delete | `<resource>.deleted` |

## The payload

```json
{
  "name": "attendance_records.created",
  "project": "school",
  "env": "development",
  "payload": {
    "resource": "attendance_records",
    "change": "created",
    "record": { "id": 91, "student_id": 12, "class_id": 7, "date": "2026-09-28", "status": "absent", "recorded_by": "5" }
  },
  "source": "api",
  "actor": "5",
  "id": "8cea56bf64ad4c25818eadf9e7b120eb",
  "occurred_at": "2026-09-28T08:14:03.112Z",
  "request_id": "…"
}
```

For updates, `record` is the row **after** the change.

## Realtime change feeds

With `realtime: true`, each change is also published on `resource:<name>` with the event name `created`, `updated` or `deleted` and the same `{resource, change, record}` payload. Clients subscribe over the [realtime socket](/realtime/resource-changes).

## Avoiding loops

A flow triggered by `invoices.updated` that updates an invoice will trigger itself. Guard with a condition (`control.if` on a field you set), trigger on a narrower operation, or emit a custom event instead of writing back.

## Turning events off

Set `events: false` for high-volume, low-value tables (telemetry, logs) to save queue work. Realtime publication is controlled separately.
