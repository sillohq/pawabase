## Overview

Relations define how resources connect to each other. They enable ?expand=<relation> on list and get operations, and they establish the foreign-key semantics between resources.

Every relation is declared in the resource definition's relations array with a name, a type (belongs_to or has_many), a target resource name, and a field name.

## Relation types

| Type | Meaning | Foreign key lives on | Expand direction |
| --- | --- | --- | --- |
| `belongs_to` | This record references one of another resource | On this resource's table | Returns the related record |
| `has_many` | Another resource references this one | On the other resource's table | Returns a collection of related records |

## belongs_to in detail

A belongs_to relation means this resource's table has a foreign key column pointing to another resource's primary key. For example, an invoices resource has a belongs_to relation to students because invoices have a student_id column that references students.

When you expand a belongs_to relation on a list or get operation, the platform fetches the related record and embeds it in the response. The related record is returned as a complete resource object with all its declared fields.

The foreign key column is automatically managed by the platform. When you create a record with a belongs_to field, the platform validates that the referenced record exists and that the caller has permission to access it.

## has_many in detail

A has_many relation means another resource's table has a foreign key column pointing to this resource's primary key. For example, a students resource has a has_many relation to invoices because invoices have a student_id column that references students.

When you expand a has_many relation on a list or get operation, the platform fetches all related records and embeds them as a collection. The platform handles pagination of the related collection automatically.

Has_many relations are read-only through the expand parameter. To create or modify related records, you need to use the related resource's own operations.

## Expand depth and limits

The expand parameter supports one level of depth. You cannot expand a relation of a relation — for example, expanding invoices->student->invoices is not supported.

This limit prevents deep nesting that could lead to performance issues and excessively large responses. If you need to fetch deeply related data, use a custom route backed by a flow.

Unknown relation names in the expand parameter return 400 Bad Request with a message identifying the unknown relation name.

## Relations and filtering

Relations interact with filtering in powerful ways. You can filter a resource's list by fields on related resources using dot notation in filter parameters.

For example, filter[student.class_name]=Math filters invoices to only those belonging to students in the Math class.

The platform translates these filter parameters into SQL JOINs, allowing efficient filtering across resource boundaries.

## Relations and pagination

When you expand a has_many relation on a paginated list, the pagination applies to the parent resource's records. Each parent record includes its related records as a nested collection.

The total count reflects the number of parent records matching the filters, not the total number of related records across all parents.

## Circular relations

Circular relations between resources are supported but should be used with caution. A circular relation creates a dependency loop that can cause issues with compilation and response size.

If two resources have mutual belongs_to relations, the platform can handle them, but expanding both directions in a single request will produce large responses.

## Performance considerations

Relations require additional database queries. The platform optimizes this by fetching related records in a single query per relation, avoiding the N+1 problem.

For list operations with many parent records and large related collections, consider using select to limit the fields returned, or use a custom route for more complex queries.

## Troubleshooting

- Relation not working: verify that the field name matches the actual foreign key column name.

- Expand returns 400: the relation name does not match any declared relation on the resource.

- Related records not showing: check that the foreign key values match existing records in the related resource.
