Firebase and Pawabase both offer backend-as-a-service, but they take fundamentally different approaches. Firebase uses Firestore (a NoSQL document database) with Cloud Functions triggered by database events. Pawabase uses a relational database (SQLite or PostgreSQL) with flows and Python functions triggered by 8 different event types.

This guide walks through migrating a Firebase project to Pawabase, covering each subsystem: authentication, database, functions, storage, and realtime.

## Key architectural differences

Before starting the migration, understand the fundamental differences that affect how you port your logic:

| Aspect | Firebase | Pawabase |
| --- | --- | --- |
| **Database model** | NoSQL document store (Firestore) | Relational (SQLite/Postgres) with ORM |
| **Query language** | Firestore query API | Full SQL via `db.query`, relational via `resource.get` |
| **Functions** | Cloud Functions (Node.js/Python), triggered by events | Flows (visual) and Python functions, triggered by 8 types |
| **Deployment** | `firebase deploy` required | Save definitions — no deploy, compiles instantly |
| **Auth** | Firebase Auth SDK | Akountz with email/password, OAuth, MFA |
| **Storage** | Firebase Storage | S3-compatible object storage |
| **Realtime** | Firestore listeners | Angula WebSocket server |
| **Security** | Firebase Rules | Pawabase policies (unified engine) |

## Authentication migration

Firebase Auth users need to be migrated to Pawabase's Akountz system. Each service has a different user model.

### Step 1: Export Firebase users

Use the Firebase Admin SDK to list all users:

```javascript
const admin = require("firebase-admin");
admin.initializeApp();

const listUsersResult = await admin.auth().listUsers(1000);
listUsersResult.users.forEach((userRecord) => {
  console.log(JSON.stringify({
    uid: userRecord.uid,
    email: userRecord.email,
    displayName: userRecord.displayName,
    photoURL: userRecord.photoURL,
    emailVerified: userRecord.emailVerified,
    metadata: userRecord.metadata,
  }));
});
```

### Step 2: Create Pawabase accounts

Each Firebase user maps to a Pawabase user through Akountz. Use the management API or the migration script to create accounts. Email and password are preserved; if the user signed in via a social provider, create an OAuth link in Pawabase.

Pawabase supports the same providers as Firebase for OAuth (Google, GitHub, and generic OIDC). Map each Firebase provider ID to the corresponding Pawabase OAuth configuration.

### Step 3: Verify token compatibility

Pawabase issues its own JWT tokens. Your client application needs to switch from Firebase's `firebase.auth().currentUser` to Pawabase's auth SDK. The token format, claims, and refresh mechanism differ.

| Firebase | Pawabase |
| --- | --- |
| `firebase.auth().currentUser.getIdToken()` | `PawabaseAuth.getToken()` |
| `firebase.auth().signInWithEmailAndPassword` | `PawabaseAuth.signIn({ email, password })` |
| Custom claims via `setCustomUserClaims` | RBAC roles and permissions via `defineRole` |
| Token expiration configurable | Token pair with rotation and theft detection |

### Migrated auth features

| Firebase Auth | Pawabase Auth | Status |
| --- | --- | --- |
| Email/password | Email/password | ✅ Direct mapping |
| Google OAuth | Google OAuth | ✅ Supported |
| GitHub OAuth | GitHub OAuth | ✅ Supported |
| Apple OAuth | Generic OAuth/OIDC | ✅ Supported |
| Phone auth | SMS | ❌ Coming soon |
| MFA (TOTP) | TOTP MFA | ✅ Supported |
| Email verification | Email verification | ✅ Supported |
| Password recovery | Password recovery | ✅ Supported |
| Anonymous auth | Not yet supported | ❌ Planned |

## Database migration

Firestore documents map to Pawabase resources. Each Firestore collection becomes a resource definition, and each document becomes a record.

### Step 1: Define resources in Studio

For each Firestore collection, create a corresponding resource in Pawabase Studio:

1. Go to **Studio → Data → Resources**
2. Create a new resource with the same name as the Firestore collection
3. Define fields matching the Firestore document schema
4. Configure validation rules based on your Firestore security rules

Firestore field types map to Pawabase resource field types:

| Firestore type | Pawabase type | Notes |
| --- | --- | --- |
| `string` | `string` | Direct mapping |
| `number` | `number` | Pawabase uses decimal |
| `boolean` | `boolean` | Direct mapping |
| `timestamp` | `datetime` | Stored as ISO 8601 |
| `array` | `list` | Array of typed elements |
| `map` | `object` | Nested resource or JSON field |
| `GeoPoint` | Not supported | Use a `{ lat, lng }` object field |
| `Reference` | Relation | Maps to a resource relation |

### Step 2: Migrate documents

Use the migration utility to copy documents from Firestore to Pawabase's database:

```python
import firebase_admin
from firebase_admin import firestore, credentials
from pawabase_core.platform import Platform
from app.config import ApiSettings

# Initialize Firebase
cred = credentials.Certificate("firebase-key.json")
firebase_admin.initialize_app(cred)
fb_db = firestore.client()

# Initialize Pawabase
platform = Platform(ApiSettings())

# Migrate each collection
for collection_name in ["users", "orders", "products"]:
    fb_collection = fb_db.collection(collection_name)
    for doc in fb_collection.stream():
        data = doc.to_dict()
        data["id"] = doc.id
        # Create the Pawabase record via the resource API
        await platform.dispatch(
            CreateResourceJob,
            project="my-project",
            env="development",
            resource=collection_name,
            data=data,
        )
```

### Step 3: Convert queries

Firestore queries need to be rewritten for Pawabase's SQL-based query system:

```javascript
// Firestore
db.collection("orders").where("total", ">", 100).get()
```

```python
# Pawabase — using resource.get
result = await ctx.runtime.resource_list(
    "orders",
    filters=[{"field": "total", "operator": ">", "value": 100}],
)
```

Or use the `db.query` block in a flow for complex SQL:

```json
{
  "id": "query-orders",
  "data": {
    "block": "db.query",
    "config": {
      "sql": "SELECT * FROM orders WHERE total_minor > :min ORDER BY created_at DESC",
      "params": {"min": 100}
    }
  }
}
```

### Relational data

One advantage Pawabase has over Firestore is relational queries. If your Firestore data has references between documents, define them as resource relations in Pawabase:

```json
{
  "resource": "orders",
  "fields": [
    {"name": "customer_id", "type": "relation", "target": "users"},
    {"name": "items", "type": "list", "item_type": "object"}
  ]
}
```

This lets you use `resource.get` to load related data with joins — something not possible in Firestore without denormalizing.

## Functions migration

Cloud Functions triggered by Firestore events map to Pawabase flows and Python functions.

### Trigger mapping

| Firebase trigger | Pawabase equivalent | Migration approach |
| --- | --- | --- |
| `onCreate` / `onWrite` | `trigger.resource` in a flow | Create a flow with `trigger.resource` node |
| `onDelete` | `trigger.resource` with `operations: ["deleted"]` | Filter to deletion operations |
| `onCall` | `function.call` or inline function | Convert to a Pawabase function |
| `onSchedule` | `trigger.schedule` in a flow | Create a flow with cron/interval trigger |
| `onRequest` | HTTP route via `route` definition | Create a custom route or extension route |
| `functions.https.onRequest` | Extension route or `queue.function` | Convert to a flow block or function |

### Example: converting an `onCreate` function

**Firebase (TypeScript):**
```typescript
exports.createUser = functions.firestore
  .document("users/{userId}")
  .onCreate((snap, context) => {
    const userData = snap.data();
    return admin.messaging().send({
      token: userData.fcmToken,
      notification: { title: "Welcome!", body: "Your account was created." },
    });
  });
```

**Pawabase flow equivalent:**
```json
{
  "id": "welcome-new-user",
  "nodes": [
    {
      "id": "start",
      "data": {
        "block": "trigger.resource",
        "config": { "resource": "users", "operations": ["created"] }
      }
    },
    {
      "id": "send-notification",
      "data": {
        "block": "control.if",
        "config": { "condition": "{{ steps.start.output.fcm_token != null }}" },
        "true": "send-msg",
        "false": "end"
      }
    }
  ]
}
```

### Example: converting an `onCall` function

**Firebase:**
```typescript
exports.calculateGrade = functions.https.onCall(async (data, context) => {
  const score = data.score;
  return { grade: score >= 90 ? "A" : score >= 80 ? "B" : "C" };
});
```

**Pawabase Python function:**
```python
from pawabase import function

@function("calculate-grade")
def calculate_grade(ctx, score: int) -> dict:
    if score >= 90:
        return {"grade": "A"}
    elif score >= 80:
        return {"grade": "B"}
    return {"grade": "C"}
```

## Storage migration

Firebase Storage maps to Pawabase's object storage. Both support file uploads and downloads, but the APIs differ.

### Step 1: Set up storage in Pawabase

Configure an S3-compatible storage backend in Studio's **Infrastructure** settings. Pawabase uses the storage backend for all object storage operations.

### Step 2: Migrate files

Use the Firebase Admin SDK to download files and upload them to Pawabase's storage:

```python
from firebase_admin import storage as fb_storage
from app.platform import Platform

fb_bucket = fb_storage.bucket()
platform = Platform(ApiSettings())

for blob in fb_bucket.list_blobs():
    data = blob.download_as_bytes()
    await platform.storage.upload(
        bucket="my-bucket",
        key=blob.name,
        data=data,
        content_type=blob.content_type,
    )
```

### Step 3: Update client code

Firebase Storage SDK calls need to be replaced with Pawabase's storage API:

| Firebase Storage | Pawabase Storage |
| --- | --- |
| `firebase.storage().ref(path).getDownloadURL()` | `GET /storage/v1/signed/<bucket>/<key>` |
| `ref.put(file)` | `PUT /storage/v1/<bucket>/<key>` |
| `ref.delete()` | `DELETE /storage/v1/<bucket>/<key>` |
| `ref.list()` | `GET /storage/v1/<bucket>?prefix=` |

## Realtime migration

Firestore's realtime listeners map to Pawabase's Angula realtime channels.

### Step 1: Define channels

In Pawabase, realtime channels are defined with subscribe and publish policies. Each channel is a named room with configurable access rules.

### Step 2: Map listeners to subscriptions

```javascript
// Firebase
db.collection("orders").where("status", "==", "active").onSnapshot((snapshot) => { ... });
```

```javascript
// Pawabase client
pawabase.realtime.subscribe("orders-active", {
  channel: "orders-active",
  filter: { field: "status", operator: "==", value: "active" }
});
```

### Step 3: Migrate security rules

Firebase's Firestore rules are replaced by Pawabase's channel policies:

```javascript
// Firebase rules
match /orders/{orderId} {
  allow read: if request.auth != null && request.auth.uid == resource.data.owner;
  allow write: if request.auth != null && request.auth.uid == resource.data.owner;
}
```

```json
// Pawabase channel policies
{
  "channel": "orders-active",
  "subscribe": "{{ auth.user_id == payload.owner_id }}",
  "publish": "{{ auth.role == 'admin' || auth.user_id == payload.owner_id }}"
}
```
