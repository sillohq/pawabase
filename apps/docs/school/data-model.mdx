## Start from the questions

Before creating anything, list what the school needs to answer: *who is in JSS 1A? what did Amara score in the maths exam? what does the Nwosu family owe? who has "Things Fall Apart"?* Each noun that needs its own list becomes a resource; each relationship becomes a foreign-key field plus a [relation](/data/relations).

## Reusable schemas first

Some shapes appear in several places, so define them once as [schemas](/data/schemas):

<CodeGroup>
```json Address
{
  "name": "Address",
  "fields": [
    { "name": "line1", "type": "string", "required": true, "max_length": 120 },
    { "name": "line2", "type": "string", "max_length": 120 },
    { "name": "city", "type": "string", "required": true, "max_length": 80 },
    { "name": "state", "type": "string", "max_length": 80 },
    { "name": "postal_code", "type": "string", "max_length": 12 },
    { "name": "country", "type": "string", "default": "NG", "min_length": 2, "max_length": 2 }
  ]
}
```

```json AttendanceMark
{
  "name": "AttendanceMark",
  "fields": [
    { "name": "student_id", "type": "integer", "required": true },
    { "name": "status", "type": "string", "required": true, "enum": ["present", "absent", "late", "excused"] },
    { "name": "note", "type": "string", "max_length": 200 }
  ]
}
```

```json BulkAttendance
{
  "name": "BulkAttendance",
  "fields": [
    { "name": "class_id", "type": "integer", "required": true },
    { "name": "date", "type": "date", "required": true },
    { "name": "marks", "type": "array", "required": true, "items": { "type": "ref", "schema": "AttendanceMark" } }
  ]
}
```
</CodeGroup>

`teachers.address` is a field of type `ref` pointing at `Address`, so its shape is validated and documented without a separate table. `BulkAttendance` is the request body of a custom route, not a table.

## The resources

<AccordionGroup>
  <Accordion title="Academics: academic_years, terms, classes, subjects, class_subjects, timetable_slots">
    - `academic_years.name` has `pattern: ^\d{4}/\d{4}$`: "2026/2027", never "26-27".
    - `terms.name` uses **allowed values** (`First Term`, `Second Term`, `Third Term`) instead of free text, so reports can group reliably.
    - `classes.grade_level` is an integer with `minimum: 1, maximum: 12`; `capacity` defaults to 40.
    - `subjects.code` enforces `^[A-Z]{3}\d{3}$` (`MTH101`).
    - `class_subjects` is the **teaching assignment**: which teacher teaches which subject to which class in which term. Timetables, assessments and gradebooks hang off it.
    - `timetable_slots.starts_at` uses `^([01]\d|2[0-3]):[0-5]\d$` so "8:00" is rejected in favour of "08:00".
  </Accordion>
  <Accordion title="People: teachers, guardians, students, student_guardians">
    - `students.admission_no` follows `^BFA-\d{4}-\d{4}$`; a flow allocates it.
    - `students.guardian_user_ids` is an **array of strings**: the user ids of the guardians with portal accounts. It's denormalised on purpose, so a policy can decide family access with one `contains` check (see [access control](/school/access-control)).
    - `students.emergency_contact` is a `ref` to the `EmergencyContact` schema, `nullable`.
    - `student_guardians` is the many-to-many join with `is_primary` and `can_pickup`.
    - `guardians.user_id` links a guardian to their login. It is **not** an owner field: guardians are created by the office, and an owner field would stamp the admin's id on every row.
  </Accordion>
  <Accordion title="Records: attendance_records, assessments, grades, report_cards, discipline_incidents">
    - `attendance_records.recorded_by`, `grades.graded_by` and `discipline_incidents.reported_by` are **owner fields** and `read_only`: the server records who did it; clients can't forge it.
    - `assessments.weight` (0–100) and `max_score` drive the report-card maths.
    - `report_cards.subjects` is `json`: the computed breakdown per subject.
    - `attendance_records` has **Broadcast changes** on for live registers.
  </Accordion>
  <Accordion title="Money: fee_items, invoices, payments">
    - `fee_items.grade_level` is **nullable**: `null` means every level (tuition), a number targets one (lab fee for grade 10).
    - `invoices.status` is an enum: `draft, issued, partially_paid, paid, overdue, void`.
    - `payments` has **update and delete disabled**, so money received is immutable through the API. Corrections are new records.
  </Accordion>
  <Accordion title="Community: announcements, calendar_events, library_books, library_loans">
    - `announcements.audience` values are role names (`all`, `teacher`, `guardian`, `student`) so a policy can match them against `auth.roles`.
    - `library_loans.borrower_user_id` is a user id, so the `owner:borrower_user_id` policy lets borrowers see their own loans.
    - `calendar_events` and `library_books` have a **cache TTL**: hot, public, rarely changing.
  </Accordion>
</AccordionGroup>

## Relations

Relations don't create foreign keys in your database; they tell the API how to answer `?expand=`:

```json
"relations": [
  { "name": "class",        "type": "belongs_to", "resource": "classes",            "field": "class_id" },
  { "name": "guardians",    "type": "has_many",   "resource": "student_guardians",  "field": "student_id" },
  { "name": "report_cards", "type": "has_many",   "resource": "report_cards",       "field": "student_id" }
]
```

```bash
GET /rest/v1/class_subjects?filter[class_id]=7&expand=subject,teacher,slots
```

returns each assignment with its subject, its teacher and all its timetable slots: the whole weekly timetable in one request.

<Tip>
Create resources first, **then** add relations. A relation to a resource that doesn't exist yet is refused.
</Tip>

## Migrate

Each resource's **Create / migrate table** (or `POST …/resources/<name>/migrate`) creates the table, or adds new columns when fields are added. It never drops or rewrites columns. See [migrations](/data/migrations).
