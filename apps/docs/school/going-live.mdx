## 1. Promote definitions

**Project → Promote…** from `development` to `staging`. Select every kind: schemas, transformers, policies, resources, routes, flows, buckets, mail templates, subscriptions, webhooks, inbound hooks, schedules. Definitions copy; **data, keys and secrets don't**.

Then, in staging, run **Create / migrate table** for each resource (or call the migrate endpoint for all of them from CI).

## 2. Real infrastructure

In **staging → Settings → Infrastructure**:

```json
{
  "database_url": "postgres://school:secret://DB_PASSWORD@db.internal:5432/school_staging",
  "storage": { "driver": "s3", "bucket": "brightfield-staging", "region": "eu-west-1",
               "access_key": "secret://S3_ACCESS_KEY", "secret_key": "secret://S3_SECRET_KEY" },
  "mail": { "host": "smtp.postmarkapp.com", "port": 587,
            "username": "secret://SMTP_USER", "password": "secret://SMTP_PASSWORD",
            "from": "Brightfield Academy <office@brightfield.example>" }
}
```

Create the secrets first under **Secrets**. Until `mail.host` is set, every email is recorded as *suppressed* in the mail log, which makes staging safe to test with real addresses.

## 3. Auth settings

In **Users & auth → Settings** for production:

```json
{
  "signup_enabled": false,
  "require_email_verification": true,
  "password_policy": "strict",
  "password_min_length": 10,
  "site_url": "https://portal.brightfield.example",
  "redirect_urls": ["https://portal.brightfield.example/auth"],
  "default_roles": []
}
```

Schools don't want open sign-up: the office creates accounts with roles (`POST /admin/v1/…/users` with `"roles": ["guardian"]`).

## 4. Webhooks and hooks

The two outbound webhooks (`accounting_sync`, `sms_gateway`) were created **disabled** with placeholder URLs. Set real URLs and enable them; each delivery is signed and retried (up to `max_attempts`). Give the payment provider the inbound hook URL from **Inbound hooks → payment-gateway → Show URL** and set its secret.

## 5. Keys and CORS

Create a production publishable key for the portal and set the environment's `cors_origins` to the portal origin, so the key is useless on other sites. Create a **scoped** secret key for the accounting integration: `resource:read` only.

## 6. Schedules

Schedule flows (`mark_overdue_invoices`, `library_overdue_sweep`, `fee_reminders`) start as soon as they exist in an environment and are enabled. Make sure exactly **one** scheduler process runs in your deployment.
