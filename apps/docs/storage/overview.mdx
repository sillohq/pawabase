**Storage** in Pawabase is object storage — buckets that hold files, governed by per-bucket read and write policies, backed by an S3-compatible store. Every project-environment has its own set of buckets, and every bucket is isolated from every other bucket in the project.

Storage is designed for the same pattern you see throughout the platform: **everything is a resource with a policy**. A bucket is a resource, `storage.put` writes to it, `storage.read` reads from it, and `read_policy` / `write_policy` decide who can do what. The policies are JSON conditions evaluated by the same engine that guards resources, routes, and realtime channels.

## The storage model

A bucket has a name, a driver configuration (which S3-compatible store to use), and two policies — `read_policy` and `write_policy`. Every operation on a bucket is gated by the relevant policy.

```json
{
  "name": "receipts",
  "driver": "s3",
  "config": {
    "endpoint": "https://s3.amazonaws.com",
    "region": "us-east-1",
    "bucket": "my-project-receipts"
  },
  "read_policy": {
    "all": [
      {"authenticated": true},
      {"eq": ["$object.segments.0", "user"]}
    ]
  },
  "write_policy": {
    "all": [
      {"authenticated": true},
      {"in": ["$auth.roles", ["admin", "finance_staff"]]}
    ]
  }
}
```

The `$object` variable in policies gives you access to the object's key and segments — this means you can write policies that depend on the file path itself (e.g., "users can only read files under `user/<user_id>/`").

## How storage integrates with flows

Four blocks let flows interact with storage: `storage.put`, `storage.read`, `storage.signed_url`, and `storage.delete`. All four run with the platform's service rights, so a flow can always write to any bucket regardless of who triggered the flow.

```json
{
  "id": "archive",
  "data": {
    "block": "storage.put",
    "config": {
      "bucket": "exports",
      "key": "orders/{{ steps.day.output }}.json",
      "content": "{{ steps.rows.output }}",
      "content_type": "application/json"
    }
  }
}
```

`storage.put` writes with a service credential (`{"is_service": True, "role": "service", "scopes": []}`), bypassing the bucket's own `write_policy`. This is the same pattern as resource blocks — the flow's own service rights mean writes always succeed.

## Drivers

Pawabase supports any S3-compatible storage backend. The driver determines how the store is accessed — the endpoint URL, region, and authentication method. See [Drivers](/storage/drivers) for the full list of supported drivers and configuration options.

<Note>
The default driver is `s3`, which works with any S3-compatible store (AWS S3, MinIO, Ceph, etc.). The driver configuration lives in the bucket's `config` object and is set when the bucket is created.
</Note>

## Content safety

When files are uploaded to a bucket, content safety checks can be configured to scan for malicious content, validate file types, and enforce size limits. See [Content safety](/storage/content-safety) for details.
