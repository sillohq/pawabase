Objects are downloaded from Pawabase storage using `GET /storage/v1/<bucket>/<key>`. The gateway evaluates the bucket's read policy before returning the file.

Two download patterns:

1. **Direct download** — call the storage API directly with a valid API key (and user token if the policy requires authentication).
2. **Signed URL** — your server generates a time-limited pre-authorized URL, and the client fetches the file directly without an API key.

## Direct download

```bash
# With a secret key (bypasses policy)
curl "$GW/storage/v1/exports/reports/q3-2026.csv" \
  -H "apikey: $SK" \
  -o q3-2026.csv

# With a publishable key + user token (policy applied)
curl "$GW/storage/v1/documents/contract-001.pdf" \
  -H "apikey: $PK" \
  -H "Authorization: Bearer $TOKEN" \
  -o contract.pdf
```

The response is the raw file with the appropriate `Content-Type` header. A `403 Forbidden` means the read policy refused the caller. A `404 Not Found` means the object doesn't exist (the gateway doesn't distinguish between "doesn't exist" and "policy refused" for read operations — both return 404, to avoid leaking whether objects exist).

## Signed URL downloads

For browser or mobile clients, generate a signed URL from a flow using `storage.signed_url`. The client can then fetch the file directly without an API key:

```json
{
  "id": "get_download_url",
  "data": {
    "block": "storage.signed_url",
    "config": {
      "bucket": "invoices",
      "key": "{{ input.body.invoice_key }}",
      "method": "GET",
      "expires_in": 3600
    }
  }
}
```

The block output is `{ "url": "<signed_url>", "expires_at": "<iso_timestamp>" }`.

Return the URL to the client, which can use it with a plain `fetch` or `<a href>` — no additional headers needed.

```javascript
const { url } = await fetch('/api/download-link', {
  method: 'POST',
  body: JSON.stringify({ invoice_id: '44' })
}).then(r => r.json());

// Open in browser
window.location.href = url;

// Or download programmatically
const file = await fetch(url);
```

The signed URL is scoped to one specific object and one specific HTTP method. It cannot be used to access a different key. After `expires_in` seconds, it returns `403`.

## Read from a flow

The `storage.read` block retrieves an object's contents directly in a flow:

```json
{
  "id": "load_template",
  "data": {
    "block": "storage.read",
    "config": {
      "bucket": "templates",
      "key": "email/welcome.html"
    }
  }
}
```

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `bucket` | string | Yes | The bucket name |
| `key` | string | Yes | The object key |

The block output is the raw object content as a string. For binary files, the content is base64-encoded. `storage.read` runs with service rights and bypasses the bucket's read policy.

## Public buckets

If a bucket's `read_policy` is `"public"`, objects can be fetched without any authentication:

```bash
curl "$GW/storage/v1/product-images/sku-001/main.jpg"
```

No `apikey` header required. This is appropriate for static assets like product images, public documents, or media.

## Content disposition

To prompt a browser download (rather than inline display), set the `Content-Disposition` header on the signed URL or include it on direct requests. The gateway passes through response headers from the driver, and S3-compatible drivers support `response-content-disposition` as a query parameter on signed URLs.

## Troubleshooting

<AccordionGroup>
  <Accordion title="404 on a file I just uploaded">
    Check the bucket name and key exactly — both are case-sensitive. Also confirm the bucket's read policy allows the calling credential. A policy refusal returns 404, not 403, to avoid exposing whether an object exists.
  </Accordion>
  <Accordion title="Signed URL returns 403 immediately">
    The URL may have expired, or the signing secret rotated since the URL was generated. Generate a fresh URL.
  </Accordion>
  <Accordion title="Binary file content is garbled">
    When using `storage.read` in a flow, binary content is returned as base64. Decode it before use, or use a signed URL to let the client fetch the binary directly from the driver.
  </Accordion>
</AccordionGroup>
