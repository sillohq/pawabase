**Drivers** in Pawabase storage determine how the platform connects to an S3-compatible object store. Pawabase supports any S3-compatible backend — AWS S3, MinIO, Ceph, DigitalOcean Spaces, and custom S3 implementations all work through the same driver abstraction.

## Driver configuration

Each bucket specifies a `driver` name and a `config` object. The `config` is passed directly to the driver at runtime:

```json
{
  "name": "receipts",
  "driver": "s3",
  "config": {
    "endpoint": "https://s3.amazonaws.com",
    "region": "us-east-1",
    "bucket": "my-project-receipts",
    "acl": "private"
  }
}
```

The `driver` field selects the driver implementation. The `config` fields are driver-specific but all drivers require `endpoint`, `region`, and `bucket`.

## Supported drivers

| Driver | Endpoint | Notes |
| --- | --- | --- |
| `s3` | Any S3-compatible | The default driver. Works with AWS S3, MinIO, Ceph, and any S3-compatible store. |
| `minio` | Your MinIO server | Optimized for MinIO deployments. Same S3 API as `s3`. |
| `gcs` | Google Cloud Storage | Google Cloud Storage with HMAC key authentication. |
| `custom` | Any URL | For stores that implement the S3 API but require custom connection settings. |

The `s3` driver is the default and the most widely supported. It uses the `boto3`-compatible S3 client under the hood and works with any store that implements the S3 API.

## Configuration options

All drivers support these configuration options:

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `endpoint` | `string` | yes | The S3-compatible store's endpoint URL |
| `region` | `string` | yes | The region for the storage bucket |
| `bucket` | `string` | yes | The bucket name in the storage backend |
| `acl` | `string` | no | Default ACL for uploaded objects (e.g. `"private"`, `"public-read"`) |
| `cache_control` | `string` | no | Default Cache-Control header |
| `content_type` | `string` | no | Default content type |

Driver-specific options may be added through the `config` object. Consult the specific driver documentation for additional options.

## Connecting to multiple stores

A project can use multiple buckets pointing to different storage backends. This is useful for separating hot and cold data, or for multi-region deployments:

```json
{
  "buckets": [
    {
      "name": "hot-storage",
      "driver": "s3",
      "config": {"endpoint": "https://s3.us-east-1.amazonaws.com", "region": "us-east-1", "bucket": "hot"}
    },
    {
      "name": "cold-storage",
      "driver": "s3",
      "config": {"endpoint": "https://s3.us-west-2.amazonaws.com", "region": "us-west-2", "bucket": "cold"}
    },
    {
      "name": "local-assets",
      "driver": "minio",
      "config": {"endpoint": "http://minio:9000", "region": "local", "bucket": "assets"}
    }
  ]
}
```

## Environment variables

Driver configuration can also be set through `PAWABASE_*` environment variables. The `PlatformSettings` class reads from the environment with the `PAWABASE_` prefix:

```toml
[storage]
PAWABASE_STORAGE_ENDPOINT = "https://s3.amazonaws.com"
PAWABASE_STORAGE_REGION = "us-east-1"
PAWABASE_STORAGE_BUCKET = "my-project-receipts"
```

## Performance considerations

- **Connection pooling**: The S3 client maintains a connection pool. Connections are reused across operations.
- **Multipart uploads**: Files larger than the configured threshold are uploaded in multipart chunks.
- **Retries**: Failed operations are retried with exponential backoff by the underlying HTTP client.
- **CORS**: Bucket-level CORS policies are set when the bucket is created and control which origins can access objects directly.

<Note>
The driver configuration is set when the bucket is created and cannot be changed without recreating the bucket. If you need to switch storage backends, create a new bucket and migrate your objects.
</Note>
