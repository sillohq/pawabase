The storage driver determines where objects are physically stored. It is configured at the **environment** level — all buckets in one environment share one driver. You configure the driver in Studio under **Settings → Infrastructure → Storage**, or in the environment's `infra` settings through the Platform API.

Three drivers are supported:

| Driver | Use case |
| --- | --- |
| `local` | Development and single-server deployments. Files stored on the local filesystem. |
| `s3` | Production. Any S3-compatible service: AWS S3, MinIO, Tigris, Cloudflare R2, DigitalOcean Spaces. |
| `memory` | Tests and ephemeral environments. Files stored in memory, lost on restart. |

<Warning>
There is no Google Cloud Storage driver and no Azure Blob Storage driver. If you need GCS or Azure, use an S3-compatible proxy (like rclone serve s3, or a gateway that presents a GCS/Azure bucket as S3) and configure it with the `s3` driver.
</Warning>

## Local driver

Files are stored on the filesystem, under the path configured by `PAWABASE_STORAGE_ROOT` (default: `storage/objects` relative to the working directory).

In Studio, select **local** as the driver and leave the driver-specific fields empty — no credentials or endpoint are needed.

```json
{
  "storage": {
    "driver": "local"
  }
}
```

The local driver is suitable for:
- Local development (`scripts/dev.sh` uses it by default).
- Single-server deployments where the machine running Pawabase also stores files.
- Evaluation and testing.

It is not suitable for multi-replica deployments — each API instance would have its own separate filesystem, and files uploaded to one instance would not be visible to another.

## S3 driver

The S3 driver works with any S3-compatible object storage service. It requires a bucket name, region, access key, and secret key. The endpoint URL is required for non-AWS services.

```json
{
  "storage": {
    "driver": "s3",
    "bucket": "my-app-production",
    "region": "us-east-1",
    "access_key": "AKIAIOSFODNN7EXAMPLE",
    "secret_key": "secret://S3_SECRET_KEY",
    "endpoint": null
  }
}
```

For AWS S3, omit `endpoint` (or set it to `null`). For other providers, set `endpoint` to the service's endpoint URL:

| Provider | Example endpoint |
| --- | --- |
| AWS S3 | (leave null) |
| MinIO | `http://localhost:9000` |
| Cloudflare R2 | `https://<account_id>.r2.cloudflarestorage.com` |
| DigitalOcean Spaces | `https://nyc3.digitaloceanspaces.com` |
| Tigris | `https://fly.storage.tigris.dev` |
| Backblaze B2 | `https://s3.us-west-002.backblazeb2.com` |

### Using secret references

Store the `secret_key` (and `access_key` if you prefer) as an environment secret and reference it:

```json
{
  "storage": {
    "driver": "s3",
    "bucket": "acme-production",
    "region": "eu-west-1",
    "access_key": "secret://S3_ACCESS_KEY",
    "secret_key": "secret://S3_SECRET_KEY"
  }
}
```

See [Secrets](/operate/secrets) for how to create and reference secrets.

### S3 driver field reference

| Field | Required | Description |
| --- | --- | --- |
| `driver` | Yes | `"s3"` |
| `bucket` | Yes | The S3 bucket name |
| `region` | Yes | Region code, e.g. `"us-east-1"` |
| `access_key` | Yes | AWS access key id or equivalent |
| `secret_key` | Yes | AWS secret access key or equivalent — use `secret://` reference |
| `endpoint` | No | Custom endpoint URL for non-AWS providers |

### Bucket creation

Pawabase does not create the S3 bucket for you. You must create it in the provider's console or CLI before configuring the driver. The IAM credentials you provide must have `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject`, and `s3:ListBucket` permissions on the bucket.

## Memory driver

The memory driver stores files in-process and loses them on restart. Use it only for tests:

```json
{
  "storage": {
    "driver": "memory"
  }
}
```

In `scripts/dev.sh`, the API uses the `local` driver by default, not memory. The memory driver is used in unit tests where you need storage to work without any external dependency.

## Configuring via the Platform API

```bash
curl -X PATCH "$STUDIO/studio/api/platform/projects/acme/envs/production/settings" \
  -H "content-type: application/json" -H "X-XSRF-TOKEN: $XSRF" -b cookies.txt \
  -d '{
    "infra": {
      "storage": {
        "driver": "s3",
        "bucket": "acme-prod-files",
        "region": "us-east-1",
        "access_key": "secret://S3_ACCESS_KEY",
        "secret_key": "secret://S3_SECRET_KEY"
      }
    }
  }'
```

The `infra` object uses a flat structure — `infra.storage` contains the driver configuration directly. There is no nested `infra.database.url` style nesting for storage; it's `infra.storage.driver`, `infra.storage.bucket`, etc.

## Signed URLs and the driver

Signed URLs are generated by the driver itself (for S3) or by Pawabase (for local). The URL format differs by driver:

- **S3**: pre-signed S3 URLs, redeemable directly at the S3 endpoint.
- **Local**: Pawabase-signed URLs redeemable through the gateway.

Clients don't need to know which driver is in use — the URL works either way.
