## Policy Structure

```json
{
  "read_policy": {
    "eq": ["$auth.org", "store-7"]
  },
  "write_policy": {
    "in": ["$auth.roles", ["admin", "manager"]]
  }
}
```

## Policy Operators

| Operator | Description | Example |
| --- | --- | --- |
| eq | Equal to | `{"eq": ["$auth.org", "store-7"]}` |
| neq | Not equal to | `{"neq": ["$auth.role", "guest"]}` |
| in | In a list | `{"in": ["$auth.roles", ["admin", "manager"]]}` |
| exists | Field exists | `{"exists": "$auth.user_id"}` |
| and | Logical AND | `{"and": [cond1, cond2]}` |
| or | Logical OR | `{"or": [cond1, cond2]}` |

## Best Practices

**1. Start with the most restrictive policies and broaden as needed**
**2. Use service keys only for server-side operations**
**3. Test policies with different user contexts**
**4. Audit access logs regularly**
**5. Separate read and write policies for fine-grained control**
