Pawabase's API surface is plain REST and JSON — the same surface a browser calls. There is no published native iOS or Android SDK (see [Ecosystem and maturity](/compare/overview#ecosystem-and-maturity-the-honest-section) for why), and this page is honest about that rather than inventing package names that don't exist. Every mobile client guide on this site shows you how to call the REST API directly with the HTTP client your platform already has (`URLSession`, `OkHttp`, `HttpClient`, `dio`), plus a small, honest, hand-rolled wrapper you own and can read top to bottom. Pawabase's surface is plain REST precisely so this works well: you are not missing a "real" way to do it.

## The gateway and the two-credential model

Every mobile request goes through the same gateway as every other client. It carries up to two credentials:

| Header | Answers | Who sets it |
| --- | --- | --- |
| `apikey` | Which project and environment is this? | Your app, once, from configuration — the same value for every user. |
| `Authorization: Bearer <access_token>` | Who, specifically, is calling? | Set per request, after the user signs in. |

`apikey` is **always required**. `Authorization` is **only required when a policy needs to know who's calling**.

Because mobile apps are compiled binaries, the publishable key is embedded in the app bundle. Treat it as public — it's designed to be public — and never embed a secret key. The gateway can't tell where a valid key came from, so a secret key in a mobile app binary means every policy in your project is irrelevant for as long as that key is valid.

<Warning>
A secret key in a mobile app binary is a critical security failure. Decompiled binaries reveal embedded strings. If you need elevated client-side behavior, use a publishable key plus a dedicated service-account user whose roles your policies recognise, or move the operation server-side. See [Security guidance](/concepts/credentials#security-guidance).
</Warning>

## Platform-specific HTTP clients

### iOS (Swift with URLSession)

```swift
struct PawabaseClient {
    let baseUrl: URL
    let apiKey: String
    var accessToken: String?

    func request<T: Decodable>(
        _ path: String,
        method: String = "GET",
        body: Encodable? = nil
    ) async throws -> T {
        var urlComponents = URLComponents(url: baseUrl.appendingPathComponent(path), resolvingAgainstBaseURL: true)!
        var request = URLRequest(url: urlComponents.url!)
        request.httpMethod = method
        request.setValue(apiKey, forHTTPHeaderField: "apikey")
        request.setValue("application/json", forHTTPHeaderField: "content-type")
        if let token = accessToken {
            request.setValue("Bearer \(token)", forHTTPHeaderField: "Authorization")
        }
        if let body = body {
            request.httpBody = try JSONEncoder().encode(body)
        }

        let (data, response) = try await URLSession.shared.data(for: request)
        let httpResponse = response as! HTTPURLResponse

        if httpResponse.statusCode == 401 && method != "POST" {
            try await refreshToken()
            // Retry with new token…
        }

        guard httpResponse.statusCode < 400 else {
            let err = try JSONDecoder().decode(PawabaseError.self, from: data)
            throw err
        }
        return try JSONDecoder().decode(T.self, from: data)
    }

    func refreshToken() async throws {
        guard let refreshToken = Keychain.load("refresh_token") else { return }
        let body: [String: Any] = ["refresh_token": refreshToken, "grant_type": "refresh_token"]
        // … sign-in with refresh_token …
    }
}
```

### Android (Kotlin with OkHttp)

```kotlin
class PawabaseClient(
    private val baseUrl: String,
    private val apiKey: String,
) {
    private val client = OkHttpClient.Builder()
        .connectTimeout(30, TimeUnit.SECONDS)
        .readTimeout(30, TimeUnit.SECONDS)
        .build()

    private var accessToken: String? = null

    suspend fun <T> request(
        path: String,
        method: String = "GET",
        body: Any? = null
    ): T {
        val request = buildRequest(path, method, body)
        val response = client.newCall(request).execute()

        if (response.code == 401 && method != "POST") {
            refreshToken()
            // Retry with new token…
        }

        if (!response.isSuccessful) {
            val error = Gson().fromJson(response.body?.string(), PawabaseError::class.java)
            throw PawabaseApiException(error)
        }
        return Gson().fromJson(response.body?.string(), T::class.java)
    }

    private fun buildRequest(path: String, method: String, body: Any?): Request {
        val url = "$baseUrl$path"
        val builder = Request.Builder().url(url)
            .header("apikey", apiKey)
            .header("content-type", "application/json")
        accessToken?.let { builder.header("Authorization", "Bearer $it") }
        if (body != null) {
            builder.method(method, body.toString().toRequestBody("application/json".toMediaType()))
        }
        return builder.build()
    }
}
```

### Cross-platform (Dart/Flutter with `dio`)

```dart
class PawabaseClient {
  final String baseUrl;
  final String apiKey;
  String? _accessToken;
  String? _refreshToken;

  final _dio = Dio(BaseOptions(
    connectTimeout: const Duration(seconds: 30),
    receiveTimeout: const Duration(seconds: 30),
  ));

  PawabaseClient(this.baseUrl, this.apiKey);

  Future<T> request<T>(
    String path, {
    String method = "GET",
    Map<String, dynamic>? body,
  }) async {
    final options = Options(
      method: method,
      headers: {
        "apikey": apiKey,
        "content-type": "application/json",
        if (_accessToken != null) "Authorization": "Bearer $_accessToken",
      },
    );

    final response = await _dio.request<T>(
      "$baseUrl$path",
      data: body,
      options: options,
    );

    if (response.statusCode == 401 && method != "POST") {
      await _refreshToken();
      // Retry with new token…
    }

    return response.data;
  }

  Future<void> signin(String email, String password) async {
    final data = await request<Map>("auth/v1/token",
      method: "POST",
      body: {"grant_type": "password", "email": email, "password": password},
    );
    _accessToken = data["access_token"];
    _refreshToken = data["refresh_token"];
  }

  Future<void> _refreshToken() async {
    final data = await request<Map>("auth/v1/token/refresh",
      method: "POST",
      body: {"refresh_token": _refreshToken},
    );
    _accessToken = data["access_token"];
    _refreshToken = data["refresh_token"];
  }
}
```

## Resource operations on mobile

The same REST conventions that apply to browsers and servers apply to mobile clients:

```dart
// List with filtering, sorting, and pagination
final orders = await client.request<List>("rest/v1/orders",
  body: {"filter[store_id]": "acme", "sort": "-placed_at", "limit": 20, "offset": 0},
);

// Create
final order = await client.request<Map>("rest/v1/orders",
  method: "POST",
  body: {"store_id": "acme", "total_minor": 2999, "currency": "usd"},
);

// Get with expanded relations
final order = await client.request<Map>("rest/v1/orders/42",
  body: {"expand": "customer,line_items"},
);

// Update
await client.request("rest/v1/orders/42",
  method: "PATCH",
  body: {"status": "paid"},
);

// Delete
await client.request("rest/v1/orders/42", method: "DELETE");
```

## Authentication on mobile

```dart
// Sign up
await client.signin("ada@example.com", "correct horse battery staple");

// The access token and refresh token are stored securely
// Use the platform's secure storage (Keychain on iOS, EncryptedSharedPreferences on Android)
SecureStorage.write(key: "access_token", value: accessToken);
SecureStorage.write(key: "refresh_token", value: refreshToken);
```

Mobile apps should store the refresh token in the platform's secure storage, never in `SharedPreferences` or `NSUserDefaults` in plaintext. The access token can live in memory for the session duration.

<Note>
On mobile, the access token's short lifetime (typically 15 minutes by default) is less of a concern because the refresh token is stored in secure storage and the refresh flow is seamless in the background. The main security concern is preventing the publishable key from being extracted alongside a secret key — which is why mobile apps should only ever have the publishable key.
</Note>

## Signing out

```dart
await client.request("auth/v1/logout",
  method: "POST",
  body: {"scope": "local"}, // "local", "others", or "global"
);
SecureStorage.delete("access_token");
SecureStorage.delete("refresh_token");
```

## Realtime over WebSocket

This is the complete, canonical reference for the realtime WebSocket protocol. It applies identically to web browsers, iOS, Android, and server clients. The gateway proxies WebSocket connections to Angula exactly as it proxies HTTP, applying the same key resolution and forwarding a signed context.

### Connection

Because browsers can't set custom headers on a WebSocket handshake, the key goes in the query string:

```
wss://<gateway host>/realtime/v1/socket?apikey=<publishable key>&token=<access token>
```

The `token` query parameter is optional for anonymous access (publishable key alone), but required for any operation that needs to know who's calling.

### Message protocol

Every message is a JSON object with an `action` field. The messages you send and the messages you receive follow these shapes:

**Subscribe to a channel:**

```json
{"action": "subscribe", "channel": "resource:orders"}
```

**Publish to a channel:**

```json
{"action": "publish", "channel": "resource:orders", "event": "order.paid", "payload": {"id": "42", "status": "paid"}}
```

**Presence — announce yourself on a channel:**

```json
{"action": "presence", "channel": "resource:orders", "user_id": "8", "data": {"name": "Ada"}}
```

**History — request past messages on a channel:**

```json
{"action": "history", "channel": "resource:orders", "limit": 50}
```

**Auth — authenticate a connection after the handshake:**

```json
{"action": "auth", "token": "<access_token>"}
```

**Server → client messages:**

```json
{"type": "message", "channel": "resource:orders", "event": "order.paid", "payload": {"id": "42", "status": "paid"}}
{"type": "presence", "channel": "resource:orders", "action": "join", "user_id": "8", "data": {"name": "Ada"}}
{"type": "presence", "channel": "resource:orders", "action": "leave", "user_id": "8"}
{"type": "history", "channel": "resource:orders", "messages": [{"event": "order.paid", "payload": {...}}, …]}
{"type": "auth", "status": "ok"}
{"type": "auth", "status": "error", "message": "token expired"}
```

### Close codes

The gateway uses custom, application-level close codes so client libraries can distinguish "you're not allowed" from "the network died":

| Close code | Meaning |
| --- | --- |
| `1000` | Normal closure |
| `4001` | Missing or invalid API key |
| `4003` | Upstream refused the connection (channel policy, unknown environment) |
| `1011` | Internal error |

<Tip>
A client library that only inspects close codes can distinguish "you're not allowed" (4001/4003) from "the network died" (1000 or 1011). This is intentional — a library that sees close code 4001 should prompt the user to check their network configuration or sign in again, not retry the connection blindly.
</Tip>

### Reconnection

Realtime connections are inherently fragile on mobile — cellular networks drop, background the app suspends sockets. A robust client:

1. **Detects disconnection** via `onClose` (WebSocket) or the equivalent platform callback.
2. **Waits with exponential backoff** before reconnecting (1s, 2s, 4s, 8s, …, capped at 30s).
3. **Re-subscribes** to all previously subscribed channels after reconnection.
4. **Requests history** for channels that need catch-up data.
5. **Handles `auth` re-authentication** if the access token expired while disconnected.

```dart
void connectWebSocket() {
  final ws = IOWebSocket.connect(
    "wss://api.example.com/realtime/v1/socket?apikey=$PK&token=$token",
  );

  ws.listen((msg) {
    final data = jsonDecode(msg);
    if (data["type"] == "message") {
      _onMessage(data["channel"], data["event"], data["payload"]);
    }
  }, onDone: () {
    // Reconnect with exponential backoff
    Future.delayed(Duration(seconds: _reconnectDelay), connectWebSocket);
    _reconnectDelay = min(_reconnectDelay * 2, 30);
  });
}
```

### Multiple instances and Redis pub/sub

With multiple Angula instances (a typical production deployment), they share publications over Redis pub/sub. A message published against instance A reaches subscribers connected to instance B. Your client library doesn't need to know about this — it just reconnects to whatever gateway URL it's configured with. The gateway handles the routing.

Without Redis (a single instance, or Redis misconfigured), realtime still works but only within one instance's own connections — fine for development, wrong for a multi-replica production deployment. See [Angula — scaling](/concepts/architecture#angula--realtime) for details.

## Storage on mobile

```dart
// Generate a signed URL for upload
final signed = await client.request<Map>("storage/v1/signed/receipts/receipt.pdf");

// Upload directly to the signed URL
final response = await http.put(Uri.parse(signed["url"]), body: fileBytes, headers: signed["fields"]);

// Download
final download = await client.request<Map>("storage/v1/signed/receipts/receipt.pdf?action=read");
```

Storage operations are proxied through the gateway (see [A streaming request/response](/concepts/architecture#a-streaming-requestresponse-gateway-to-api)). Large file uploads and downloads stream through without being fully buffered.

## Error handling on mobile

```dart
try {
  final order = await client.request<Map>("rest/v1/orders/unknown-id");
} on PawabaseApiException catch (e) {
  if (e.statusCode == 422) {
    // Validation error — show field-level messages
    for (final detail in e.details ?? []) {
      print("${detail['field']}: ${detail['message']}");
    }
  } else if (e.statusCode == 401) {
    // Token expired — refresh and retry
    await refreshToken();
  } else if (e.statusCode == 403) {
    // Not authorized
    showError("You don't have permission to do this");
  } else if (e.statusCode == 429) {
    // Rate limited — respect Retry-After
    final retryAfter = e.retryAfter ?? 3;
    await Future.delayed(Duration(seconds: retryAfter));
  } else if (e.statusCode >= 500) {
    // Server error — retry with backoff
  }
}
```
