Python has an official package, **`pawabase`**, and the API is also plain REST that you can call with `requests` or `httpx` yourself. The package is for two jobs: calling a project from a script or server, and writing, testing, deploying and emulating [functions](/code/functions) with the [`pawabase` command](/code/cli). It needs only `httpx`.

```bash
pip install pawabase
```

```python
from pawabase import Pawabase

with Pawabase("https://api.example.com", "pb_sk_...", project="shop", environment="development") as pb:
    page = pb.list("orders", sort="-created_at", limit=20)       # data API
    pb.create("orders", {"total": 12.5})
    pb.invoke_function("orders.pay", {"order_id": 7})             # POST /functions/v1/orders.pay
    pb.invoke_flow("send-receipt", {"order": 7})
    pb.emit_event("order.paid", {"id": 7})                         # needs a secret key: management plane
    pb.run_schedule("nightly-report")
    pb.deployments(branch="my-feature")
```

`AsyncPawabase` has the same methods, each returning an awaitable. Both retry reads on connection errors and `502/503/504`, wait and retry on `429` as the gateway asks, and raise `PawabaseError(status_code, detail)` with `.code`, `.message` and (for a refused deployment) `.problems`. A publishable key (`pb_pk_…`) reaches the data plane under your policies; a **secret** key also reaches the management plane for its own project and environment only.

The rest of this page shows the same calls with `requests` and `httpx`, which is what the package does underneath.

## The two-credential model

Every Python request carries up to two credentials:

| Header | Answers | Who sets it |
| --- | --- | --- |
| `apikey` (or `x-api-key`, or `?apikey=`) | Which project and environment is this? Also carries the key's role (`publishable`/`secret`) and scopes. | Your script, once, from environment variables — the same value for every user of your app. |
| `Authorization: Bearer <access_token>` | Who, specifically, is calling? | Set per request, after the user signs in, from the token Akountz issued them. |

`apikey` is **always required**. `Authorization` is **only required when a policy needs to know who's calling**. For server-to-server calls using the **secret** key, the `apikey` alone is sufficient — the secret key already has full access, and no `Authorization` header is needed.

```python
# A server-to-server call using the secret key
import requests

res = requests.get(
    f"{GW}/rest/v1/invoices",
    headers={"apikey": SECRET_KEY},
)

# A signed-in user's request — both credentials
res = requests.get(
    f"{GW}/rest/v1/orders?filter[store_id]=acme",
    headers={
        "apikey": PUBLISHABLE_KEY,
        "Authorization": f"Bearer {access_token}",
    },
)
```

<Warning>
The secret key is a service credential: it bypasses every policy in your project. Never ship it in a client bundle, a public repository, or a mobile app's assets. Keep it in a server-side secret manager or environment variable that never gets bundled. If one leaks, treat it as compromised: rotate it immediately from Studio's API keys page. See [Security guidance](/concepts/credentials#security-guidance).
</Warning>

## Sync client: `requests`

For scripts, background workers, and server-side tooling, the synchronous `requests` library is the natural fit:

```python
import requests
import os

GW = os.environ["PAWABASE_GW"]
PK = os.environ["PAWABASE_PUBLISHABLE_KEY"]
SK = os.environ["PAWABASE_SECRET_KEY"]

# List records with filtering, sorting, and pagination
res = requests.get(
    f"{GW}/rest/v1/orders",
    headers={"apikey": PK},
    params={"filter[store_id]": "acme", "sort": "-placed_at", "limit": 20, "offset": 0},
)
res.raise_for_status()
data = res.json()  # {"data": [...], "total": <int>, "limit": 20, "offset": 0}

# Create a record
res = requests.post(
    f"{GW}/rest/v1/orders",
    headers={"apikey": PK, "content-type": "application/json"},
    json={"store_id": "acme", "total_minor": 2999, "currency": "usd"},
    headers={"Idempotency-Key": "order-42-create-2026-09-28"},
)
res.raise_for_status()
order = res.json()

# Get a single record with expanded relations
res = requests.get(
    f"{GW}/rest/v1/orders/42?expand=customer,line_items",
    headers={"apikey": PK, "Authorization": f"Bearer {access_token}"},
)
order = res.json()

# Update a record
res = requests.patch(
    f"{GW}/rest/v1/orders/42",
    headers={"apikey": PK, "content-type": "application/json"},
    json={"status": "paid"},
)
res.raise_for_status()

# Delete a record
res = requests.delete(
    f"{GW}/rest/v1/orders/42",
    headers={"apikey": PK, "Authorization": f"Bearer {access_token}"},
)
assert res.status_code == 204
```

### Error handling with `requests`

```python
import requests
from requests.exceptions import HTTPError, ConnectionError, Timeout

def api_request(method: str, path: str, **kwargs) -> dict:
    res = requests.request(method, f"{GW}{path}", **kwargs)
    try:
        res.raise_for_status()
    except HTTPError as e:
        err = res.json()
        raise PawabaseApiError(
            code=err.get("code", "unknown"),
            message=err.get("message", str(e)),
            status=res.status_code,
            details=err.get("details"),
        ) from e
    return res.json()
```

## Async client: `httpx`

For async Python (FastAPI backends, aiohttp workers, scheduled jobs), `httpx` gives you the same REST surface with async I/O:

```python
import httpx
import os

GW = os.environ["PAWABASE_GW"]
PK = os.environ["PAWABASE_PUBLISHABLE_KEY"]

async def list_orders(store_id: str) -> dict:
    async with httpx.AsyncClient() as client:
        res = await client.get(
            f"{GW}/rest/v1/orders",
            headers={"apikey": PK},
            params={"filter[store_id]": store_id, "sort": "-placed_at", "limit": 50},
            timeout=30.0,
        )
        res.raise_for_status()
        return res.json()

async def create_order(data: dict) -> dict:
    async with httpx.AsyncClient() as client:
        res = await client.post(
            f"{GW}/rest/v1/orders",
            headers={"apikey": PK, "content-type": "application/json"},
            json=data,
            timeout=30.0,
        )
        res.raise_for_status()
        return res.json()
```

<Note>
The gateway streams request and response bodies without fully buffering them (see [A streaming request/response](/concepts/architecture#a-streaming-requestresponse-gateway-to-api)). `httpx` handles streaming natively — for large file uploads or downloads, pass `content` as a file-like object or use `httpx.Client(transport=httpx.HTTPTransport(stream_writes=True))` to avoid buffering the entire body in memory.
</Note>

## The typed wrapper pattern

Because Pawabase resources are user-defined, a hand-rolled wrapper gives you typed call sites without the code-generation step. This wrapper covers the common patterns:

```python
from __future__ import annotations
from dataclasses import dataclass
from typing import Any, Generic, TypeVar, Optional
import requests

T = TypeVar("T")

@dataclass
class PawabaseClient:
    base_url: str
    api_key: str
    _token: Optional[str] = None
    _refresh_token: Optional[str] = None

    def _headers(self, *, with_auth: bool = False) -> dict[str, str]:
        headers: dict[str, str] = {
            "apikey": self.api_key,
            "content-type": "application/json",
        }
        if with_auth and self._token:
            headers["Authorization"] = f"Bearer {self._token}"
        return headers

    def _request(self, method: str, path: str, **kwargs) -> dict:
        res = requests.request(method, f"{self.base_url}{path}", headers=self._headers(), **kwargs)
        if res.status_code == 401 and method != "POST" and self._refresh_token:
            self._refresh_token_and_retry()
            res = requests.request(method, f"{self.base_url}{path}", headers=self._headers(**kwargs), **kwargs)
        res.raise_for_status()
        return res.json()

    def _refresh_token_and_retry(self) -> None:
        data = self._request("POST", "/auth/v1/token/refresh", json={
            "refresh_token": self._refresh_token,
        })
        self._token = data["access_token"]
        self._refresh_token = data["refresh_token"]

    def list(self, resource: str, params: Optional[dict[str, Any]] = None) -> list[dict]:
        data = self._request("GET", f"/rest/v1/{resource}", params=params or {})
        return data["data"]

    def get(self, resource: str, id: str, params: Optional[dict[str, Any]] = None) -> dict:
        qs = f"?{params}" if params else ""
        return self._request("GET", f"/rest/v1/{resource}/{id}{qs}")

    def create(self, resource: str, data: dict) -> dict:
        return self._request("POST", f"/rest/v1/{resource}", json=data)

    def update(self, resource: str, id: str, data: dict) -> dict:
        return self._request("PUT", f"/rest/v1/{resource}/{id}", json=data)

    def patch(self, resource: str, id: str, data: dict) -> dict:
        return self._request("PATCH", f"/rest/v1/{resource}/{id}", json=data)

    def delete(self, resource: str, id: str) -> None:
        self._request("DELETE", f"/rest/v1/{resource}/{id}")

    def auth_signup(self, email: str, password: str) -> dict:
        return self._request("POST", "/auth/v1/signup", json={"email": email, "password": password})

    def auth_signin(self, email: str, password: str) -> dict:
        data = self._request("POST", "/auth/v1/token", json={
            "grant_type": "password", "email": email, "password": password,
        })
        self._token = data["access_token"]
        self._refresh_token = data["refresh_token"]
        return data

    def auth_signout(self) -> None:
        self._request("POST", "/auth/v1/logout", json={"scope": "local"})
        self._token = None
        self._refresh_token = None

    def flow_run(self, name: str, input: dict) -> dict:
        return self._request("POST", f"/flows/v1/{name}", json=input)
```

Usage is clean and typed:

```python
client = PawabaseClient(base_url=os.environ["PAWABASE_GW"], api_key=os.environ["PAWABASE_PUBLISHABLE_KEY"])
client.auth_signin("ada@example.com", "correct horse battery staple")

orders = client.list("orders", params={"filter[store_id]": "acme", "sort": "-placed_at", "limit": 20})
order = client.create("orders", {"store_id": "acme", "total_minor": 2999, "currency": "usd"})
client.flow_run("pay-order", {"params": {"id": "order_42"}})
```

## Authentication

### Sign up and sign in

```python
# Sign up
data = client.auth_signup("ada@example.com", "correct horse battery staple")
# {"access_token": "eyJhbGciOi…", "refresh_token": "8f2c9e…", "token_type": "bearer", "expires_in": 3600, "user": {…}}

# Sign in (the same flow)
data = client.auth_signin("ada@example.com", "correct horse battery staple")

# Access and refresh tokens are stored by the client
access_token = data["access_token"]
refresh_token = data["refresh_token"]
```

### Token refresh

```python
# The wrapper handles this automatically on a 401, but you can do it manually:
data = client._request("POST", "/auth/v1/token/refresh", json={"refresh_token": refresh_token})
access_token = data["access_token"]
refresh_token = data["refresh_token"]
```

Refresh tokens are **rotating**: every use issues a new access token and a new refresh token, and the one just used stops working. See [Refreshing and revocation](/concepts/credentials#refreshing-and-revocation).

### Sign out

```python
client.auth_signout()
```

## Resource operations

Full CRUD with filtering, sorting, pagination, and relation expansion:

```python
# List with filtering, sorting, and pagination
orders = client.list("orders", params={
    "filter[store_id]": "acme",
    "sort": "-placed_at",
    "limit": 20,
    "offset": 0,
})
# Returns [{"id": "42", "store_id": "acme", …}, …]

# Get a single record with expanded relations
order = client.get("orders", "42", params={"expand": "customer,line_items"})

# Create
order = client.create("orders", {"store_id": "acme", "total_minor": 2999, "currency": "usd"})

# Update (full replacement)
order = client.update("orders", "42", {"status": "paid", "total_minor": 2999})

# Update (partial)
order = client.patch("orders", "42", {"status": "paid"})

# Delete
client.delete("orders", "42")
```

## Calling flows

```python
# Run a flow by name
result = client.flow_run("pay-order", {"params": {"id": "order_42"}})
# The flow runs synchronously — the response is the flow's output

# Run a flow with an auth context (acting on behalf of a specific user)
result = client.flow_run("pay-order", {"params": {"id": "order_42"}})
```

## Server-to-server calls with the secret key

A backend you control — a Python worker, a scheduled job, a CI pipeline — calling Pawabase is a client like any other, just usually with the **secret** key and no `Authorization` header:

```python
import os
import requests

GW = os.environ["PAWABASE_GW"]
SECRET_KEY = os.environ["PAWABASE_SECRET_KEY"]

# The secret key bypasses all policies — full access to the environment
res = requests.get(f"{GW}/rest/v1/invoices", headers={"apikey": SECRET_KEY})
res.raise_for_status()

# Create records without policy checks
res = requests.post(f"{GW}/rest/v1/invoices", headers={
    "apikey": SECRET_KEY,
    "content-type": "application/json",
}, json={"student_id": 12, "amount": 210000})
```

<Warning>
If a server integration should have *limited* power rather than full access, give it a secret key with [scopes](/concepts/credentials#scopes) narrowed to what it needs (for example `resource:read` only), or issue it a publishable key plus a dedicated service-account user whose role your policies recognise, rather than routing everything through an unscoped secret key.
</Warning>

## Error handling in practice

```python
class PawabaseApiError(Exception):
    def __init__(self, code: str, message: str, status: int, details: list | None = None):
        self.code = code
        self.message = message
        self.status = status
        self.details = details
        super().__init__(f"[{status}] {code}: {message}")

def api_request(method: str, path: str, **kwargs) -> dict:
    res = requests.request(method, f"{GW}{path}", **kwargs)
    try:
        res.raise_for_status()
    except requests.HTTPError:
        err = res.json()
        raise PawabaseApiError(
            code=err.get("code", "unknown"),
            message=err.get("message", str(res.status_code)),
            status=res.status_code,
            details=err.get("details"),
        ) from None
    return res.json()
```

| Error code | Status | Python handling |
| --- | --- | --- |
| `validation` | `422` | Inspect `error.details` for per-field messages |
| `unauthenticated` | `401` | Refresh token and retry, or redirect to sign-in |
| `missing_role` | `403` | Don't retry — the caller isn't authorized |
| `rate_limit_exceeded` | `429` | Sleep `error.retry_after` seconds, then retry |
| `order_not_found` | `404` | Resource doesn't exist — handle gracefully |
| `timeout` | `504` | The flow timed out — retry the request |
| `internal_error` | `500` | Server-side failure — log and retry with backoff |

## Streaming large bodies

For large file uploads and downloads, use `requests` streaming mode to avoid buffering the entire body in memory:

```python
# Streaming upload
with open("large-file.pdf", "rb") as f:
    res = requests.put(
        f"{GW}/storage/v1/receipts/2026/inv-04.pdf",
        headers={"apikey": SECRET_KEY, "content-type": "application/pdf"},
        data=f,  # httpx/requests streams this without buffering
    )
    res.raise_for_status()

# Streaming download
res = requests.get(f"{GW}/storage/v1/receipts/2026/inv-04.pdf", headers={"apikey": SECRET_KEY}, stream=True)
with open("inv-04.pdf", "wb") as f:
    for chunk in res.iter_content(chunk_size=8192):
        f.write(chunk)
```

The gateway proxies streaming request and response bodies without fully buffering them. See [A streaming request/response](/concepts/architecture#a-streaming-requestresponse-gateway-to-api) for the full walkthrough.
