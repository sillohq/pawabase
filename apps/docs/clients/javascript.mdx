`@pawabase/client` is the official TypeScript client. It has no dependencies, uses only `fetch` and `WebSocket`, and gives every part of Pawabase a method: records (`from`), auth, storage, functions, flows, custom routes and realtime. It does the parts that are easy to get subtly wrong: one shared token refresh, retries that are safe, and filters that the server would otherwise answer wrongly.

```bash
npm install @pawabase/client
```

```typescript
import { createClient } from "@pawabase/client";

const pawabase = createClient({
  url: "https://api.example.com",   // the gateway
  apiKey: "pb_pk_…",                // a publishable key
});

await pawabase.auth.signInWithPassword({ email: "ada@example.com", password: "…" });
const page = await pawabase.from("posts").eq("status", "live").order("created_at", "desc").perPage(20);
```

## The two credentials

Each request carries up to two credentials, and the client sets both.

| Credential | Header | Answers |
| --- | --- | --- |
| API key | `apikey` | Which project and environment, and with which role |
| User token | `Authorization: Bearer` | Who is calling. Only sent when someone is signed in |

A **publishable** key (`pb_pk_…`) is safe in a browser and policies apply. A **secret** key (`pb_sk_…`) bypasses every policy, so the client refuses to start with one in a browser (`ConfigError`).

## Records

```typescript
const posts = pawabase.from("posts");

await posts.create({ title: "Hello" });            // the created row, with id, defaults and timestamps
await posts.get(1, { expand: ["author"] });        // a missing record is a NotFoundError
await posts.maybeGet(1);                           // null instead
await posts.update(1, { title: "Hi" });            // PATCH
await posts.delete(1);
```

A list is a query: chain methods, then `await` it. Queries are immutable, so a base query can be reused.

```typescript
const live = pawabase.from("posts").eq("status", "live");

await live.gte("views", 100).order("views", "desc").perPage(50).page(2);
await live.like("title", "Intro*").first();        // a row or null
await live.count();                                // a number
await live.all({ maxRecords: 1000 });              // every row, across pages
for await (const post of live) { /* page by page */ }

await pawabase.from("posts").where({ status: "live", views: { gte: 10 }, org_id: null });
await pawabase.from("posts").in("id", [1, 2, 3]).select("id", "title").expand("author");
```

| Methods | Server operator |
| --- | --- |
| `eq` `neq` `gt` `gte` `lt` `lte` | `eq` `neq` `gt` `gte` `lt` `lte` |
| `like` `ilike` | `like` `ilike`; `*` or `%` match any run of characters |
| `in` `notIn` | `in` `nin` |
| `is` `isNot` | `is` `isnot` with `null`, `true` or `false` |

A page is `{ data, page, per_page, total }`. `per_page` is 20 by default and at most 200.

### Where the client protects you

Three behaviours of the list endpoint return wrong data without an error. The client handles each (see [Filtering](/data/filtering) for the server side).

| Server behaviour | What the client does |
| --- | --- |
| A repeated filter on one field keeps only the last, so a two-sided range cannot be written | Throws `InvalidQueryError` for the second filter on a field |
| `filter[flag]=eq.false` matches the wrong rows | Sends `is.false` for `eq(col, false)`, `is.null` for `eq(col, null)` |
| `in` lists are split on commas | Refuses a value that contains a comma; an empty list matches nothing and sends no request |

Two more things to know. `total` is `null` when a per-row policy makes the count unknowable (see [Pushdown](/policies/pushdown)), and pages can then be short or empty with more behind them, so `all()` stops at the first empty page (`stopAfterEmptyPages` makes it more patient). `select()` leaves unselected columns in the row as `null`.

`createMany(rows)` creates a few at a time and returns `{ created, failed }`. It is **not atomic**.

## Auth

```typescript
const { session, verificationRequired } = await pawabase.auth.signUp({ email, password, data: { plan: "free" } });

const result = await pawabase.auth.signInWithPassword({ email, password });
if (result.status === "mfa_required") await result.verify(codeFromAuthenticator);

pawabase.auth.onAuthStateChange((event, session) => { /* INITIAL_SESSION, SIGNED_IN, TOKEN_REFRESHED, USER_UPDATED, SIGNED_OUT */ });

await pawabase.auth.getUser();
await pawabase.auth.updateUser({ name: "Ada", data: { theme: "dark" } });
await pawabase.auth.signOut();                     // { scope: "global" } ends every session
```

### The session

The session is stored in `localStorage` in browsers and in memory elsewhere; pass `auth.storage` (anything with `getItem`, `setItem`, `removeItem`) for React Native or cookies. It is refreshed shortly before the access token expires, and a `401` triggers one refresh and a replay of the request.

Refreshing happens **once at a time**. Akountz rotates refresh tokens and treats a reused one as theft, so two refreshes racing would sign the user out. Concurrent requests share one exchange, and across tabs the Web Locks API serialises it where the browser has it. A refresh is never retried after a network failure, for the same reason.

### Other flows

| Need | Methods |
| --- | --- |
| Email links | `signInWithMagicLink`, `verifyMagicLink`, `requestPasswordReset`, `resetPassword`, `verifyEmail`, `resendVerification`, `confirmEmailChange` |
| Second factor | `mfa.enroll`, `mfa.verifyEnrollment`, `mfa.disable`, `mfa.regenerateRecoveryCodes`, `mfa.status` |
| Devices | `sessions.list`, `sessions.revoke`, `sessions.history` |
| Organizations | `orgs.*` (members, invitations, teams) and `switchOrg(slug)` |
| What the project offers | `settings()` |

Social sign-in builds a URL that names the project and environment, so pass them:

```typescript
const pawabase = createClient({ url, apiKey, project: "acme", environment: "production" });
pawabase.auth.signInWithOAuth("github", { redirectTo: location.origin });
// Back on your page, the tokens in the URL fragment are read automatically.
```

## Storage

```typescript
const avatars = pawabase.storage.from("avatars");

await avatars.upload("u1/me.png", file);           // Blob, File, bytes, string or a stream
const blob = await avatars.download("u1/me.png");
const { files, prefixes, cursor } = await avatars.list({ prefix: "u1/" });
for await (const file of avatars.listAll({ prefix: "u1/" })) { /* every object */ }
await avatars.remove("u1/me.png");

avatars.getPublicUrl("u1/me.png");                 // public bucket; for <img src>
const { url } = await avatars.createSignedUrl("u1/me.png", { expiresIn: 300 });

const slot = await avatars.createSignedUploadUrl("u1/new.png", { contentType: "image/png", maxBytes: 1_000_000 });
await avatars.uploadToSignedUrl(slot.url, file);   // sends no key: the URL is the credential
```

The bucket's policy, accepted types and size limit decide what is allowed, and a refusal is an error, not a truncated file. `getPublicUrl` puts the publishable key in the URL and refuses a secret key.

## Functions, flows and routes

```typescript
await pawabase.functions.invoke<{ total: number }>("price", { sku: "a" });   // unwraps { data }
await pawabase.flows.run("whoami");                                          // the flow's response body
await pawabase.routes.post("checkout/start", { cart: 1 }, { query: { dry: true } });
await pawabase.request("GET", "/some/path");                                 // anything else, with auth and retries
```

`flows.run` reaches flows whose HTTP trigger has no path. Flows bound to a path are custom routes.

## Realtime

```typescript
const room = pawabase.realtime.channel<{ text: string }>("chat:lobby", { presence: { name: "Ada" }, replay: 50 });

room.on("message", (m) => console.log(m.from, m.payload.text));
room.onEvent("typing", (m) => { /* only this event */ });
room.on("presence", ({ joins, leaves, members }) => { /* … */ });

await room.subscribe();                            // rejects with RealtimeError("forbidden") if the rule refuses
await room.send("message", { text: "hi" });        // resolves when the server accepted it
await room.track({ name: "Ada", typing: true });
await room.history(20);
await room.unsubscribe();
```

The connection reconnects with backoff, rejoins every channel, and with `replay: n` fetches the last `n` messages and delivers the ones you missed once (messages are de-duplicated by id). Pings run every 25 seconds, and a silent link is recycled. A refreshed access token is sent to the open socket. Channel names are authorised by the project's [realtime rules](/realtime/overview).

On Node 20 there is no global `WebSocket`; pass one with `realtime: { webSocket }`.

## Types

Generate a `Database` type from your environment's OpenAPI document, and resource names, row types and column names are checked:

```bash
npx pawabase-types --url https://api.example.com --project acme --env production --out src/pawabase.types.ts
```

```typescript
import type { Database } from "./pawabase.types";
const pawabase = createClient<Database>({ url, apiKey });

await pawabase.from("posts").create({ title: "ok" });   // checked
await pawabase.from("posts").create({ views: 3 });      // error: title is required
pawabase.from("posts").eq("nope", 1);                   // error: no such column
```

The gateway serves the document at `/docs/v1/<project>/<env>/openapi.json` when the environment's public docs setting is on. Otherwise save it from Studio's API Explorer and pass `--file`. Run `pawabase-types --check` in CI to catch drift. Relations you `expand` are not in the document; add them to the row type yourself.

## Errors

Everything thrown is a `PawabaseError`. The server sends errors as plain strings, as arrays of validation issues, and as `{ error, message, details }` objects, and the client turns all of them into one set of classes. See [Errors](/clients/errors) for the status table.

| Class | Meaning | Useful fields |
| --- | --- | --- |
| `AuthenticationError` | `401`: a bad key (`code: "invalid_api_key"`), signed out, or expired | |
| `PermissionError` | `403` | `policy`, the refusing policy when named |
| `NotFoundError` | `404`: no record, or a read policy hides it | |
| `ValidationError` | `422`: refused before any policy ran | `fieldError("email")`, `byField()`, `issues` |
| `ConflictError` | `409` | |
| `RateLimitError` | `429` | `retryAfter` in seconds |
| `ServerError` | `5xx` | |
| `NetworkError`, `TimeoutError`, `AbortError` | No response | |

Every `ApiError` has `status`, `code`, `message`, `details`, `body` and `requestId`. The request id is the `x-request-id` header: look it up in [Observability](/operate/observability).

```typescript
try {
  await pawabase.from("posts").create(input);
} catch (error) {
  if (error instanceof ValidationError) showFieldErrors(error.byField());
  else if (error instanceof PermissionError) console.warn(`refused by policy ${error.policy}`);
  else throw error;
}
```

## Retries and timeouts

| Situation | Retried |
| --- | --- |
| `429` | Yes, for any method (it is answered before a handler runs), after `Retry-After` up to 30 seconds; a longer wait is surfaced |
| `502`, `503`, `504`, a network failure, a timeout | Yes for `GET`, `PUT` and `DELETE`. Not for `POST` and `PATCH` unless the call sets `idempotent: true` |
| `500` and every `4xx` | No |

The defaults are two retries with jittered exponential backoff (300 ms up to 8 s) and a 30 second timeout per attempt. Set `retry` and `timeoutMs` on the client; every call also takes an `AbortSignal`. `hooks` (`onRequest`, `onResponse`, `onRetry`, `onError`) observe traffic with keys and tokens masked.

## Servers and server-side rendering

```typescript
// Act for the signed-in user of this request: no session, no refresh, no storage.
const asUser = pawabase.asUser(tokenFromTheRequest);
await asUser.from("tasks").all();

// Act as the server itself, bypassing policies.
const admin = createClient({ url, apiKey: process.env.PAWABASE_SECRET_KEY! });
```

Call `client.dispose()` when you discard a client, to stop its timers and close the socket.

## Without the SDK

Everything above is plain REST, so any HTTP client works: send `apikey` always and `Authorization: Bearer` when a policy needs to know who is calling. The conventions are in [REST conventions](/clients/rest-conventions). The things the SDK does for you, and a hand-written wrapper would have to: share one refresh, avoid retrying a `POST`, send `is.false` for booleans, and read three error body shapes.
