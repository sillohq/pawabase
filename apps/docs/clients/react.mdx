Pawabase's API surface is plain REST and JSON. There is no published `@pawabase/react` SDK — and this page is honest about that rather than inventing package names that don't exist. Every React client guide on this site shows you how to call the REST API directly with `fetch` (or your preferred HTTP client) and build the React layer yourself, plus a small, honest, hand-rolled wrapper you own and can read top to bottom. Pawabase's surface is plain REST precisely so this works well: you are not missing a "real" way to do it.

## The two-credential model in React

Every React request carries up to two credentials:

| Header | Answers | Who sets it |
| --- | --- | --- |
| `apikey` | Which project and environment is this? Also carries the key's role and scopes. | Your app, once, from environment variables or config. |
| `Authorization: Bearer <access_token>` | Who, specifically, is calling? | Set per request, after the user signs in, from the token Akountz issued them. |

`apikey` is **always required**. `Authorization` is **only required when a policy needs to know who's calling**.

## The Pawabase context

A React context holds the authentication state and provides it to every component that needs it. This is the foundation everything else is built on:

```tsx
// PawabaseContext.tsx — your hand-rolled auth context
import { createContext, useContext, useState, useCallback, useEffect, type ReactNode } from "react";

interface PawabaseUser {
  id: string;
  email: string;
  name: string;
  roles: string[];
  permissions: string[];
  org: string | null;
}

interface PawabaseAuthState {
  user: PawabaseUser | null;
  isAuthenticated: boolean;
  isLoading: boolean;
  error: string | null;
  accessToken: string | null;
}

interface PawabaseAuthContextValue extends PawabaseAuthState {
  signin: (email: string, password: string) => Promise<void>;
  signup: (email: string, password: string) => Promise<void>;
  signout: () => Promise<void>;
}

const PawabaseAuthContext = createContext<PawabaseAuthContextValue | null>(null);

const GW = import.meta.env.VITE_PAWABASE_GW;
const PK = import.meta.env.VITE_PAWABASE_PUBLISHABLE_KEY;

function getStoredToken(): string | null {
  if (typeof window === "undefined") return null;
  return localStorage.getItem("access_token");
}

function getStoredUser(): PawabaseUser | null {
  if (typeof window === "undefined") return null;
  const raw = localStorage.getItem("pawabase_user");
  return raw ? JSON.parse(raw) : null;
}

export function PawabaseProvider({ children }: { children: ReactNode }) {
  const [state, setState] = useState<PawabaseAuthState>({
    user: getStoredUser(),
    isAuthenticated: !!getStoredToken(),
    isLoading: true,
    error: null,
    accessToken: getStoredToken(),
  });

  // On mount, validate the stored token
  useEffect(() => {
    const token = getStoredToken();
    if (!token) {
      setState(prev => ({ ...prev, isLoading: false }));
      return;
    }
    // Verify the token is still valid by making a lightweight request
    fetch(`${GW}/auth/v1/me`, {
      headers: { "apikey": PK, "Authorization": `Bearer ${token}` },
    })
      .then(res => res.json())
      .then(data => {
        const user: PawabaseUser = data.user;
        localStorage.setItem("pawabase_user", JSON.stringify(user));
        setState({ user, isAuthenticated: true, isLoading: false, error: null, accessToken: token });
      })
      .catch(() => {
        // Token expired or invalid — clear storage and prompt sign-in
        localStorage.removeItem("access_token");
        localStorage.removeItem("pawabase_user");
        setState({ user: null, isAuthenticated: false, isLoading: false, error: null, accessToken: null });
      });
  }, []);

  const signin = useCallback(async (email: string, password: string) => {
    const res = await fetch(`${GW}/auth/v1/token`, {
      method: "POST",
      headers: { "apikey": PK, "content-type": "application/json" },
      body: JSON.stringify({ grant_type: "password", email, password }),
    });
    if (!res.ok) {
      const err = await res.json();
      throw new Error(err.message);
    }
    const data = await res.json();
    localStorage.setItem("access_token", data.access_token);
    localStorage.setItem("refresh_token", data.refresh_token);
    localStorage.setItem("pawabase_user", JSON.stringify(data.user));
    setState({ user: data.user, isAuthenticated: true, isLoading: false, error: null, accessToken: data.access_token });
  }, []);

  const signup = useCallback(async (email: string, password: string) => {
    const res = await fetch(`${GW}/auth/v1/signup`, {
      method: "POST",
      headers: { "apikey": PK, "content-type": "application/json" },
      body: JSON.stringify({ email, password }),
    });
    if (!res.ok) {
      const err = await res.json();
      throw new Error(err.message);
    }
    const data = await res.json();
    localStorage.setItem("access_token", data.access_token);
    localStorage.setItem("refresh_token", data.refresh_token);
    localStorage.setItem("pawabase_user", JSON.stringify(data.user));
    setState({ user: data.user, isAuthenticated: true, isLoading: false, error: null, accessToken: data.access_token });
  }, []);

  const signout = useCallback(async () => {
    const token = getStoredToken();
    await fetch(`${GW}/auth/v1/logout`, {
      method: "POST",
      headers: { "apikey": PK, "Authorization": `Bearer ${token}` },
      body: JSON.stringify({ scope: "local" }),
    }).catch(() => {}); // Sign out even if the server call fails
    localStorage.removeItem("access_token");
    localStorage.removeItem("refresh_token");
    localStorage.removeItem("pawabase_user");
    setState({ user: null, isAuthenticated: false, isLoading: false, error: null, accessToken: null });
  }, []);

  return (
    <PawabaseAuthContext.Provider value={{ ...state, signin, signup, signout }}>
      {children}
    </PawabaseAuthContext.Provider>
  );
}

export function useAuth(): PawabaseAuthContextValue {
  const ctx = useContext(PawabaseAuthContext);
  if (!ctx) throw new Error("useAuth must be used within a PawabaseProvider");
  return ctx;
}
```

<Note>
The access token belongs in memory and in `localStorage` for SPA convenience — but be aware that anything in `localStorage` is readable by any script on your page, including a successful XSS payload. If your app has any server component, prefer setting the refresh token as an httpOnly, `Secure`, `SameSite=Lax` cookie from your own domain rather than handing it to client JavaScript at all. See [Tokens and storage](/clients/overview#tokens-and-storage).
</Note>

## Automatic token refresh

A `fetch` wrapper that catches `401` responses, refreshes the token, and retries the original request once. This is the single most important piece of infrastructure every Pawabase React client needs:

```tsx
// apiClient.ts — the authenticated fetch wrapper

let refreshPromise: Promise<{ access_token: string } | null> | null = null;

async function refreshAccessToken(): Promise<{ access_token: string } | null> {
  if (refreshPromise) return refreshPromise;
  refreshPromise = (async () => {
    const refreshToken = localStorage.getItem("refresh_token");
    if (!refreshToken) return null;
    try {
      const res = await fetch(`${GW}/auth/v1/token/refresh`, {
        method: "POST",
        headers: { "apikey": PK, "content-type": "application/json" },
        body: JSON.stringify({ refresh_token: refreshToken }),
      });
      if (!res.ok) throw new Error("refresh failed");
      const data = await res.json();
      localStorage.setItem("access_token", data.access_token);
      localStorage.setItem("refresh_token", data.refresh_token);
      return data;
    } catch {
      localStorage.removeItem("access_token");
      localStorage.removeItem("refresh_token");
      localStorage.removeItem("pawabase_user");
      return null;
    } finally {
      refreshPromise = null;
    }
  })();
  return refreshPromise;
}

export async function pawabaseFetch<T>(path: string, options: RequestInit = {}): Promise<T> {
  const token = localStorage.getItem("access_token");
  const headers: Record<string, string> = {
    "apikey": PK,
    "content-type": "application/json",
    ...(options.headers as Record<string, string> || {}),
  };
  if (token) headers["Authorization"] = `Bearer ${token}`;

  const res = await fetch(`${GW}${path}`, { ...options, headers });

  if (res.status === 401 && options.method !== "POST") {
    const newData = await refreshAccessToken();
    if (!newData) {
      window.location.href = "/signin";
      throw new Error("Session expired");
    }
    headers["Authorization"] = `Bearer ${newData.access_token}`;
    const retryRes = await fetch(`${GW}${path}`, { ...options, headers });
    if (!retryRes.ok) throw await parseError(retryRes);
    return retryRes.json();
  }

  if (!res.ok) throw await parseError(res);
  return res.json();
}

async function parseError(res: Response): Promise<Error & { code: string; status: number; details?: unknown[] }> {
  const body = await res.json().catch(() => ({}));
  const error = new Error(body.message || res.statusText) as Error & { code: string; status: number; details?: unknown[] };
  error.code = body.code || "unknown";
  error.status = res.status;
  error.details = body.details;
  return error;
}
```

## Data-fetching hooks

With `pawabaseFetch` in place, building data hooks is straightforward. Here's a pattern using `react-query`-style hooks (adaptable to `swr` or any data-fetching library):

```tsx
// hooks/useResourceList.tsx
import { useQuery, useQueryClient } from "@tanstack/react-query";
import { pawabaseFetch } from "../apiClient";

interface ResourceListOptions {
  filter?: Record<string, string>;
  sort?: string;
  limit?: number;
  offset?: number;
  expand?: string;
}

export function useResourceList<T>(resource: string, options: ResourceListOptions = {}) {
  const params = new URLSearchParams();
  if (options.filter) Object.entries(options.filter).forEach(([k, v]) => params.set(`filter[${k}]`, v));
  if (options.sort) params.set("sort", options.sort);
  if (options.limit) params.set("limit", String(options.limit));
  if (options.offset) params.set("offset", String(options.offset));
  if (options.expand) params.set("expand", options.expand);

  return useQuery<T[]>({
    queryKey: ["resource", resource, options],
    queryFn: () => pawabaseFetch<T[]>(`/rest/v1/${resource}?${params.toString()}`),
    staleTime: 30000, // Data is fresh for 30 seconds
  });
}

export function useResource<T>(resource: string, id: string, options: ResourceListOptions = {}) {
  const params = new URLSearchParams();
  if (options.expand) params.set("expand", options.expand);

  return useQuery<T>({
    queryKey: ["resource", resource, id],
    queryFn: () => pawabaseFetch<T>(`/rest/v1/${resource}/${id}?${params.toString()}`),
  });
}
```

Usage:

```tsx
function OrderList() {
  const { data: orders, isLoading, error, refetch } = useResourceList("orders", {
    filter: { store_id: "acme" },
    sort: "-placed_at",
    limit: 20,
  });

  if (isLoading) return <Spinner />;
  if (error) return <Alert>{(error as Error & { code: string }).message}</Alert>;

  return (
    <ul>
      {orders?.map(order => (
        <li key={order.id}>{order.number}</li>
      ))}
    </ul>
  );
}
```

## Realtime subscriptions

Pawabase realtime is handled through Angula's WebSocket connection. A React hook subscribes to a channel and updates component state when events arrive:

```tsx
// hooks/useRealtimeChannel.tsx
import { useEffect, useRef, useState, type ReactNode } from "react";

interface RealtimeEvent {
  event: string;
  payload: unknown;
}

export function useRealtimeChannel(channel: string, handlers: Record<string, (payload: unknown) => void>) {
  const [lastEvent, setLastEvent] = useState<RealtimeEvent | null>(null);
  const wsRef = useRef<WebSocket | null>(null);

  useEffect(() => {
    const url = `${GW.replace(/^http/, "ws")}/realtime/v1/socket?apikey=${PK}`;
    const ws = new WebSocket(url);
    wsRef.current = ws;

    ws.onopen = () => {
      ws.send(JSON.stringify({ action: "subscribe", channel }));
    };

    ws.onmessage = (event) => {
      const msg: RealtimeEvent = JSON.parse(event.data);
      setLastEvent(msg);
      const handler = handlers[msg.event];
      if (handler) handler(msg.payload);
    };

    ws.onclose = () => {
      // Reconnect after a delay
      setTimeout(() => {
        if (wsRef.current?.readyState !== WebSocket.OPEN) {
          // Re-subscribe — handled by the effect re-running when `channel` changes
        }
      }, 1000);
    };

    return () => { ws.close(); };
  }, [channel]);

  return { lastEvent };
}
```

Usage:

```tsx
function StoreDashboard({ storeId }: { storeId: string }) {
  const [orders, setOrders] = useState([]);

  useRealtimeChannel(`store:${storeId}`, {
    "order.paid": (payload) => setOrders(prev => [payload, ...prev]),
    "order.created": (payload) => setOrders(prev => [...prev, payload]),
  });

  return <OrderList orders={orders} />;
}
```

The realtime protocol (`subscribe`, `publish`, `presence`, `history`, `auth`) is documented once at [WebSocket protocol](/clients/mobile#realtime-over-websocket) — it's identical across web, mobile, and server clients.

## Optimistic updates

When a user performs an action that updates a resource, you can apply the change immediately and reconcile when the server responds:

```tsx
// hooks/useResourceUpdate.tsx
import { useMutation, useQueryClient } from "@tanstack/react-query";
import { pawabaseFetch } from "../apiClient";

export function useResourceUpdate(resource: string) {
  const queryClient = useQueryClient();

  return useMutation({
    mutationFn: (id: string) => pawabaseFetch(`/rest/v1/${resource}/${id}`, {
      method: "PATCH",
      body: JSON.stringify({ /* … */ }),
    }),
    onMutate: async (id) => {
      // Cancel outgoing refetches
      await queryClient.cancelQueries({ queryKey: ["resource", resource] });
      // Snapshot the previous value
      const previous = queryClient.getQueryData(["resource", resource]);
      // Optimistically update
      queryClient.setQueryData(["resource", resource], (old: any[]) =>
        old.map(item => item.id === id ? { ...item, status: "paid" } : item)
      );
      return { previous };
    },
    onError: (err, _, context) => {
      // Roll back on error
      queryClient.setQueryData(["resource", resource], context?.previous);
    },
    onSettled: () => {
      // Always refetch to ensure consistency
      queryClient.invalidateQueries({ queryKey: ["resource", resource] });
    },
  });
}
```

Usage:

```tsx
function ToggleOrder({ orderId }: { orderId: string }) {
  const update = useResourceUpdate("orders");

  return (
    <button onClick={() => update.mutate(orderId)} disabled={update.isPending}>
      {update.isPending ? "Updating…" : "Mark paid"}
    </button>
  );
}
```

If the server rejects the change, the mutation's `onError` rolls back to the previous state automatically — the user sees the change briefly, then it reverts.

## Forms with validation errors

When a `422` validation error comes back, the `details` array tells you exactly which fields failed:

```tsx
function OrderForm() {
  const [errors, setErrors] = useState<Record<string, string>>({});

  const handleSubmit = async (data: Record<string, unknown>) => {
    try {
      await pawabaseFetch("/rest/v1/orders", {
        method: "POST",
        body: JSON.stringify(data),
      });
    } catch (err) {
      const error = err as Error & { code: string; status: number; details?: { field: string; message: string }[] };
      if (error.status === 422 && error.details) {
        const fieldErrors: Record<string, string> = {};
        error.details.forEach(d => { fieldErrors[d.field] = d.message; });
        setErrors(fieldErrors);
      } else {
        throw err;
      }
    }
  };

  return (
    <form onSubmit={handleSubmit}>
      <input name="email" />
      {errors.email && <span className="error">{errors.email}</span>}
      <button type="submit">Create order</button>
    </form>
  );
}
```

## Security in React

| Safe to ship in your bundle | Never ship in your bundle |
| --- | --- |
| The **publishable** key | The **secret** key, in any form |
| The gateway URL | A refresh token in `localStorage` on any site with XSS risk |
| A user's own **access token** (preferably in memory) | Another user's token, ever |

Keep the access token in a module-level variable or React context rather than `localStorage` where possible. If you must use `localStorage`, be aware of the XSS trade-off. The refresh token is long-lived and is a bigger prize — prefer httpOnly cookies when your app has a server component. See [Tokens and storage](/clients/overview#tokens-and-storage).
