Common subscribe policy patterns include:
```json
{
  "subscribe_policy": {
    "eq": ["$auth.org", "store-7"]
  }
}
```

```json
{
  "subscribe_policy": {
    "in": ["$auth.roles", ["admin", "manager"]]
  }
}
```

```json
{
  "subscribe_policy": {
    "and": [
      `{"eq": ["$auth.org", "store-7"]}`,
      `{"exists": "$auth.user_id"}`
    ]
  }
}
```

### Policy Operators

| Operator | Description | Example |
| --- | --- | --- |
| eq | Equal to | `{"eq": ["$auth.org", "store-7"]}` |
| neq | Not equal to | `{"neq": ["$auth.role", "guest"]}` |
| in | In a list | `{"in": ["$auth.roles", ["admin", "manager"]]}` |
| exists | Field exists | `{"exists": "$auth.user_id"}` |
| and | Logical AND | `{"and": [cond1, cond2]}` |
| or | Logical OR | `{"or": [cond1, cond2]}` |

```json
{
  "publish_policy": {
    "in": ["$auth.roles", ["admin", "manager"]]
  }
}
```

Publish policies are typically more restrictive than subscribe policies. While many users may need to view a channel, fewer should be able to write to it.
