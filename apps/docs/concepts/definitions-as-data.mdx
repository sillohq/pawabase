Pawabase lets you design a backend from named building blocks. Studio stores and validates those choices so the same environment can expose data, authentication, automation, storage, realtime, and integrations consistently.

You do not need to edit the representation that Studio stores. Think in terms of the product behavior you are configuring.

## The pieces you will use

| You need to… | Configure… |
| --- | --- |
| Store and query durable application data | A resource with fields, operations, relations, and validation |
| Decide who may perform an operation | A policy attached to the operation |
| Accept a structured request | A schema used by a route or flow |
| Shape what a client receives | A transformer |
| Coordinate several steps | A flow |
| Run work after something happens | An event and a subscription |
| Run work later or outside the request | A queue, job, or schedule |
| Store files | A storage bucket and its access rules |
| Send or receive external events | An outbound webhook or inbound hook |
| Send reusable email | A mail template |
| Deliver live updates | A realtime channel or resource-change subscription |

## A typical product operation

Suppose a customer places an order:

```text
Resource or custom route
        ↓
Authentication + policy
        ↓
Validate and save the order
        ↓
Order-created event
   ┌────┼─────────────┐
   ↓    ↓             ↓
Flow  Realtime      Webhook
   ↓
Queue payment or fulfillment work
```

Each piece has a distinct responsibility. Keep the initial request short and observable; move slow, retryable, or externally dependent work into the appropriate asynchronous feature.

## Names and references

When Studio asks you to select a resource, policy, schema, flow, event, bucket, or template, it is connecting two backend features by name. Choose stable names that describe business intent:

- `orders` for the data;
- `customer_order_access` for the policy;
- `checkout_input` for the request shape;
- `fulfill_order` for the workflow;
- `order.created` for the event.

Avoid renaming a definition casually after other definitions depend on it. Before changing a name, search the environment's references and update dependents in the same change.

## Validation and problems

Studio validates individual settings when you save them and checks cross-feature references when the environment is compiled. A missing policy, invalid flow connection, unavailable handler, or conflicting route should appear as a configuration problem before application traffic depends on it.

When Studio reports a problem:

1. Open the problem from the environment overview.
2. Read which definition and reference failed.
3. Open the referenced feature and correct the name, field, connection, or setting.
4. Save and wait for the environment to recompile.
5. Re-run the application request that exposed the problem.

## Moving a backend between environments

Use environment promotion for a controlled move from development to staging or production. Definitions can move as a unit, while production data, credentials, sessions, and secrets remain environment-specific.

Before promoting:

- confirm policies with a test user for each role;
- migrate resource changes in the target environment;
- configure target-specific secrets and integrations;
- verify webhook destinations and realtime rules;
- check the target environment's API documentation.

See [Environments and promotion](/operate/environments-and-promotion) for the operational workflow.

## When to choose which piece

Use a resource when the main job is storing and querying records. Use a flow when the job is coordinating steps. Use an event when multiple independent consumers should react to a change. Use a queue when the work can outlive the request or needs retry isolation. Use a function or extension only when the product behavior genuinely needs code that the available Studio capabilities cannot express.

This separation keeps your backend understandable: data has a home, access has a policy, orchestration has a flow, and operational work has a visible job or event.
