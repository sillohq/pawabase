This glossary is a reference, not a tutorial. Each entry gives a precise, one-paragraph definition of a term as it is used throughout the Pawabase documentation, with links to the pages that explain it in depth. If you are new to Pawabase, start with [the mental model](/concepts/mental-model) instead — read this page when you already know roughly what a term means and want the exact definition, or when a docs page uses a word you haven't seen yet.

Terms are alphabetical. Product surfaces (Studio areas like "Build" or "Automate") are included where customers will see the word in the interface; purely internal implementation names are included only where a customer might reasonably encounter them (for example, in generated API documentation or an error message), and are marked as such.

<ResponseField name="AAL">Authentication assurance level. `aal1` describes a session established with a single factor (password, magic link, or OAuth); `aal2` describes a session that has also completed a second factor. Policies and flow conditions test it with the `aal` shorthand (`{"aal": "aal2"}`) or the built-in `mfa` policy, which requires both an authenticated session and `aal2`. See [Expressions](/concepts/expressions) and [Policies](/policies/overview).</ResponseField>

<ResponseField name="Access token">The short-lived credential a signed-in user's session presents on each request, sent as `Authorization: Bearer <token>`. It identifies the caller to authentication and, through the caller's roles, permissions, and organization membership, to every policy the request touches. Access tokens expire and are refreshed using a refresh token; they are environment-specific and must never be reused across environments. See [Credentials](/concepts/credentials) and [Tokens and sessions](/auth/tokens-and-sessions).</ResponseField>

<ResponseField name="Akountz">The identity capability behind Pawabase's authentication surface: user accounts, sessions, OAuth providers, multi-factor authentication, organizations, roles, and permissions. Customers interact with it only through the public `/auth/v1/` endpoints and Studio's **Users & auth** area — its internal name occasionally surfaces in service-level error messages or logs, but it is not a product surface you configure directly. See [Authentication overview](/auth/overview).</ResponseField>

<ResponseField name="Angula">The realtime capability behind Pawabase's live-update surface: channels, presence, message history, and the `/realtime/v1/` connection endpoint. Customers configure it through Studio's **Realtime** area and connect to it with a realtime client; its internal name is not something you reference in configuration. See [Realtime overview](/realtime/overview).</ResponseField>

<ResponseField name="API key">A credential that identifies a project environment to the gateway. A publishable key (conventionally shown with a `pb_pk_` prefix in Studio) is safe to embed in client applications; a secret key (`pb_sk_`) is not and must stay server-side. Keys can optionally carry scopes that narrow what they may do. See [Credentials](/concepts/credentials).</ResponseField>

<ResponseField name="Application boundary">The conceptual line between your product's own code — web, mobile, or server — and the Pawabase environment it calls. Everything on your side of the boundary is untrusted by the backend by default: the backend re-validates and re-authorizes every request regardless of what the client believes is true. See [Architecture](/concepts/architecture).</ResponseField>

<ResponseField name="Atlas">Pawabase's generated OpenAPI documentation UI for one environment, reachable from Studio as **API docs**. It reflects the resources, operations, and routes actually enabled in that environment, so it is the fastest way to confirm exact request and response shapes rather than guessing from the resource editor. See [Studio](/concepts/studio).</ResponseField>

<ResponseField name="Audit">The operational record of who changed what in Studio and when — resource edits, policy changes, key rotations, and promotions. Distinct from application-level request logs, which record traffic to your public API rather than changes to your configuration. See [Observability](/operate/observability).</ResponseField>

<ResponseField name="Auth (root)">In an [expression](/concepts/expressions), the root that exposes the current caller's context: `auth.user_id`, `auth.roles`, `auth.authenticated`, and similar fields. Available in policy conditions and in flow steps that run with caller context. Distinct from `credential`, which describes the API key or service credential making the call rather than the signed-in user.</ResponseField>

<ResponseField name="Authentication">The process of establishing who is calling — validating a session, token, or credential and producing the caller context (`auth`) that policies and flows read. Authentication answers "who is this?"; it never by itself answers "may they do this?". See [Authentication overview](/auth/overview) and [The mental model](/concepts/mental-model).</ResponseField>

<ResponseField name="Authorization">The process of deciding whether an already-identified caller may perform a specific operation on specific data. In Pawabase this is the job of [policies](/policies/overview), not of authentication. A caller can be authenticated and still be denied by authorization.</ResponseField>

<ResponseField name="Automation boundary">The set of Pawabase capabilities — flows, events, queues, schedules, and webhooks — that run work outside the synchronous request/response cycle. Work placed here can be retried, observed, and reasoned about independently of the request that triggered it. See [Architecture](/concepts/architecture).</ResponseField>

<ResponseField name="Blueprint">A reusable starting configuration you can apply when creating a new project, giving you a pre-built set of resources, policies, and flows instead of an empty environment. Distinct from [promotion](#promotion), which moves definitions between environments of the same project rather than seeding a new one. See [Projects and environments](/concepts/projects-and-environments).</ResponseField>

<ResponseField name="Block">One configured step inside a flow, such as `resource.create`, `control.if`, or `mail.send`. Pawabase ships 64 built-in blocks across five categories — 8 triggers, 10 control blocks, 14 data blocks, 7 resource blocks, and 25 platform blocks — and installed extensions can register more. See the [block reference](/flows/block-reference).</ResponseField>

<ResponseField name="Branch">A named outcome a block can produce, used to wire different next steps to different results — for example `control.if`'s `true`/`false` branches, or `resource.get`'s `next`/`missing` branches. Most blocks have a single `next` branch; any block can additionally have an `error` branch. See [Control flow](/flows/control-flow) and [Errors and retries](/flows/errors-and-retries).</ResponseField>

<ResponseField name="Bucket">A named storage area you configure with read/write policies, accepted content types, and a maximum object size. Files uploaded to a bucket are addressed by a key within it, and access to each object is decided by the bucket's policy at request time, not by the obscurity of the key. See [Storage overview](/storage/overview).</ResponseField>

<ResponseField name="Caller context">The combined set of facts a policy or flow condition can read about who is making a request: `auth` (the signed-in user, if any), `credential` (the API key or service credential), and where relevant `record` and `input`. See [Policy context](/policies/context) and [Expressions](/concepts/expressions).</ResponseField>

<ResponseField name="Channel">A realtime topic, such as `chat:lobby` or `resource:notes`, that clients subscribe to and publish on. A channel's behavior — who may subscribe, who may publish, whether presence and history are recorded — is governed by the channel rule matching its name, not by the channel itself. See [Realtime overview](/realtime/overview).</ResponseField>

<ResponseField name="Channel rule">A pattern (for example `chat:*`) plus subscribe and publish policies, and presence/history settings, applied to every channel matching that pattern. Channel rules are how you avoid configuring access per individual channel name. See [Realtime overview](/realtime/overview).</ResponseField>

<ResponseField name="Client">Your web, mobile, or server application code that calls a Pawabase environment. Pawabase documents official client patterns for JavaScript, React, Python, and mobile; a client can also be a plain HTTP caller such as `curl` or another backend service. See [Client integration](/clients/overview).</ResponseField>

<ResponseField name="Collection">Used loosely in this documentation to mean the set of records belonging to one resource — for example, "the `orders` collection." Pawabase's configuration term for the thing that defines that data is [resource](#resource); "collection" describes the data, "resource" describes its definition.</ResponseField>

<ResponseField name="Compiled application">The running backend Pawabase generates for one environment from its stored definitions — resources, policies, flows, and the rest. You never edit the compiled form directly; you change definitions in Studio and Pawabase recompiles. See [Definitions as data](/concepts/definitions-as-data).</ResponseField>

<ResponseField name="Condition">A structured expression — combinators, comparisons, presence checks, and shorthands — used to decide `true`/`false` in a policy, a `control.if`/`control.while` block, `transform.filter`, or `policy.check`. Conditions are one of the two forms of [expression](#expression); the other is a template. See [Expressions](/concepts/expressions).</ResponseField>

<ResponseField name="Context (platform)">The verified identity of a request — its project, environment, key, role, and scopes — that the gateway establishes before the request reaches any resource, route, or flow. Everything downstream trusts this context rather than re-deriving it. Distinct from `auth`, which specifically describes the signed-in user, if any. See [Architecture](/concepts/architecture).</ResponseField>

<ResponseField name="Credential">Any value that identifies a caller or an environment to Pawabase: a publishable key, a secret key, a user access token, a Studio session, or a webhook secret. See [Credentials and trust boundaries](/concepts/credentials).</ResponseField>

<ResponseField name="Custom route">A public endpoint you define under `/rest/v1/` that is handled by a flow (or, in code-extension deployments, by project code) rather than generated automatically from a resource. Use it for a business operation that doesn't map cleanly to a single record's CRUD, such as checkout or a report export. See [Routes](/flows/overview).</ResponseField>

<ResponseField name="Definition">Any stored configuration describing one part of a backend — a resource, a policy, a flow, a schema, a transformer, and so on. Definitions are what Studio edits and validates; see [Definitions as data](/concepts/definitions-as-data).</ResponseField>

<ResponseField name="Environment">An isolated runtime of a project with its own data, users, keys, secrets, integrations, storage, and realtime activity. Typical environments are `development`, `staging`, and `production`; definitions can be promoted between them, but data, credentials, and sessions never move automatically. See [Projects and environments](/concepts/projects-and-environments).</ResponseField>

<ResponseField name="Error branch">An optional branch you can wire on any flow block, taken when that step raises an error instead of completing normally. Distinct from a block's declared branches (like `true`/`false`), which represent normal outcomes. See [Errors and retries](/flows/errors-and-retries).</ResponseField>

<ResponseField name="Event">A named fact that something happened in the backend, such as `order.created`, with a payload describing it. Events are recorded and fanned out to every matching subscription, so several independent consumers can react to the same change without knowing about each other. See [Events overview](/events/overview).</ResponseField>

<ResponseField name="Expand">A request-time option (`?expand=relation`) on a resource operation that includes related records in the response instead of requiring a second request. Governed by the same policies as the relation it expands — a caller cannot expand their way past a permission they don't have. See [Resources](/data/resources).</ResponseField>

<ResponseField name="Expression">A value entered in a Studio field that is evaluated at request or flow-run time instead of being treated as a fixed literal. Expressions take two forms: a `$path` for when the field needs the value itself (used in conditions), and a `{{ }}` template for building text. See [Expressions and references](/concepts/expressions).</ResponseField>

<ResponseField name="Extension route">A route implemented directly in project code rather than through a flow, used only in self-hosted, code-extension deployments where the platform's built-in blocks genuinely cannot express the behavior needed. Most Pawabase backends need none of these. See [Flows overview](/flows/overview).</ResponseField>

<ResponseField name="Filter (template)">A transformation applied to a value inside a `{{ }}` template with the `|` syntax, such as `default`, `upper`, `lower`, `json`, `length`, `int`, `float`, `str`, `bool`, `first`, `last`, and `keys`. See [Expressions](/concepts/expressions).</ResponseField>

<ResponseField name="Flow">A configurable, multi-step backend process: a trigger starts it, blocks read input, branch, call services, and produce a result. Flows are how Pawabase expresses behavior with more than one meaningful step — validation followed by a side effect, a retextryable external call, a scheduled job. See [Flows overview](/flows/overview).</ResponseField>

<ResponseField name="Flow run">One execution of a flow, with its own input, step outputs, variables, and final outcome, visible in Studio's execution trace. Distinct from the flow definition itself, which is reused across many runs. See [Observability](/operate/observability).</ResponseField>

<ResponseField name="Function">Project-level code registered to run as part of a flow (`function.call`) or as a background job (`queue.function`), used when a behavior genuinely needs general-purpose code that the built-in blocks cannot express. See [Platform blocks](/flows/platform-blocks).</ResponseField>

<ResponseField name="Gateway">The single public entry point for every application request to a Pawabase environment. The gateway identifies the project and environment from the request, resolves the API key, and forwards the request to the capability that owns it (authentication, data, storage, flows, or realtime) behind one stable origin. See [Architecture](/concepts/architecture).</ResponseField>

<ResponseField name="Idempotency">A property of an operation that lets it be safely repeated — for example, retried after a timeout — without causing a duplicate effect, such as charging a customer twice. Designing idempotency explicitly (an idempotency key, a status check before acting) matters most in flows that call external systems. See [The request lifecycle](/concepts/request-lifecycle).</ResponseField>

<ResponseField name="Inbound hook">A public, verified URL that turns a third-party webhook delivery into a Pawabase event or a flow run. Distinct from an outbound webhook, which is Pawabase notifying an external system. See [Inbound webhooks](/webhooks/inbound).</ResponseField>

<ResponseField name="Item / Index">In a `control.foreach` step, `item` is the current element being processed and `index` is its position in the list, both available to expressions inside that branch. See [Expressions](/concepts/expressions).</ResponseField>

<ResponseField name="Job">One unit of asynchronous work placed on a queue, such as one flow run dispatched by `queue.flow` or one function call dispatched by `queue.function`. Jobs have their own retry and failure state, inspectable in Studio, independent of the request that enqueued them. See [Queues and jobs](/jobs/queues).</ResponseField>

<ResponseField name="Migration">The process of applying a resource's field or relation changes to its underlying data. Studio prompts for a migration when a resource change affects existing records, and some changes — a new required field, a renamed field — need an explicit backfill or compatibility plan. See [Migrations](/data/migrations).</ResponseField>

<ResponseField name="Operation">One of the actions a resource exposes — list, get, create, update, or delete — each independently enabled and independently protected by its own policy. See [Resources](/data/resources).</ResponseField>

<ResponseField name="Operator">A person who uses Studio to configure and run a backend, as distinct from an end user of the application built on it. Operator accounts should use strong authentication and least-privilege roles; they are never a credential your application's users hold. See [Credentials](/concepts/credentials).</ResponseField>

<ResponseField name="Organization">A grouping of users under one authentication context, used to model multi-tenant products — a company, team, or workspace whose members share access to certain records. Policies commonly combine organization membership with role or ownership checks. See [Authentication overview](/auth/overview).</ResponseField>

<ResponseField name="Owner field">A resource field, typically `owner_id`, that Pawabase sets to the caller's user id on create rather than trusting a client-supplied value. The built-in `owner` policy checks this field against the caller's identity. See [Policies overview](/policies/overview).</ResponseField>

<ResponseField name="Permission">A named capability a role can be granted, such as `posts.write`, checked with the `permission` shorthand in a condition. Distinct from a [role](#role), which is the named bundle of permissions actually assigned to a user.</ResponseField>

<ResponseField name="Policy">A named, reusable condition that decides whether an operation may proceed, attached to a resource operation, a custom route, a storage bucket, or a realtime channel rule. Built-in policies include `public`, `deny`, `authenticated`, `service`, `owner`, and `mfa`. See [Policies overview](/policies/overview).</ResponseField>

<ResponseField name="Project">The top-level boundary grouping the backend definitions, credentials, and environments for one product or system. A project is not itself an environment, a database, or a deployment — it is the container that holds them. See [Projects and environments](/concepts/projects-and-environments).</ResponseField>

<ResponseField name="Project reference">The stable, URL-safe identifier chosen when a project is created, used in environment URLs and client configuration. It should not encode a temporary customer, branch, or developer name, because renaming it later breaks existing integrations. See [Projects and environments](/concepts/projects-and-environments).</ResponseField>

<ResponseField name="Promotion">The controlled process of copying definitions — resources, policies, flows, schemas, transformers — from one environment to another, typically development to staging to production. Application data, credentials, sessions, and secrets are always environment-specific and are never moved by promotion. See [Projects and environments](/concepts/projects-and-environments).</ResponseField>

<ResponseField name="Publishable key">An API key meant to be present in a browser or mobile application. It identifies which environment a request targets; it is not itself an authorization decision, which is why policies must still be configured correctly even though the key is public. See [Credentials](/concepts/credentials).</ResponseField>

<ResponseField name="Pushdown">The technique Pawabase uses to turn certain policy conditions on record fields — equalities between a record column and a known value — into database `WHERE` clauses for list operations, so filtering happens in the database rather than after every row is fetched. A condition that can't be pushed down (for example, one that depends on the request body) is instead checked per row after the query runs. See [Policies overview](/policies/overview).</ResponseField>

<ResponseField name="Queue">A named channel of asynchronous work that jobs are placed on and workers process, used to move slow, retryable, or externally-dependent work out of the request path. See [Queues and jobs](/jobs/queues).</ResponseField>

<ResponseField name="Realtime">The Pawabase capability for delivering live updates to connected applications over channels, with authentication and channel rules deciding who may subscribe, publish, or see presence and history. See [Realtime overview](/realtime/overview).</ResponseField>

<ResponseField name="Record">One row of data belonging to a resource — a single customer, order, or message. Records are what resource operations read and write, and what policies and pushdown filters ultimately decide access to.</ResponseField>

<ResponseField name="Refresh token">A longer-lived credential paired with an access token, used to obtain a new access token without asking the user to sign in again. Refresh tokens should be handled by the supported client integration rather than manually, and are as sensitive as the session they extend. See [Credentials](/concepts/credentials).</ResponseField>

<ResponseField name="Resource">The configured definition of a kind of application data — its fields, validation, relations, response shaping, and which operations (list, get, create, update, delete) are enabled and under what policy. A resource is the primary way Pawabase turns a data model into a public API. See [Resources](/data/resources).</ResponseField>

<ResponseField name="Role">A named bundle of permissions assigned to a user, checked with the `role` shorthand in a condition (`{"role": "admin"}`). Roles are how Pawabase expresses coarse-grained authorization without writing a bespoke condition for every operation. See [Authentication overview](/auth/overview).</ResponseField>

<ResponseField name="Route">A public path an application can call. A route can be generated automatically from a resource's enabled operations, or defined explicitly as a custom route backed by a flow. See [Architecture](/concepts/architecture).</ResponseField>

<ResponseField name="Schedule">A rule that starts a flow or event at a fixed interval or according to a cron expression, used for periodic work such as nightly reconciliation or subscription renewal reminders. See [Flows overview](/flows/overview) and the `trigger.schedule` block in the [block reference](/flows/block-reference).</ResponseField>

<ResponseField name="Schema">A reusable, named field definition used to validate structured input for a route or a flow step (`validate.schema`), independent of any one resource. See [Definitions as data](/concepts/definitions-as-data).</ResponseField>

<ResponseField name="Scope (API key)">An optional restriction on what an API key may do, narrower than the full access implied by its type — for example, a key scoped to read-only reporting rather than full read/write access. Checked with the `scope` shorthand in a condition. See [Credentials](/concepts/credentials).</ResponseField>

<ResponseField name="Secret">An encrypted, per-environment value — a provider API key, a signing secret, a connection string — referenced from configuration rather than typed inline, so it never appears in a stored definition or a Studio screenshot. See [Credentials](/concepts/credentials).</ResponseField>

<ResponseField name="Secret key">An API key meant only for a trusted server or private integration, with elevated access. It must never be sent to a browser, embedded in a mobile bundle, or logged. See [Credentials](/concepts/credentials).</ResponseField>

<ResponseField name="Service credential">A credential — a secret key, an operator session, or an internal service call — that is treated as trusted and bypasses ordinary policy checks. Service credentials are how your own trusted servers, Studio, and resource blocks inside flows can read and write data without re-running every policy. See [Policies overview](/policies/overview).</ResponseField>

<ResponseField name="Session (user)">The state created when a user signs in, consisting of an access token and usually a refresh token, scoped to one environment. See [Access token](#access-token) and [Tokens and sessions](/auth/tokens-and-sessions).</ResponseField>

<ResponseField name="Session (Studio)">The credential identifying a signed-in operator inside Studio. It is never a credential your application should hold or automate against. See [Credentials](/concepts/credentials).</ResponseField>

<ResponseField name="Shorthand">A named condition operator that expands to a common combination of comparisons, used to keep policies and flow conditions readable. The built-in shorthands are `authenticated`, `role`, `permission`, `owner`, `service`, `kind`, `scope`, and `aal`. See [Expressions](/concepts/expressions).</ResponseField>

<ResponseField name="Step">One configured occurrence of a block inside a specific flow, with its own id and output, referenced from later steps as `steps.<id>.output`. Distinct from "block," which names the kind of step (its behavior), not a particular placement of it in a flow. See [Expressions](/concepts/expressions).</ResponseField>

<ResponseField name="Storage">The Pawabase capability for storing and serving files — images, documents, exports — organized into buckets with their own access policies. See [Storage overview](/storage/overview).</ResponseField>

<ResponseField name="Studio">The customer-facing control-plane interface for configuring, inspecting, and operating a Pawabase backend: resources, policies, flows, authentication, storage, realtime, integrations, and operational views. See [Pawabase Studio](/concepts/studio).</ResponseField>

<ResponseField name="Subscription">A rule connecting an event to a consumer — a flow, a function, an outbound webhook, or a realtime channel — so that when the event fires, the consumer runs or is notified. See [Events overview](/events/overview).</ResponseField>

<ResponseField name="Template">A `{{ }}` field that builds a text (or, when the whole field is one expression, a typed) value from paths and filters, evaluated at run time. The other expression form is a condition. See [Expressions](/concepts/expressions).</ResponseField>

<ResponseField name="Transformer">A declarative rule for reshaping a response before it reaches the caller — omitting fields, picking fields, setting a value, renaming a key, or changing case — used to give different consumers different views of the same underlying data. See [Definitions as data](/concepts/definitions-as-data).</ResponseField>

<ResponseField name="Trigger">The block that starts a flow and determines the shape of its initial input — an HTTP request, an event, a schedule, a resource change, a webhook, a realtime message, a job dispatch, or a manual run. Every flow needs at least one. See [Triggers](/flows/triggers).</ResponseField>

<ResponseField name="Variable (flow)">A named value set during a flow run with the **Set variables** step and read elsewhere in that same run as `vars.<name>`. Variables exist only for the lifetime of one run; they are not a database and are not shared across runs or requests. See [Expressions](/concepts/expressions).</ResponseField>

<ResponseField name="Version">The counter on an environment's definitions that increments with every configuration change, used by Studio to track what has changed and to detect a stale view. See [Definitions as data](/concepts/definitions-as-data).</ResponseField>

<ResponseField name="Webhook (inbound)">See [Inbound hook](#inbound-hook).</ResponseField>

<ResponseField name="Webhook (outbound)">A signed HTTP request Pawabase sends to an external system when a subscribed event fires, used to notify partners, warehouses, or other services outside the platform. See [Outbound webhooks](/webhooks/outbound).</ResponseField>

<ResponseField name="Webhook signature">A cryptographic signature attached to a webhook delivery — inbound or outbound — that lets the receiver verify the payload genuinely came from the claimed sender and was not tampered with in transit. See [Webhook signatures](/webhooks/signatures).</ResponseField>
