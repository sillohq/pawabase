---
title: "API Explorer"
description: "Browse and call every endpoint generated for an active API version from Studio."
---

Open **Studio → API Explorer** inside a project environment. The explorer reads the active release's OpenAPI document, so its endpoint list, parameters, request schemas, and paths match what `/rest/v1`, `/rest/v2`, or another selected version currently serves.

Select an endpoint, fill its path and query parameters, edit the generated JSON body, and choose **Send request**. The response panel shows the HTTP status, duration, selected response headers, and parsed body.

## Authentication

You do not need to paste a project API key. Studio creates a short-lived, signed anonymous project context for each request. This context identifies the project and environment but does not bypass policies.

- Public endpoints work with the token field empty.
- Endpoints protected by `authenticated`, user roles, ownership, or permissions need an Akountz project user. Sign in with that user's email and password directly in the explorer, including MFA when enabled.
- You can alternatively paste an existing project-user access token under **Use an existing access token**.
- The token remains in page memory and is not saved by Studio.

Secret project keys and operator privileges are deliberately unavailable in the explorer. This means its result accurately represents an anonymous or signed-in application user instead of silently succeeding with administrative access.

Explorer calls are real data-plane requests. Writes modify the environment database and trigger the same validation, policies, events, flows, realtime publications, request logs, and observability traces as calls made through the gateway.
