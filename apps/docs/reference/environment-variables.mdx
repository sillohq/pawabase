Pawabase's configuration is entirely environment-variable-driven. Every service reads its settings from the `PAWABASE_*` environment variables, loaded from the `.env` file that `docker-compose.yml` provides to every container. There is no configuration file on disk, no JSON config blobs in a database, and no command-line flags to pass at runtime.

## How configuration works

Every service subclass `PlatformSettings` (in `pawabase_kit.settings`), which has `Env.env_prefix = "PAWABASE_"`. This means any field named `database_url` maps to `PAWABASE_DATABASE_URL`, any field named `redis_url` maps to `PAWABASE_REDIS_URL`, and so on. The `sillo.config.Config` class handles reading from environment variables and `.env` files automatically.

```python
class PlatformSettings(Config):
    class Env:
        env_prefix = "PAWABASE_"
    
    database_url: str = "sqlite://storage/api.db"
    redis_url: str = ""
```

This means `PAWABASE_DATABASE_URL=postgres://...` in your `.env` file automatically sets `settings.database_url` to the Postgres connection string.

## Required secrets

These variables **must** be set before `docker compose up` will succeed:

| Variable | Default | Description |
| --- | --- | --- |
| `PAWABASE_INTERNAL_SECRET` | — | Signs service-to-service tokens and the gateway's platform context header. Must be identical in every container. Generate with `openssl rand -hex 32`. |
| `PAWABASE_JWT_MASTER_SECRET` | — | Master key from which per-environment user token signing keys are derived: `HMAC(master_key, "<project>:<env>")`. Must be 32+ characters. |
| `PAWABASE_MASTER_KEY` | — | Encrypts environment secrets and webhook signing keys at rest in the database. Must be 32+ characters. |
| `POSTGRES_PASSWORD` | — | Postgres superuser password. Required by `docker-compose.yml` with explicit validation. |
| `PAWABASE_ADMIN_EMAIL` | — | Email of the first platform operator. Creates the `_platform` project operator on first start. |
| `PAWABASE_ADMIN_PASSWORD` | — | Password for the initial operator account. Must have upper/lowercase letters, a digit, and a symbol. |

<Warning>
All three master secrets (`INTERNAL_SECRET`, `JWT_MASTER_SECRET`, `MASTER_KEY`) are generated once and never change unless you deliberately rotate them. They are the root of trust for the entire platform. If any is compromised, the blast radius is the entire installation. Generate them with `openssl rand -hex 32` and store them in a secrets manager.
</Warning>

## Platform settings

These variables are read by every service:

| Variable | Default | Description |
| --- | --- | --- |
| `PAWABASE_SERVICE_NAME` | `pawabase` | Service name in tokens and telemetry |
| `PAWABASE_APP_ENV` | `production` | Application environment: `local`, `testing`, `staging`, or `production` |
| `PAWABASE_DEBUG` | `false` | Sillo debug mode — shows stack traces in errors when true |
| `PAWABASE_INTERNAL_SECRET` | `dev-internal-secret-change-me-please` | **Required in production** — service-to-service token signing |
| `PAWABASE_JWT_MASTER_SECRET` | `dev-jwt-master-secret-change-me-please` | **Required in production** — JWT master secret |
| `PAWABASE_MASTER_KEY` | `dev-master-key-change-me-please-32bytes` | **Required in production** — encryption key for secrets |
| `PAWABASE_API_URL` | `http://127.0.0.1:8001` | Internal URL of the API service |
| `PAWABASE_AKOUNTZ_URL` | `http://127.0.0.1:8002` | Internal URL of the Akountz identity service |
| `PAWABASE_ANGULA_URL` | `http://127.0.0.1:8003` | Internal URL of the Angula realtime service |
| `PAWABASE_GATEWAY_URL` | `http://127.0.0.1:8080` | Internal URL of the gateway |
| `PAWABASE_STUDIO_URL` | `http://127.0.0.1:8090` | Internal URL of the Studio control plane |
| `PAWABASE_REDIS_URL` | `""` (empty) | Redis URL for events, cache, and queues. Empty means in-process fallbacks. |
| `PAWABASE_CORS_ORIGINS` | `http://localhost:8090,http://127.0.0.1:8090` | Comma-separated origins allowed by gateway and Studio |

## Gateway settings

Read by the gateway service (`python -m app.main` with `gateway` entrypoint):

| --- | --- | --- |

| `PAWABASE_RATE_LIMIT` | `600` | Requests per window per key or client address |
| `PAWABASE_RATE_WINDOW` | `60` | Rate limit window in seconds |
| `PAWABASE_MAX_BODY_BYTES` | `100485760` (100 MB) | Largest request body forwarded (uploads included) |
| `PAWABASE_UPSTREAM_TIMEOUT` | `60.0` | Seconds to wait for an upstream response |
| `PAWABASE_KEY_CACHE_TTL` | `30` | Seconds a resolved API key is cached |
| `PAWABASE_CORS_ORIGINS` | `*` | Gateway CORS origins (default `*` for backend-as-a-service) |

## API settings

Read by the API service:

| Variable | Default | Description |
| --- | --- | --- |
| `PAWABASE_API_PORT` | `8001` | Port the API listens on |
| `PAWABASE_DATABASE_URL` | `sqlite://storage/api.db` | Platform database connection string |

| `PAWABASE_STORAGE_ROOT` | `storage/objects` | Default local storage root for environments |
| `PAWABASE_CODE_PATH` | `code` | Directory where project code (functions, routes, policies) is mounted |
| `PAWABASE_PUBLIC_URL` | `http://127.0.0.1:8080` | Gateway's public origin, used in signed URLs and docs |
| `PAWABASE_INLINE_WORKER` | `true` (dev), `false` (compose) | Run a queue worker inside the API process |

| `PAWABASE_QUEUE_PREFIX` | `pawabase:queue:` | Redis key prefix for queue names |
| `PAWABASE_MAX_UPLOAD_BYTES` | `52428800` (50 MB) | Maximum upload size in bytes |
| `PAWABASE_QUERY_TIMEOUT` | `15.0` | Timeout for `db.query` operations in seconds |
| `PAWABASE_WORKER_CONCURRENCY` | `4` | Number of concurrent jobs per worker process |
| `PAWABASE_WORKER_QUEUES` | `""` | Comma-separated list of additional queues beyond the platform defaults |

## Worker settings

Read by the worker process (`python -m app.worker`):

| Variable | Default | Description |
| --- | --- | --- |
| `PAWABASE_WORKER_CONCURRENCY` | `4` | Number of concurrent jobs the worker processes |
| `PAWABASE_WORKER_QUEUES` | `""` | Additional queues to listen on, beyond `events`, `webhooks`, `flows`, `functions`, `mail`, `default` |

The platform queues are always listened on, regardless of `PAWABASE_WORKER_QUEUES`:
- `events` — event fan-out and processing
- `webhooks` — outbound webhook deliveries
- `flows` — flow executions triggered by events or schedules
- `functions` — Python function invocations
- `mail` — email sending
- `default` — catch-all queue

## Development configuration

When using `scripts/dev.sh`, the script sets additional variables:

```bash
export PAWABASE_APP_ENV="${PAWABASE_APP_ENV:-local}"
export PAWABASE_INTERNAL_SECRET="${PAWABASE_INTERNAL_SECRET:-dev-internal-secret-change-me-please}"
export PAWABASE_JWT_MASTER_SECRET="${PAWABASE_JWT_MASTER_SECRET:-dev-jwt-master-secret-change-me-please}"
export PAWABASE_MASTER_KEY="${PAWABASE_MASTER_KEY:-dev-master-key-change-me-please-0000}"
export PAWABASE_DB_GENERATE_SCHEMAS=true
export PAWABASE_PUBLIC_URL="http://127.0.0.1:8080"
export PAWABASE_PUBLIC_GATEWAY_URL="http://127.0.0.1:8080"
export PAWABASE_ADMIN_EMAIL="${PAWABASE_ADMIN_EMAIL:-admin@pawabase.local}"
export PAWABASE_ADMIN_PASSWORD="${PAWABASE_ADMIN_PASSWORD:-Pawabase!admin1}"
export PAWABASE_INLINE_SCHEDULER=true
```

<Warning>
The development defaults use placeholder secrets (`dev-internal-secret-change-me-please`, etc.) that are printed in the script itself. If you run `scripts/dev.sh` on a host accessible to other people, change these immediately. For any shared development environment, set `PAWABASE_INTERNAL_SECRET`, `PAWABASE_JWT_MASTER_SECRET`, and `PAWABASE_MASTER_KEY` before running the script.
</Warning>
