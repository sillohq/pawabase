Every project environment can have its own infrastructure settings. These are configured per environment in Studio and are accessible to your code and flows at runtime. Settings control how your environment connects to databases, storage, mail, and custom services.

## What are environment settings?

Each environment in a project can have its own `settings` object. Settings are stored as a JSON object in the environment record and are accessible at runtime via `EnvironmentState.settings`. They cover two categories:

1. **Infra settings** — `infra` field, controlling databases, storage, mail, and other platform infrastructure
2. **Custom settings** — `settings` field, arbitrary key-value pairs for your application logic

The `infra` settings are resolved by the platform before being passed to your code. This means `secret://NAME` references are automatically replaced with the actual secret values from the environment's secret store.

## Infra settings

The `infra` field is a dictionary of infrastructure configuration keys:

```json
{
  "infra": {
    "database_url": "postgres://user:pass@host:5432/mydb",
    "storage": { "bucket": "my-bucket", "driver": "s3" },
    "mail": { "host": "smtp.example.com", "port": 587, "from": "no-reply@example.com" },
    "redis_url": "redis://localhost:6379/0"
  }
}
```

### `database_url`

The connection string for this environment's project data database. If not set, the environment falls back to `PAWABASE_DEFAULT_DATA_URL` (default: `sqlite:///data/envs/{project}__{env}.db`). The `{project}` and `{env}` placeholders are substituted at runtime.

```python
# In code, resolve the database URL
url = state.database_url()  # Uses infra.database_url or falls back to default
```

When `database_url` contains `secret://NAME`, the platform resolves it:

```python
# infra.database_url = "postgres://user:${DB_PASSWORD}@host:5432/mydb"
# The platform resolves ${DB_PASSWORD} from the secret store
url = state.database_url()  # "postgres://user:actualpassword@host:5432/mydb"
```

### `storage`

Configure the object storage backend for this environment:

```json
{
  "infra": {
    "storage": {
      "driver": "s3",
      "bucket": "my-project-assets",
      "region": "us-east-1",
      "endpoint": "https://s3.example.com"
    }
  }
}
```

| Field | Description |
| --- | --- |
| `driver` | Storage driver (`"s3"` or `"local"`) |
| `bucket` | Default bucket name |
| `region` | AWS region or equivalent |
| `endpoint` | Custom endpoint URL (for S3-compatible providers) |

If `storage` is not configured, files are stored locally under `PAWABASE_STORAGE_ROOT`.

### `mail`

Configure the SMTP service for outbound email:

```json
{
  "infra": {
    "mail": {
      "host": "smtp.sendgrid.net",
      "port": 587,
      "use_tls": true,
      "username": "apikey",
      "password": "SG.xxx",
      "from": "no-reply@myapp.com",
      "reply_to": "support@myapp.com",
      "suppress": false
    }
  }
}
```

The `MailManager._config()` method reads these settings and constructs a `MailConfig` object. Key behavior:

- If `host` is not set, `suppress_send` is automatically `true` and messages are logged but not sent
- `use_ssl` defaults to `true` when port is `465`, `false` otherwise
- `use_tls` defaults to `true` when port is `587`, `false` otherwise
- The `default_from` falls back to `no-reply@{project_ref}.pawabase.local` if not set
- The `password` field can use `secret://NAME` references

### `redis_url`

Optional Redis URL for caching and pub/sub. If not set, the platform uses an in-memory cache. The Redis URL is used by the event bus, the cache, and the queue connection.

## Custom settings

The `settings` field is a dictionary of arbitrary key-value pairs for your application:

```json
{
  "settings": {
    "app_name": "My School",
    "max_students_per_class": 30,
    "feature_flags": { "new_grading_system": true, "analytics_v2": false },
    "email_templates": { "welcome": "welcome-v2", "reminder": "reminder-v3" }
  }
}
```

Custom settings are accessed at runtime:

```python
settings = state.settings  # {"app_name": "My School", ...}
app_name = settings.get("app_name", "Default App")
```

Settings can also be resolved using `platform.resolve_value()`:

```python
value = platform.resolve_value(state, settings["api_key"])
# If api_key is "secret://API_KEY", this returns the actual secret value
```

## Accessing settings at runtime

### In functions

```python
from pawabase import function
from app.platform import get_platform

@function("get-config")
def get_config(ctx):
    platform = get_platform()
    state = await platform.state(ctx.project, ctx.env)
    return {
        "infra": state.infra,
        "settings": state.settings,
        "database_url": state.database_url(),
    }
```

### In flows

Use `resource.get` or `db.query` to access settings, or use a Python function called via `function.call`:

```json
{
  "id": "get-settings",
  "nodes": [
    {
      "id": "start",
      "data": {
        "block": "function.call",
        "config": { "function": "get-config" }
      }
    }
  ]
}
```

### In event processors

The `EventProcessor` has access to `EnvironmentState` for every event, giving it access to `state.infra`, `state.settings`, `state.database_url()`, and `state.mail_templates`.

## Setting settings programmatically

Settings can be set via the platform API or through the `Environment` model directly. In a flow, you can use the `control.if` block with `resource.update` to modify settings:

```json
{
  "id": "update-config",
  "nodes": [
    {
      "id": "start",
      "data": { "block": "resource.update", "config": { "resource": "environment_settings", "data": { ... } }}
    }
  ]
}
```

For programmatic updates, use the management API:

```python
await platform.envs.update_settings(project_ref, env_name, {
    "infra": { "mail": { "host": "smtp.new.com" } },
    "settings": { "feature_flags": { "new_ui": true } }
})
```

## Settings inheritance

Settings are not inherited across environments — each environment has its own independent `infra` and `settings` objects. However, you can use the platform's promotion feature to copy settings from one environment to another:

1. In Studio, go to **Environments → Promote**
2. Select the source and target environments
3. Choose which definition types to promote (including settings)
4. The promotion creates the same settings in the target environment

## Environment settings reference table

| Setting | Type | Default | Description |
| --- | --- | --- | --- |
| `infra.database_url` | string | `{PAWABASE_DEFAULT_DATA_URL}` | Project data database connection string |
| `infra.storage` | object | Local storage | Object storage configuration |
| `infra.mail` | object | Suppressed | SMTP configuration |
| `infra.redis_url` | string | Empty (in-memory) | Redis URL for caching and pub/sub |
| `settings.*` | any | `{}` | Custom application settings |

<Warning>
Changes to `infra.database_url` take effect immediately for new connections but do not affect existing connections. If you change the database URL, existing connections in the connection pool will continue using the old URL until they are closed. The `DataSourcePool` manages connections per `(project, env)` pair and opens them lazily on first use.
</Warning>
