## Version 0.20.0 — 2026-09-28

### Added

- Mail templates: Jinja2 template rendering in a sandboxed environment, with subject, HTML, and plain-text parts
- `MailManager.render()` method for previewing templates without sending
- `SendMailJob` with 3 retries and 5-second backoff
- `MailLog` model for tracking all email deliveries with status tracking
- `suppress_send` configuration option for development environments

### Changed

- `platform.mail.send()` now queues a `SendMailJob` instead of sending inline
- Template rendering now uses `SandboxedEnvironment` with `autoescape=True`
- Mail configuration moved to `infra.mail` settings in the environment configuration

### Fixed

- Race condition in `EventProcessor.handle()` where duplicate events could be processed under at-least-once delivery
- `WebhookDelivery` now correctly records `duration_ms` for both successful and failed deliveries
- Scheduler reconciliation no longer duplicates jobs when `Schedule` rows are updated during reconciliation

## Version 0.19.0 — 2026-09-15

### Added

- `PlatformScheduler` class with `desired()`, `reconcile()`, and `fire()` methods
- `trigger.schedule` node in flows for cron and interval-based scheduling
- `RunFlowJob` and `RunFunctionJob` job classes for scheduled flow/function execution
- Scheduler heartbeat tracking via `WorkerHeartbeat` with `kind: "scheduler"`
- `SchedulerManager` integration for in-memory job scheduling

### Changed

- Scheduler now reconciles every 15 seconds (`RECONCILE_SECONDS`) instead of every 30 seconds
- Schedule firing now emits events directly via `platform.bus.emit()` for `target_type: "event"` schedules
- `Schedule.last_run_at`, `last_status`, and `run_count` fields now tracked on every firing

### Fixed

- Scheduler would register duplicate jobs if `Schedule` changed during reconciliation — now uses a `_registered` dict keyed by a composite spec key
- `fire()` now catches exceptions and records `last_status: "failed"` on the schedule row

## Version 0.18.0 — 2026-08-28

### Added

- Standalone worker process (`python -m app.worker`) with `QueueWorker` integration
- `InlineWorker` class for single-process development setups
- `WorkerHeartbeat` model with `processed`, `concurrency`, and `status` fields
- `PAWABASE_WORKER_CONCURRENCY` environment variable to control worker concurrency
- `PAWABASE_WORKER_QUEUES` environment variable to add custom queues
- `RecordFailedJobRepository` for persisting failed jobs in the platform database
- Heartbeat loop in the standalone worker process (every 10 seconds)

### Changed

- `build_worker()` now uses `ConnectionManager` and `WorkerOptions` from Sillo
- Worker now registers signal handlers (`SIGINT`, `SIGTERM`) for graceful shutdown
- `InlineWorker` sets `_register_signals = lambda: None` since signals belong to the server

### Fixed

- Worker would crash if `app.jobs` import failed — now imports with `# noqa: F401` comment
- Heartbeat `upsert` now correctly updates `last_seen` on every iteration

## Version 0.17.0 — 2026-08-10

### Added

- `EventProcessor` class for consuming platform events and routing to consumers
- `flow_event_entries()` helper for finding flow subscribers by `trigger.event` and `trigger.resource`
- `webhooks.endpoint_matches()` and `webhooks.queue_deliveries()` for outbound webhook routing
- `EventLog` model for recording every emitted event
- `EventLog.consumers` field for tracking which consumers processed each event
- `platform.emit()` method for emitting events with actor and request_id context
- `fnmatch.fnmatchcase` for event name pattern matching (case-sensitive)

### Changed

- Event routing now goes through `EventProcessor.handle()` → `EventProcessor.route()` pipeline
- Consumers are queued as jobs rather than executed inline — slow consumers no longer delay others
- `EventSubscription` now supports conditions via `matches_condition()`
- `EventLog` records `source` and `actor` fields for audit trail

### Fixed

- Events for unknown environments were silently dropped — now logged as warnings
- `EventProcessor` now checks `EventLog.filter(event_id=event.id).exists()` for at-least-once delivery before processing

## Version 0.16.0 — 2026-07-20

### Added

- `DataPlaneDispatcher` for serving per-environment compiled Sillo apps under `/rest/v1`
- `FORWARDED_KEYS` constant for copying scope keys between inner and outer apps
- `RequestRollup` for tracking request metrics per environment
- `Platform` class as the central long-lived services object
- `EnvironmentCache` with version-based caching — `EnvironmentState` cached by `(project, env)` and invalidated on version bump
- `EnvironmentState` dataclass with all definition types: resources, routes, flows, schemas, policies, buckets, mail_templates, subscriptions, webhooks, schedules, secrets
- `Platform.dispatch()` method for queuing jobs with `JobRun` tracking
- `Platform.publish()` method for publishing to realtime channels via Angula

### Changed

- API application assembly moved to `bootstrap.py` with `create_service()`, `DataPlaneDispatcher`, and `Record` installables
- Middleware order documented in `bootstrap.py` docstring — Sillo builds inside-out (last registered runs first)
- `start_platform()` startup hook now conditionally starts inline worker and scheduler

### Fixed

- Compiled app cache key collisions when multiple environments have the same name but different projects
- `DataPlaneDispatcher` now copies `pawabase.policy` and `pawabase.plan` scope keys back to the outer scope

## Version 0.15.0 — 2026-07-01

### Added

- `platform.queue` attribute (`QueueConnection`) for pushing jobs onto Redis-backed queues
- `platform.bus` attribute (`EventBus`) for publishing and subscribing to events
- `platform.cache` attribute (`BaseCache`) for caching compiled apps and key lookups
- `platform.storage` attribute (`StorageManager`) for object storage operations
- `platform.mail` attribute (`MailManager`) for sending email
- `platform.code` dictionary for loaded project code (`ProjectCode` objects)
- `platform.ensure_code()` and `platform.reload_code()` for lazy code loading
- `Platform.bind()` method for making the platform globally accessible via `get_platform()`

### Changed

- All long-lived services consolidated under `Platform` — previously scattered across multiple module-level variables
- `platform.start()` and `platform.stop()` lifecycle methods now start/stop bus, sources, storage, mail, and clients
- API settings moved to `config.py` with `ApiSettings(PlatformSettings)` subclass
- `default_data_url` now uses `{project}` and `{env}` substitution for per-environment databases

## Version 0.14.0 — 2026-06-10

### Added

- `PlatformSettings` base class in `pawabase_kit.settings` shared by all services
- `Env` inner class with `env_prefix = "PAWABASE_"` for automatic environment variable binding
- `validate_for_production()` method that flags development defaults still in place
- `internal_secret`, `jwt_master_secret`, and `master_key` as required secrets for all services
- Service-specific config modules: `gateway/config.py`, `akountz/config.py`, `angula/config.py`, `studio/config.py`, `api/config.py`

### Changed

- All services now subclass `PlatformSettings` instead of defining their own configuration
- `internal_secret` must be 32+ characters in production — `validate_for_production()` enforces this
- `cors_origins` defaults to `"*"` for gateway, comma-separated list for other services

## Version 0.13.0 — 2026-05-15

### Added

- `GatewaySettings` with `cors_origins`, `key_cache_ttl`, `rate_limit`, `rate_window`, `max_body_bytes`, `upstream_timeout`
- `AkountzSettings` with `database_url`, `admin_email`, `admin_password`, `lockout_threshold`, `lockout_minutes`, `config_ttl`
- `AngulaSettings` with `max_channels`, `max_message_bytes`, `history_bytes`, `config_ttl`, `idle_timeout`
- `StudioSettings` with `session_secret`, `session_ttl`, `cookie_secure`, `vite_dev`, `vite_dev_server`, `frontend_dir`, `public_gateway_url`

### Fixed

- Gateway `max_body_bytes` now defaults to 100 MB instead of 10 MB
- Studio session TTL corrected to 12 hours (`session_ttl: 12 * 3600`)

## Version 0.12.0 — 2026-04-20

### Added

- `akountz` service (port 8002) — identity management with accounts, sessions, MFA, organizations, and roles
- `angula` service (port 8003) — realtime server built on `sillo-wire` with channels, presence, and replay history
- `studio` service (port 8090) — control plane UI with Inertia + React and bridge to internal services
- Service-to-service authentication with `ServiceClient` and audience-bound service tokens
- `BRIDGE` table in Studio for mapping targets to service clients and path prefixes

### Changed

- Seven processes from one Docker image (`python -m app.main` with different entrypoints)
- `create_service()` in `pawabase_kit.service` now supports `inner`, `installables`, and `backends` parameters
- Service tokens use `issuer` and `audience` fields for audience-bound verification

### Fixed

- Studio bridge now rejects path-traversal segments (`..`) before making the internal call
- WebSocket connections to Angula now include `open_timeout=10s`

## Version 0.11.0 — 2026-03-25

### Added

- Gateway service (port 8080) — single public entry point with API key resolution, rate limiting, CORS enforcement, and internal proxying
- `GatewayProxy` ASGI middleware class in `services/gateway/app/proxy.py`
- HTTP and WebSocket proxying through the gateway
- Streaming request/response support with `httpx` for large bodies
- `route_for()` function for mapping public paths to internal services
- `Upstream` route table with `required`, `optional`, and no-key modes

### Changed

- All external traffic must go through the gateway — no service is directly exposed
- Internal service calls use signed `X-Pawabase-Context` headers
- Gateway strips `x-pawabase-*` headers and raw API keys before forwarding

### Fixed

- WebSocket close codes now use application-level codes (`4001`, `4003`, `1011`) instead of HTTP status codes
- Streaming uploads now track total bytes and return `413 payload_too_large` before exceeding `max_body_bytes`

## Migration between versions

### From 0.19.x to 0.20.x

The mail system was refactored in 0.20.0. If you were sending email inline (before `SendMailJob` existed), update your code to use `platform.mail.send()` which now queues a background job. The `suppress_send` option is new — without it, messages are sent immediately if SMTP is configured.

### From 0.17.x to 0.18.x

The event processing pipeline moved from inline handling to the `EventProcessor` class. If you were subscribing to the platform event bus directly, update to use `platform.bus.subscribe(EventProcessor(platform).handle)` instead. Event subscriptions are now tracked in `EventSubscription` records associated with each environment.

### From 0.15.x to 0.16.x

The `Platform` class was introduced as the central services object. If you were accessing services via module-level variables (e.g., `queue`, `bus`, `cache`), use `platform.queue`, `platform.bus`, `platform.cache` instead. The `get_platform()` function provides access to the bound instance.

### From 0.13.x to 0.14.x

All services now require `PAWABASE_INTERNAL_SECRET`, `PAWABASE_JWT_MASTER_SECRET`, and `PAWABASE_MASTER_KEY` to be set to 32+ character random values in production. The `validate_for_production()` check will refuse to start if any development default remains. Generate new secrets with `openssl rand -hex 32` and update your `.env`.
