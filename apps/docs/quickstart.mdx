This guide takes you from a fresh installation to a working backend you can call from an application. You'll create a project, define a resource, configure authentication, and make your first API call — all through **Studio**.

By the end, you will have a running Pawabase backend with a `todos` resource protected by policies, and a token you can use from any application.

<Callout>
If you haven't installed Pawabase yet, complete the [Docker installation](/installation/docker) or [local development setup](/installation/local-development) first. This guide assumes you have a running Pawabase at `http://localhost:8080`.
</Callout>

<Steps>
  <Step title="Start Pawabase and open Studio">
    Pawabase runs as a single Docker Compose stack. Once it's up, Studio is available at `http://localhost:8090`.

    ```bash
    docker compose up -d
    ```

    Wait 30 seconds for all services to start, then open [Studio](http://localhost:8090) in your browser. The first time you open Studio, you create an admin account.
  </Step>

  <Step title="Create a project">
    In Studio, click **New project**. Enter:
    - **Project name:** `my-app`
    - **Slug:** `my-app`
    - **Environment:** `development` (created automatically)

    Click **Create**. Studio creates your first environment and opens the project dashboard.
  </Step>

  <Step title="Create the todos resource">
    In the project sidebar, go to **Data → Resources**, then click **New resource**.

    | Field | Value |
    | --- | --- |
    | Resource name | `todos` |
    | Database table | `todos` |
    | Add to API | Checked |

    Click **Create**. Studio opens the resource editor with five operations pre-configured: `list`, `get`, `create`, `update`, `delete`.

    <Note>
    Every operation starts **disabled**. You must enable each one and attach a policy before it's accessible. Nothing is public by default.
    </Note>
  </Step>

  <Step title="Define fields">
    With the `todos` resource open, click **Fields** and add:

    | Name | Type | Required | Default |
    | --- | --- | --- | --- |
    | `title` | string | yes | — |
    | `completed` | boolean | no | `false` |
    | `due_date` | date | no | — |

    Click **Save fields**. Studio generates the validation model and creates the database columns on the next request.
  </Step>

  <Step title="Enable operations and attach policies">
    Go to the **Operations** tab for the `todos` resource. For each operation, flip it to **Enabled** and choose or create a policy.

    Start with a simple policy that lets anyone with a valid token create and read todos:

    1. Click the policy dropdown on `list` → **Create policy**.
    2. Name it `authenticated_access`.
    3. Set the condition to `{"truthy": "$auth.user_id"}` — this requires the caller to be authenticated.
    4. Click **Save**.
    5. Repeat for `get`, `create`, `update`, and `delete`.

    <Note>
    The condition `{"truthy": "$auth.user_id"}` means: "the caller's token must include a user_id." Anonymous (key-only) requests have `$auth.user_id = null`, so they fail this condition. See [Policies overview](/policies/overview) and [Expressions](/concepts/expressions) for more condition syntax.
    </Note>
  </Step>

  <Step title="Create a user and get a token">
    Go to **Auth → Users** in Studio. Click **Create user** and enter any email and password (e.g., `test@example.com` / `password123`).

    Now get an access token:

    ```bash
    curl -X POST http://localhost:8080/auth/signin \
      -H "Content-Type: application/json" \
      -d '{"email": "test@example.com", "password": "password123"}'
    ```

    The response contains `access_token` and `refresh_token`. Copy the access token — you'll use it in the next step.
  </Step>

  <Step title="Call the API">
    Create a todo:

    ```bash
    curl -X POST http://localhost:8080/rest/v1/todos \
      -H "apikey: $(grep PROJECT_KEY .env | cut -d= -f2)" \
      -H "Authorization: Bearer <access_token>" \
      -H "Content-Type: application/json" \
      -d '{"title": "Buy groceries"}'
    ```

    List todos:

    ```bash
    curl http://localhost:8080/rest/v1/todos \
      -H "apikey: $(grep PROJECT_KEY .env | cut -d= -f2)" \
      -H "Authorization: Bearer <access_token>"
    ```

    You should get back a JSON response with your todo item.
  </Step>

  <Step title="Build a flow">
    Go to **Automate → Flows** and click **New flow**.

    - **Name:** `on_todo_created`
    - **Trigger:** `Event` → `todos.created`
    - **Description:** "Send a notification when a new todo is created"

    In the flow editor, add a **Log** block connected to the trigger. Configure it with the message:

    ```text
    New todo: {{ input.event.payload.title }}
    ```

    Click **Save** and then **Deploy**. Now create another todo — check the **Flow runs** panel to see the execution trace.
  </Step>
</Steps>

## What you just built

```text
Studio
  ├── Project: my-app (development)
  ├── Data: todos resource with 5 operations, each gated by a policy
  ├── Auth: one user with an access token
  └── Automate: a flow that triggers on todo creation
```
