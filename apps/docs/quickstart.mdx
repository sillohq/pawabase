This guide gets you from zero to a working Pawabase platform in minutes. You will create a project, define a flow and a function, and run the platform.

## Step 1: Install and configure

Install the Pawabase package and create the configuration file:

```bash
# Install the package
pip install pawabase-kit

# Create a project directory
mkdir my-project
cd my-project

# Initialize the project
pawabase init
```

The `pawabase init` command creates the project structure with a pyproject.toml, .env.example, and the necessary configuration files.

## Step 2: Define flows and functions

Create a flows.py file with a flow definition and a functions.py file with a function definition:

```python
# flows.py
from pawabase import flow

@flow("submit_review")
async def submit_review(ctx):
    review = await ctx.input.get("review")
    user = await ctx.runtime.current_user()
    await ctx.runtime.check_policy("submit_review", user, review)
    result = await ctx.runtime.function.call("calculate_score", {"review": review})
    await ctx.runtime.db.create("reviews", result)
    await ctx.runtime.emit("review_submitted", {"review_id": result["id"]})

# functions.py
from pawabase import function

@function("calculate_score")
async def calculate_score(ctx, review):
    score = len(review.get("text", "")) * 0.1
    return {"score": score, "status": "approved" if score > 5 else "pending"}
```

<Tip>
Use the @flow decorator for flow definitions and the @function decorator for function definitions. The flow handles the orchestration shape while the function handles the algorithm.
</Tip>

## Step 3: Run and test

Start the platform and test your definitions:

```bash
# Run the platform
python -m pawabase.bootstrap

# In another terminal, test the function
pawabase call calculate_score --input '{"review": {"text": "Great product!"}}'

# Test the flow
pawabase flow submit_review
```

The platform starts the API worker, scheduler, and all background services. The flow and function definitions are compiled and ready to execute.

## Understanding the flow

A flow defines the shape of the operation. It uses blocks for branching, loops, and error handling. A function defines the algorithm. It takes input and produces output. The flow calls the function via function.call.

## Understanding the function

A function is a callable decorated with @function. It receives a FunctionContext with input, auth, project, env, runtime, trigger, request, and logs fields. The function must be an async callable.

## Understanding the runtime

The runtime is the execution engine. It provides the current_user, check_policy, function_call, db, emit, and other methods. The runtime is passed to the flow and function handlers as ctx.runtime.

## Understanding the block registry

The block registry collects all available blocks. Blocks are discovered through the pawabase.blocks entry point group. Each block has a key, title, category, config, handles, and trigger flag.

## Understanding the function registry

The function registry collects all available functions. Functions are discovered through the pawabase.functions entry point group. Each function has a project, name, and handler.

## Understanding the extension routes

Extension routes are HTTP handlers added via the pawabase.routes entry point group. They have full access to the Sillo router and can use middleware, streaming, and all HTTP features.

## Understanding the hybrid pattern

The hybrid pattern combines the strengths of flows and functions. A flow handles the shape while a function handles the algorithm. The flow calls the function via function.call.

## Understanding the event system

Events are emitted by functions and flows. The event system allows different parts of the platform to communicate. Events are used for notifications, audit trails, and cross-service communication.

## Understanding the scheduler

The scheduler dispatches flow or function jobs at specified intervals. Schedules are defined as cron expressions or frequency specifications.

## Understanding the worker

The worker executes flow and function jobs. It polls the job queue, creates a runtime context, and invokes the handler. The worker respects the PAWABASE_WORKER_CONCURRENCY and PAWABASE_WORKER_MAX_JOBS_PER_WORKER environment variables.

## Understanding the bootstrap

The bootstrap process starts the API worker, scheduler, and all background services. It initializes the block registry, function registry, and runtime protocol.

## Understanding the configuration

All configuration is done through environment variables. The PAWABASE_ENV variable controls whether the platform runs in local or production mode.

## Understanding the project structure

The project structure includes pyproject.toml, .env.example, flows.py, functions.py, routes.py, and blocks.py. Each file serves a specific purpose in the platform configuration.

## Understanding the deployment

Deployment is immediate. The platform compiles and runs on startup. Use Docker for consistent environments. Use the docker-compose.yml to orchestrate the full platform stack.

## Understanding the testing

Test flows with a fake runtime. Test functions with a fake FunctionContext. Use pytest for the test suite. The platform provides test fixtures.

## Understanding the observability

Both flows and functions produce observable data in Studio. Use the platform observability to monitor execution, debug issues, and track performance.

## Understanding the security

All components are subject to the same policy engine. Functions have the policy parameter. Blocks use the runtime check_policy. Routes use the ContextMiddleware.

## Understanding the performance

Consider the performance implications of each architectural choice. Inline function calls are faster than background dispatch.

## Understanding the collaboration

Flows can be edited by non-engineers in Studio. Functions require Python knowledge. The ideal setup uses both: engineers write functions, non-engineers compose flows.

## Understanding the versioning

Flows are versioned per environment as JSON. Functions are versioned with git. The platform tracks flow versions automatically.

## Understanding the error handling

Flows have built-in error handling with error edges. Functions raise exceptions. Handle errors gracefully.
