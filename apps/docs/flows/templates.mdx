Every `{{ }}` inside a flow's JSON config is a **template expression**. The engine renders it against the current run state before passing the result to the block. A template can be a literal string, a number, a boolean, an object, or an array — whatever the expression evaluates to.

## Syntax

A template is any value wrapped in `{{ }}`:

```json
{ "block": "control.set", "config": { "vars": { "greeting": "{{ input.event.payload.name }}" } } }
```

You can also embed templates inside a larger string — the engine resolves the template and substitutes its string representation:

```json
{ "block": "log.write", "config": { "message": "Order {{ input.event.payload.id }} processed for {{ steps.calc.output }} USD" } }
```

Templates can appear anywhere a JSON value is expected — inside a string, as an object value, inside an array, or as a standalone expression.

## Resolution scope

Templates resolve against the run state in this order:

1. `input` — the trigger payload
2. `auth` — the resolved caller (`$auth.org` is shorthand)
3. `vars` — custom values set by `control.set` (`$vars.discount` is shorthand)
4. `steps` — every block's output (`$steps.node_id.output.field` is shorthand)
5. `error` — the error object if an error edge is active (`error.message`, `error.type`, `error.node`)
6. `item` and `index` — available inside `control.foreach` bodies

Inside a `control.if` condition, `control.switch`, or `control.foreach`, you can also use **raw expressions** (without `{{ }}`) because those blocks opt into `raw_config` and pass the condition object as-is to the engine's expression evaluator.

## Literals

Templates can evaluate to any JSON literal:

```json
"{{ 42 }}"               → 42
"{{ true }}"             → true
"{{ null }}"             → null
"{{ [1, 2, 3] }}"        → [1, 2, 3]
"{{ {name: 'Alice'} }}"  → {name: 'Alice'}
```

## Object and array access

```json
"{{ input.body.email }}"                          → "alice@example.com"
"{{ steps.load.output.data.0.name }}"              → "Alice"
"{{ input.params.id }}"                            → "ord_1"
"{{ auth.user.email }}"                            → "alice@example.com"
```

Nested access chains are dot-separated. If any key in the chain is missing, the template resolves as `undefined` — it does **not** raise.

## Operators

The engine supports comparison, logical, arithmetic, and null-coalescing operators inside template expressions:

### Comparison operators

| Operator | Example | Result |
| --- | --- | --- |
| `eq` | `{ eq: ["{{ input.status }}", "paid"] }` | `true` if equal |
| `ne` | `{ ne: ["{{ input.status }}", "paid"] }` | `true` if not equal |
| `lt` | `{ lt: ["{{ input.count }}", 10] }` | `true` if less than |
| `lte` | `{ lte: ["{{ input.count }}", 10] }` | `true` if ≤ |
| `gt` | `{ gt: ["{{ input.count }}", 0] }` | `true` if greater |
| `gte` | `{ gte: ["{{ input.count }}", 0] }` | `true` if ≥ |
| `in` | `{ in: ["{{ input.type }}", ["a", "b", "c"]] }` | `true` if in array |
| `nin` | `{ nin: ["{{ input.type }}", ["a", "b"]] }` | `true` if not in array |

### Logical operators

| Operator | Example | Result |
| --- | --- | --- |
| `and` | `{ and: [{ truthy: "$input.has_discount" }, { gt: ["$input.discount", 0] }] }` | both true |
| `or` | `{ or: [{ truthy: "$input.has_discount" }, { truthy: "$input.has_coupon" }] }` | either true |
| `not` | `{ not: { truthy: "$input.is_cancelled" } }` | inverted |
| `all` | `{ all: [cond1, cond2, cond3] }` | all true |
| `any` | `{ any: [cond1, cond2] }` | any true |

### Arithmetic operators

| Operator | Example | Result |
| --- | --- | --- |
| `add` | `{ add: [5, 3] }` | 8 |
| `subtract` | `{ subtract: [10, 4] }` | 6 |
| `multiply` | `{ multiply: [6, 7] }` | 42 |
| `divide` | `{ divide: [20, 4] }` | 5 |
| `modulo` | `{ modulo: [17, 5] }` | 2 |
| `floor` | `{ floor: 4.7 }` | 4 |
| `ceil` | `{ ceil: 4.2 }` | 5 |
| `round` | `{ round: 4.6 }` | 5 |

### Null-coalescing operator

| Operator | Example | Result |
| --- | --- | --- |
| `??` | `{ "??" : ["{{ input.name }}", "Anonymous"] }` | first non-undefined, else second |

### String operators

| Operator | Example | Result |
| --- | --- | --- |
| `contains` | `{ contains: ["{{ input.email }}", "@"] }` | `true` if substring |
| `startsWith` | `{ startsWith: ["{{ input.name }}", "A"] }` | `true` if prefix |
| `endsWith` | `{ endsWith: ["{{ input.name }}", "a"] }` | `true` if suffix |
| `concat` | `{ concat: ["{{ input.first }}", " ", "{{ input.last }}"] }` | "Alice Smith" |
| `length` | `{ length: ["{{ input.items }}"] }` | array length |

## Filters

Filters transform template values. They appear after the expression, separated by `|`:

```json
"{{ input.body.email | lower }}"
"{{ input.body.name | trim | capitalize }}"
"{{ steps.result.output.amount | round:2 }}"
"{{ input.params.id | json }}"
"{{ input.body.tags | join:', ' }}"
"{{ input.body.html | safe }}"
```

| Filter | Description | Example |
| --- | --- | --- |
| `lower` | Convert to lowercase | `"HELLO" → "hello"` |
| `upper` | Convert to uppercase | `"hello" → "HELLO"` |
| `trim` | Remove leading/trailing whitespace | `"  hi  " → "hi"` |
| `capitalize` | Capitalize first letter | `"hello" → "Hello"` |
| `json` | Serialize to JSON string | `{a:1} → '{"a":1}'` |
| `join` | Join array with separator | `["a","b"] | join:", " → "a, b"` |
| `round` | Round to N decimal places | `4.567 | round:2 → 4.57` |
| `int` | Convert to integer | `"42" → 42` |
| `float` | Convert to float | `"3.14" → 3.14` |
| `safe` | Mark string as HTML-safe (no escaping) | `"<b>" → "<b>"` |
| `default` | Fallback if undefined | `"\{\{ input.name | default:\'Guest\' \}\}"` |
| `first` | Get first element of array | `["a","b"] | first → "a"` |
| `last` | Get last element of array | `["a","b"] | last → "b"` |
| `slice` | Slice an array or string | `["a","b","c"] | slice:0,2 → ["a","b"]` |
| `map` | Extract a field from array of objects | `items | map:"name"` |
| `filter` | Filter array by field | `items | filter:"active"` |

## Functions

Functions are called inside templates with parentheses:

```json
"{{ now() }}"
"{{ uuid() }}"
"{{ format_date(input.event.payload.timestamp, 'YYYY-MM-DD') }}"
"{{ format_currency(steps.result.output.total, 'USD') }}"
"{{ base64_encode(input.body.secret) }}"
"{{ json_dumps(steps.result.output) }}"
```

| Function | Description |
| --- | --- |
| `now()` | Current UTC timestamp |
| `uuid()` | A new UUID v4 string |
| `format_date(value, fmt)` | Format a timestamp |
| `format_currency(value, code)` | Format as currency |
| `base64_encode(value)` | Base64 encode |
| `base64_decode(value)` | Base64 decode |
| `json_dumps(value)` | Serialize to JSON string |
| `json_loads(value)` | Parse a JSON string |
| `slug(value)` | Convert to URL-safe slug |
| `trim(value)` | Trim whitespace |
| `random(min, max)` | Random integer in range |
| `hash(value)` | SHA-256 hash hex |

## Shorthand syntax

In conditions (inside `control.if`, `control.switch`, `control.foreach`), you can omit `{{ }}` and use `$` as a shorthand for `state.` access:

```json
{ "condition": { "eq": ["$input.status", "paid"] } }
{ "condition": { "truthy": "$auth.org" } }
{ "condition": { "lt": ["$steps.calc.output", 0] } }
```

`$steps.node_id.output.field` resolves to `state["steps"]["node_id"]["output"]["field"]`. `$vars.name` resolves to `state["vars"]["name"]`. `$auth.org` resolves to `state["auth"]["org"]`.

## Edge cases

### Templates that resolve to undefined

If a template references a key that doesn't exist, it renders as the string `"undefined"`. The engine does **not** raise for missing template variables. This is by design — a conditional that checks `{{ input.optional }}` should be falsy when the field is absent, not crash the flow.

### Empty strings vs. undefined

An empty string `""` is truthy in `control.if` — it is not the same as `undefined`. Use `{ truthy: "$input.field" }` which treats both empty string and `undefined` as falsy.

### Arrays inside strings

If an array is interpolated inside a string without a filter, it renders as the JSON representation: `"{{ input.tags }}" → '["a","b"]'` (with quotes). Use `| join:', '` to get a human-readable list.

### Nested objects and dot access

Dot access chains stop at the first missing key and resolve to `undefined`:

```json
"{{ a.b.c }}"  → undefined if a exists but a.b is null
"{{ a.b.c }}"  → undefined if a doesn't exist at all
```

### Escaping braces

To render literal `{` or `}` in output, use `{{ '{' }}` or `{{ '}' }}`. Double braces `{{ }}` are the template delimiter and cannot be escaped inside a template expression.

### Type coercion

Templates resolve to their natural JSON type. A template that evaluates to a string is a string; one that evaluates to a number is a number. The engine does **not** coerce types — if a block expects a number and gets a string, the block may fail. Use `| int`, `| float`, or `| round` to convert explicitly.

## Common mistakes

<AccordionGroup>
  <Accordion title="Missing closing brace">
    `{{ input.email }` without the closing `}` is not a template — it's a literal string. The engine renders it verbatim.
  </Accordion>
  <Accordion title="Using a block's config before it's been executed">
    A block can only reference `{{ steps.<id>.output }}` for nodes that executed before it. Forward references resolve as `undefined`.
  </Accordion>
  <Accordion title="Forgetting that arrays render as JSON inside strings">
    `"{{ input.tags }}"` inside a string produces `'["a","b"]'`, not `a, b`. Use `| join` to format arrays for display.
  </Accordion>
  <Accordion title="Assuming undefined raises an error">
    `{{ input.missing }}` renders as `undefined` silently. If a block receives `undefined` and can't handle it, the block fails — not the template.
  </Accordion>
  <Accordion title="Mixing raw conditions and template syntax">
    Inside `control.if` conditions, use `$` shorthand without `{{ }}`. Using `{{ }}` inside a condition object is parsed as a raw condition and the double braces become literal text in the expression.
  </Accordion>
</AccordionGroup>
