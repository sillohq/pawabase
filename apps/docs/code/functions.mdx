A **function** is a Python callable registered in a project's `code/<project>/functions/` directory. Functions are the escape hatch when a flow's block vocabulary isn't expressive enough.

## Writing a function

A function is a Python module containing one or more callables decorated with `@function(...)`.

```python
# code/myproject/functions/pricing.py
from pawabase import function, FunctionContext
from decimal import Decimal

@function("calculate_price", description="Compute the final price for an order", input_schema={
    "items": {"type": "json", "required": True},
    "discount_code": {"type": "string", "required": False},
})
async def calculate_price(ctx: FunctionContext, items: list[dict], discount_code: str | None = None) -> dict:
    subtotal = sum(Decimal(str(item["price"])) for item in items)
    discount = await _lookup_discount(ctx, discount_code) if discount_code else Decimal("0")
    total = subtotal - discount
    return {"subtotal": float(subtotal), "discount": float(discount), "total": float(total)}

async def _lookup_discount(ctx, code):
    result = await ctx.runtime.db_query("SELECT amount FROM discounts WHERE code = ? AND active = 1", [code])
    return Decimal(str(result[0]["amount"])) if result else Decimal("0")
```

The `@function` decorator records the function's metadata -- its name, description, and input schema.

## Input and output

Functions receive their arguments as keyword arguments matching the `input_schema` declared in the decorator. The platform's `FunctionContext` provides access to the same `Runtime` capabilities a flow block uses:

- **`ctx.runtime`** -- `resource_list`, `resource_get`, `db_query`, `cache_get`, `emit`, `call_function`, `secret`, `http_request`, and the full `Runtime` protocol
- **`ctx.state`** -- the run's current state (`input`, `auth`, `vars`, `steps`)
- **`ctx.render()`** -- render templates against the current state

The return value of the function is whatever the function returns, and it's available to the caller as the function's output.

## Registering functions

Functions are discovered through the `pawabase.functions` entry point group in `pyproject.toml`:

```toml
[project.entry-points."pawabase.functions"]
pricing = "code.myproject.functions.pricing:calculate_price"
analytics = "code.myproject.functions.analytics:track_event"
```

The platform's `FunctionRegistry` loads all registered functions at startup. New functions added to a package are picked up without restarting the API.

## Calling conventions

Functions can be called in two ways: synchronously via `function.call` within a flow, or asynchronously via `queue.function` as a background job.

### Synchronous calls via function.call

When a flow calls a function via `function.call`, the worker executes the function inline and returns the result immediately.

```json
{"id": "price", "data": {"block": "function.call", "config": {"function": "calculate_price", "input": {"items": "{{ steps.cart.output }}", "discount": "{{ vars.discount }}"}}}}
```

### Asynchronous calls via queue.function

When a flow or code dispatches a function via `queue.function`, the worker creates a job and adds it to the job queue.

```python
from pawabase import queue

await queue.function('calculate_price', {'items': [...], 'discount': 'SAVE10'})
```

### Manual calls

Functions can be called manually from the command line using the `pawabase call` CLI.

```bash
pawabase call calculate_price --input '{"items": [...]}'
```

## FunctionContext

Every function receives a `FunctionContext` as its first argument. The context provides access to input, auth, project, env, runtime, trigger, request, and logs.

```python
async def my_function(ctx, param1, param2):
    input_data = ctx.input
    auth = ctx.auth
    project = ctx.project
    env = ctx.env
    runtime = ctx.runtime
    trigger = ctx.trigger
    request = ctx.request
    logs = ctx.logs
    ...
```

## Depth limit

`call_function` is depth-limited to 8 levels. This prevents infinite recursion from crashing the worker.

## Timeout

Each function has a `timeout` parameter (default 30 seconds). The worker's `WorkerOptions.timeout` (default 300 seconds) controls the maximum job duration.

```python
@function("long_running", timeout=60)
async def long_running(ctx):
    ...
```

## Policy

Functions can have a `policy` parameter that controls access.

```python
@function("admin_only", policy="admin")
async def admin_only(ctx):
    ...
```

## Error handling

Functions raise exceptions that propagate to the caller. In a synchronous call via `function.call`, the exception is caught by the flow engine.

## Testing

Functions are tested by calling the handler with a fake `FunctionContext`.

```python
async def test_my_function():
    ctx = FunctionContext(...)
    result = await my_function(ctx, param1, param2)
    assert result == expected
```

## Performance

Functions run directly without graph execution overhead. Inline function calls are fast. Background calls have serialization overhead.

## Security

Functions are subject to the policy engine. The `policy` parameter on the `@function` decorator controls access.

## Observability

Function invocations produce logs and metrics. Both are visible in Studio Observability.
